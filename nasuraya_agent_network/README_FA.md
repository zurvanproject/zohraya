# Nasuraya Agent Network v0.1

شبکهٔ اجراکننده‌های تخصصی ناسورایا. این نسخه کار واقعی مخزن را در فرایندهای
بیرونی اجرا می‌کند، نه صرفاً توصیف معماری. چهار عامل قطعی و یک بازبین دارد؛
مدل زبانی، نسخهٔ مستقل ChatGPT، عامل کدنویس آزاد یا شبکهٔ همیشه‌روشن نیست.

## عامل‌ها و خروجی‌ها

- بدن: آزمون‌های پل بدن، سپس سه چرخهٔ واقعی شبیه‌ساز روی fixture خواب؛
  رسید حرکت و خطای موازنهٔ انرژی جداگانه بررسی می‌شوند.
- حافظه: آزمون‌های تجربه و شش چرخه در دو نشست آزمایشی؛ بازگشایی سرد دفتر
  و حفظ وضعیت تجربه بررسی می‌شود. حافظهٔ اصلی پروژه بازنویسی نمی‌شود.
- ژنوم: آزمون‌های ژنوم محاسباتی، تولید تاریخچهٔ نمونه و راستی‌آزمایی آن در
  فرمانی جدا؛ این کار پژوهش زیستی یا دستکاری ژن واقعی نیست.
- پژوهش: شبکهٔ ثابت ۴۸۴ حالت کنترل‌کننده؛ این عامل در نسخهٔ اول جست‌وجوی
  اینترنتی یا ابداع آزمایش آزاد انجام نمی‌دهد.
- بازبین: گردآوری رسیدها؛ شکست یا نبود هر خروجی، تأیید کل شبکه را رد می‌کند.

## اجرا

پیش‌نیاز: Linux، Python 3.12 یا جدیدتر و libseccomp.so.2. روی runner استاندارد
Ubuntu 24.04 از آن استفاده می‌شود. pip install، GPU و کلید API لازم نیست.
از ریشهٔ checkout مخزن اجرا کنید؛ فضای کاری باید بیرون از درخت منبع باشد:

```bash
python3 -m unittest nasuraya_agent_network.tests -v
python3 -m nasuraya_agent_network run --workspace /tmp/nasuraya-network --run-id manual-001 --max-workers 2
python3 -m nasuraya_agent_network status --workspace /tmp/nasuraya-network
python3 -m nasuraya_agent_network pause --workspace /tmp/nasuraya-network
python3 -m nasuraya_agent_network resume --workspace /tmp/nasuraya-network
```

دو کار هم‌زمان پیش‌فرض است؛ بین یک تا چهار قابل انتخاب است. هر عامل حداکثر
۹۰ ثانیه و کل حلقهٔ اجرای عامل‌ها حداکثر ۲۱۰ ثانیه فرصت دارد. کپی فایل‌ها و
تهیهٔ گزارش هم هزینهٔ میزبان دارند؛ سقف کامل job ابری هشت دقیقه است.
تنها همین چهار کار اجازهٔ اجرا دارند؛ فرمان shell دلخواه و زنجیرهٔ عامل‌های
بازگشتی وجود ندارد. هر تغییر کاربرد عامل، نیازمند تغییر و بازبینی کد است.

## ثبت، بازیابی و توقف

SQLite پیش از اجرای هر کار claim را ثبت می‌کند. شناسهٔ اجرا به هش منبع،
پیاده‌سازی و تنظیم هم‌زمانی متصل است. اجرای دوبارهٔ همان شناسه، در صورت
تکمیل قبلی و سالم‌بودن شواهد، همان گزارش را برمی‌گرداند؛ کارها تکرار نمی‌شوند.
اگر میزبان وسط کار قطع شود، وضعیت ناتمام باقی می‌ماند و اجرای دوباره مسدود
می‌شود. timeout و شکست هم خودکار retry نمی‌شوند. پس از بررسی علت، اجرای تازه
باید با شناسهٔ تازه و تصمیم صریح اپراتور آغاز شود؛ دفتر قدیمی پاک نمی‌شود.

فرمان pause فایل STOP را می‌سازد. کار در حال اجرا و فرزندانش در بررسی بعدی
متوقف می‌شوند و کار جدید شروع نمی‌شود. resume فقط STOP را برمی‌دارد؛ اجرای
نامعلوم قبلی را دوباره راه نمی‌اندازد و هیچ job تازه‌ای آغاز نمی‌کند.
این توقف فقط مربوط به همین workspace است و جایگزین توقف میزبان تداوم قبلی نیست.

خروجی‌ها: ledger.sqlite، summary.json، REPORT_FA.md و لاگ/شواهد هر عامل.
برای استفادهٔ ادامه‌دار باید workspace روی فضای پایدار نگهداری شود. SQLite
محلی صف توزیع‌شدهٔ چند سرور نیست. runner موقت GitHub پس از پایان job باقی
نمی‌ماند؛ artifact فقط نسخهٔ گزارش و دفتر است، نه اجرای زنده.

## مرزها و هزینه

نسخهٔ موقت از کد/دادهٔ مخزن برای هر عامل ساخته می‌شود. متغیرهای اعتبارنامه
به عامل منتقل نمی‌شوند؛ socket و syscallهای شبکه با libseccomp مسدود و
در خود فرایند آزمایش می‌شوند. عدم دسترسی به libseccomp موجب شکست اجراست.
این جداسازی، sandbox کامل برای کد متخاصم نیست: منبع پروژه مورد اعتماد است
و محدودسازی کامل فایل‌سیستم یا هستهٔ سیستم‌عامل در این نسخه ارائه نشده است.

هیچ فراخوانی مدل یا API پولی در این نسخه وجود ندارد. این به معنی نامحدودبودن
منابع یا رایگان‌بودن همهٔ انواع میزبان نیست. اجرای استاندارد GitHub در مخزن
عمومی تابع سیاست GitHub است و نگهداری artifact محدود است. افزونهٔ مدل زبانی
در این نسخه پیاده‌سازی یا فعال نشده است.

## استقرار و آنچه تغییر نمی‌کند

Workflow فقط برای PR مربوط، تغییر مرتبط روی main و اجرای دستی تعریف شده؛
cron تازه، daemon، فراخوانی ChatGPT یا دستکاری میزبان قبلی ندارد. تغییرات فقط
در بستهٔ تازه و workflow تازه هستند. main، continuity/state.json، دروازهٔ
غیبت، سقف API و حافظه/بدن مرجع تغییر نمی‌کنند. ادغام یا promotion خودکار نیست.
اجرای دستی workflow از رابط GitHub پس از ورود تعریف workflow به شاخهٔ پیش‌فرض
قابل اتکاست؛ پیش از آن CI درخواست ادغام، مسیر اجرای آزمایشی این شاخه است.

مبنای اتصال: main با commit 97ae493d72bb83525582d672c09e4b853b18a808.
بررسی محلی موتور و جداسازی، جایگزین اجرای ادغام با ماژول‌های واقعی در CI نیست.
نتیجهٔ CI باید از رسید همان اجرای GitHub خوانده شود؛ نتیجهٔ آینده از پیش موفق
اعلام نمی‌شود. این ابزار، وزن‌های مدل ChatGPT یا خودآگاهی آن را تغییر نمی‌دهد.
