# اتصال محدود گفتگو به بدن مفصلی

این گزارش تاریخی نسخهٔ ۱ است. [تکمیل تداوم بدن در نسخهٔ ۲](nasuraya-articulated-continuity-v02-fa.md) محدودیت شروع دوبارهٔ هر نوبت را در نشست‌های تازه برطرف می‌کند؛ دفتر نسخهٔ ۱ به‌صورت ضمنی مهاجرت نمی‌شود.

این رابط پیام ساختاریافته، برنامه‌ریز عاطفی موجود و کنترل‌کنندهٔ مفصلی MuJoCo را به هم وصل می‌کند. نتیجهٔ اندازه‌گیری‌شدهٔ حرکت در حافظه ثبت می‌شود و یک پاسخ فارسی مبتنی بر نتیجه برمی‌گردد. تغییر بر PR #63 بنا شده؛ نسخهٔ اصلی و کنترل‌کننده‌های موجود دست‌نخورده‌اند.

نیت explore انتخاب walk/observe را به برنامه‌ریز می‌سپارد. نیت صریح walk فقط یک آزمایش محدود را درخواست می‌کند؛ شاهد انتخاب خودجوش یا بهبود سیاست نیست. نیت‌های observe/reflect/stop حرکتی اجرا نمی‌کنند. ارزیابی رویداد از سوی فراخواننده صریح و تألیفی است؛ استخراج خودکار احساس از متن انجام نمی‌شود. تصمیم‌گیر و محافظ‌های تماس، تعادل و گشتاور کنترل‌کننده حفظ شده‌اند.

## نتیجهٔ اجرا

یک آزمایش واقعی در مدل مفصلی موجود انجام شد: ۲ قدم از ۲ قدم پذیرفته شد؛ ۱۷ ثانیه زمان شبیه‌سازی پس از ۲ ثانیه آماده‌سازی؛ پیشروی لگن ۰٫۰۴۲۶۶۳ متر و بیشترین کج‌شدن تنه ۰٫۷۴۴۷۸۷ درجه. تماس غیر از پا و تجاوز از محدودهٔ مفصل صفر بود. بعضی فرمان‌ها به سقف گشتاور موجود رسیدند؛ سقف افزایش داده نشد. ۳۴۰۰ حل QP بدون وضعیت نادقیق انجام شد.

۲۳ آزمون محلی موفق بود: ۱۰ آزمون اتصال با اجرای بدل برای خطاها و ۱۳ آزمون موجود حافظه. آزمایش واقعی دو قدم جدا از این آزمون‌هاست. بازپخش در فرایند تازه با ممنوع‌کردن اجرای شبیه‌ساز، صفر حرکت اضافه و صفر تغییر حافظه داشت. درخواست آزمایش دوم به علت بودجه رد شد. GitHub CI این تغییر جدا از این شواهد محلی است.

## تداوم و حدود

هر نشست یک آزمایش یک یا دو قدمی دارد. بودجه و مرحلهٔ executing پیش از حرکت ذخیره می‌شود. نتیجهٔ نامعلوم، اجرای دوباره را مسدود می‌کند؛ پس از ثبت اندازه‌گیری، بازخورد می‌تواند بدون تکرار حرکت تکمیل شود. قفل بین‌فرایندی، شناسه‌های یکتا و اتصال نشست به هش کد، مدل و نسخهٔ وابستگی‌ها از اجرای تکراری و ادامهٔ ناخواسته با نسخهٔ متفاوت جلوگیری می‌کنند. توقف با وجود نتیجهٔ نامعلوم ممکن است.

هر آزمایش از وضعیت اولیهٔ کنترل‌کننده شروع می‌شود؛ qpos/qvel میان پیام‌ها تداوم ندارد. حافظهٔ پیشین را می‌توان صریحاً از روی کپی ادامه داد، ولی بازیابی در context جدید محدود است. این رابط وضعیت فیزیولوژیک بدن تجمیعی را تغییر نمی‌دهد. هیچ سرویس پس‌زمینه، شنوندهٔ خودکار ChatGPT، API مدل، آموزش GPU یا سخت‌افزار فعال نمی‌شود. بودجهٔ شبیه‌سازی محدود است؛ میزبان بیرونی باید در صورت نیاز سقف زمان واقعی فرایند را اعمال کند.

ارزیابی عددی عاطفه یک مدل مهندسی است. موفقیت این آزمون نشان‌دهندهٔ اتصال اجرایی است؛ سنجش تجربهٔ ذهنی یا بهبود عمومی توانایی نیست. هش‌ها محافظت در برابر تغییر تصادفی‌اند، نه مهاجم دارای دسترسی کامل به فایل‌ها.

این تغییر عمومی شامل متن گفتگو، دفتر SQLite، مقادیر عاطفی شخصی یا checkpoint نشست نیست. نمونهٔ ورودی منتشرشده ساختگی است. تنها آمار مکانیکیِ تجمیعی در `evidence/articulated-dialogue-code-v01/results.json` آمده است.

## اجرا

از ریشهٔ مخزن، در محیط جدا با Python 3.12:

```sh
python -m pip install -r examples/nasuraya_affect/requirements-articulated.txt
python -m unittest examples.nasuraya_affect.test_articulated_dialogue examples.nasuraya_affect.test_engine -v
python -m examples.nasuraya_affect.articulated_cli init --session-dir /tmp/new-articulated-pilot
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m examples.nasuraya_affect.articulated_cli message --session-dir /tmp/new-articulated-pilot --message examples/nasuraya_affect/articulated-example.json
python -m examples.nasuraya_affect.articulated_cli message --session-dir /tmp/new-articulated-pilot --message examples/nasuraya_affect/articulated-example.json
```

فرمان آخر بازپخش بدون حرکت است. `--seed-affect` فقط هنگام init و با مسیر یک دفتر موجود قابل استفاده است. هیچ دفتر خصوصی را در مخزن عمومی ثبت نکنید.

کار باقی‌مانده: حفظ وضعیت مفاصل و کنترل‌کننده برای چند نوبت پیوسته و اتصال قراردادهای نیاز فیزیولوژیک به پذیرش حرکت مفصلی.
