# دیدبان تصویری ناسورایا، نسخهٔ ۰۲

۱۶ اکتبر ۲۰۲۶ — صادرکنندهٔ محلی و نمای آفلاین، همراه با آزمون CI

سهند خواست تصویرسازی با امنیت هماهنگ‌تر و مفیدتر شود. من مهرِ دو روباه و
آتش را به یک نمای مبتنی بر نتیجهٔ وارسی تبدیل کردم: متن، چراغ‌ها و رنگ
با هم تغییر می‌کنند. تصویر اختیار پذیرش کار یا پاک‌کردن قفل ندارد.

## رفتار اجراشده

`visual_status.py` فقط کتابخانهٔ استاندارد Python را import می‌کند؛ هیچ
ماژول پروژه، فرمان دریافتی یا کد تازهٔ مخزن را اجرا نمی‌کند. فهرست منابع
با هش مستقلِ پیکربندی اپراتور تطبیق داده می‌شود. خواندن فایل محدود است،
پیوند نمادین رد می‌شود، و دفتر حداکثر ۱۶ مگابایتی در یک SQLite در حافظه
بررسی می‌شود. پایگاه دادهٔ اصلی برای نوشتن باز نمی‌شود. وجود فایل WAL،
SHM یا journal موجب وضعیت نامعلوم می‌شود؛ این نسخه مصرف‌کنندهٔ SQLite
هم‌زمان یا WAL نیست. مشاهده برای یک استقرار محلیِ آرام و یک نویسنده است.

| وضعیت | دلیل | رفتار نما |
| --- | --- | --- |
| بررسی موفق | منابع و زنجیره معتبر، بدون قفل و سابقهٔ هشدار | چراغ سبزآبی همراه متن و زمان |
| هشدار | دفتر معتبر دارای سابقهٔ هشدار | کهربایی؛ کار سالم بعدی سابقه را پنهان نمی‌کند |
| توقف | قفل، نقص تمامیت یا نزدیک‌شدن به سقف دفتر | قرمز همراه دستور حفظ شاهد و بررسی |
| نامعلوم | دادهٔ مفقود، خواندن ناموفق، گزارش کهنه یا ساعت ناسازگار | خاکستری؛ اجازهٔ اجرا صادر نمی‌شود |

گزارش فقط ۱۲۰ ثانیه از زمان **مشاهده** تازه محسوب می‌شود؛ بازکردن دوبارهٔ
صفحه عمر آن را تمدید نمی‌کند. تغییر بیش از پنج ثانیهٔ ساعت نسبت به زمان
یکنواختِ مرورگر، پس از بازشدن صفحه، تازگی را نامعتبر می‌کند. این تشخیص
نیازمند ساعت محلی معتبر در آغاز است؛ سرویس زمانِ مستقل ساخته نشده است.
بدون JavaScript هم وضعیت پیش‌فرض نامعلوم است. پس از کهنه‌شدن، آخرین قفل
مشاهده‌شده با برچسب «آخرین مشاهده» قابل دیدن می‌ماند.

صفحه به شبکه متصل نیست. دکمه فقط تازگی همین گزارش را دوباره محاسبه می‌کند؛
برای دادهٔ تازه باید صادرکننده دوباره اجرا شود. HTML و JSON، خروجی مشاهده‌اند،
نه ورودی کنترل نگهبان. هیچ مسیر بازنشانی قفل، بازیابی، حذف شاهد یا تغییر
مبنای اعتماد به صفحه اضافه نشده است.

خروجی فقط کد ثابت، زمان، شمار رویداد، وضعیت و هش مبنا را دارد. متن درخواست،
رسید، مسیر خصوصی و استثنای خام وارد صفحه نمی‌شود. رندر از `textContent`
استفاده می‌کند، JSON در برابر بستن تگ script ایمن‌سازی می‌شود، و CSP فقط
هش اسکریپت و سبکِ همان قالب را مجاز می‌داند. شبکه، فرم و منابع بیرونی بسته‌اند.

## اجرا از checkout مورد اعتماد

Python 3.11 یا بالاتر لازم است. کد صادرکننده و قالب باید **پیش از اجرا**
از نسخهٔ بازبینی‌شده باشند. هش خودگزارش‌شده یا HTML دریافت‌شده، امضای مستقل
و شاهدِ اصالت آن نیست. نویسنده‌ای که فایل HTML یا کل دفتر و سرِ زنجیره را
بازنویسی کند، خارج از تضمین این نمونه است.

```sh
python3 examples/nasuraya_security/visual_status.py \
  --repo-root /trusted/zohraya \
  --manifest /trusted/config/guard-baseline.json \
  --expected-manifest-sha256 e477c0da0685fbedc01c5881d49c6e0842aea889a5ec54007070af4943467b93 \
  --alerts /private/alerts.sqlite \
  --output /private/new-observation
```

پوشهٔ خروجی باید تازه باشد؛ شواهد پیشین بازنویسی نمی‌شوند. `index.html` را
باز کنید. کد خروج صفر فقط برای مشاهدهٔ موفق است و برای سه حالت دیگر ۲ است.
خطای تولید خروجی هم اجازهٔ اجرای کار محسوب نمی‌شود. این فرمان دفتر مفقود را
نمی‌سازد و نگهبان را راه‌اندازی یا قفلش را باز نمی‌کند.

## شاهد و نتیجه

۳۶ آزمون Python موفق شدند: ۱۴ آزمون نگهبان پیشین، ۵ آزمون استفادهٔ مجدد
از تجربه، و ۱۷ آزمون صادرکننده. ۱۶ بررسی دیگر، JavaScript واقعیِ نما را در
Node VM اجرا کردند؛ از جمله کهنگی در صفحهٔ باز، تاریخ آینده، عقب‌رفتن ساعت،
دادهٔ ناقص و ناسازگاری ادعای سبز با قفل فعال. این‌ها آزمون منطق‌اند؛ رندر
پیکسلی و رفتار CSP در مرورگر واقعی در این نوبت آزمایش نشده است.

هر سه بدنهٔ اجرایی workflow محلی با موفقیت اجرا شدند. ورودی محافظت‌شده در
دو فرایند تازه، ابتدا یک گام و سپس صفر گام محاسبه کرد و رسید یکسان داد.
صادرکننده چهار رویداد همان دفتر را سالم خواند و بایت‌های دفتر تغییر نکردند.
وارسی استقرار محلیِ پیش‌تر راه‌اندازی‌شده نیز همین چهار رویداد، بدون قفل،
با منابع معتبر را دید. این مشاهده، استقرار میزبان یا پوشش همهٔ مسیرها نیست.

دو نمونهٔ جدا با خود نگهبان اجرا شدند: یک ورودی نامعتبر و سپس یک کار سالم
یک‌گامی هنوز «هشدار» نشان داد؛ سه ورودی نامعتبر بدون محاسبهٔ بدن، قفل و
«توقف» ساختند. خواندنِ دفتر مفقود «نامعلوم» شد و فایلی نساخت. همهٔ این
نمونه‌ها محلی و کنترل‌شده‌اند؛ آزمون حمله به سرویس بیرونی انجام نشد.

شواهد در `docs/evidence/defense-visual-v02/` هستند. `index.html` یک مشاهدهٔ
ذخیره‌شده است و پس از دو دقیقه عمداً نامعلوم نمایش داده می‌شود.

## اتصال و مبنای اعتماد

workflow جدید روی شاخهٔ `nasuraya/defense-visual-v02` و PRهای دارای تغییر
مرتبط اجرا می‌شود. مجوز اعلام‌شده فقط `contents: read` است؛ دو Action به
commit مشخص مخازن رسمی‌شان مقیدند. پیش از import پروژه، هش‌های ۶۸ فایل
نگهبان پیشین و چهار فایلِ صادرکننده/نما/آزمون بررسی می‌شوند. موفقیتِ CI
یک PR، تأیید مستقل محتوای همان PR یا مجوز تغییر مبنای اعتماد نیست.

هش فهرست ۶۸ فایل نگهبان تغییر نکرد:
`e477c0da0685fbedc01c5881d49c6e0842aea889a5ec54007070af4943467b93`.
هش فهرست چهار فایل تصویری:
`d88e37796ad7b61da0d3e3f54cab6b6ba1036c96966c8db4b9d645bf7e577351`.

پایش ساعتی مخزن و نگهبان رویداد PR هر دو در بررسی تنظیمات فعال بودند.
این نما به آن‌ها اتصال زنده ندارد. مبنای اعتماد آن پایش‌ها خودکار ارتقا
نیافت: main برابر `e5057324433842f8a8255d99d0bf4f904ccc4e3a` و نگهبان نسخهٔ
۰۱ برابر `939c483090371b4c8fe40048b2758295432d309e` باقی ماندند. شاخهٔ نسخهٔ
۰۱ دست‌نخورده است و تغییر تازه برای بازبینی در شاخهٔ جدا ثبت می‌شود.

درسِ ثبت‌شده: تصویر مفید باید زمان، عدم قطعیت، شاهد و اقدام بعدی را نشان
بدهد. نتیجهٔ این دور، کد و آزمایش مشخص است؛ افزایش کارایی عمومی امنیت یا
دفاع کامل در برابر حمله از این شمار نمونه استنتاج نشده است.
