# ناسورایا | لایهٔ انگیزشی میل، کنجکاوی، آرامش و خستگی (v0.1)
تاریخ: ۴ نوامبر ۲۰۲۶

## چه چیزی به تداش وصل شد؟
لایهٔ `motivation.py` به‌صورت **اختیاری** به همان
`ExperienceController`، چرخهٔ برنامه‌ریزی پیش از کنش و ثبت رسیدهای بومی
پیوند خورده است. مبنای آن PR #133 و حافظهٔ کاری PR #130 است.

**چهار عامل:**
- `desire_proxy`: مقدار **صریحاً تعیین‌شدهٔ عددی** از صفر تا یک.
  این متغیر یک جانشین محاسباتیِ *libido* است؛ سنجش میل واقعی،
  خودآگاهی، لذت جنسی، یا انگیزش زیستی نیست.
- `curiosity_proxy`: برآورد سادهٔ کم‌اطلاعی از شمار پیش‌بینی‌های قبلی
  و رویدادهای دارای رسید. «کنجکاوی حس‌شده» نیست.
- `calm_proxy`: از برانگیختگی عمومیِ مدل عاطفی و بار بدن
  شبیه‌سازی‌شده مشتق می‌شود. **برانگیختگی عمومی را با برانگیختگی
  جنسی یکی نمی‌گیریم.**
- `fatigue_proxy`: از مشاهدهٔ واقعی در همان شبیه‌ساز BodyLoop
  به دست می‌آید و همراه درد، فشار خواب، انرژی و سابقهٔ آسیب
  تصمیم پرخطر را محدود می‌کند.

این عوامل تنها بر امتیاز دو درخواست `walk` و `observe` اثر دارند.
مدل هیچ کنش جنسی، محرک بدنی، فرمان لگنی یا موتور تازه‌ای ایجاد نمی‌کند.
کنترل حفاظتی بومی همیشه تصمیم آخر را دارد و حافظهٔ کاری نیز
بعد از این لایه می‌تواند درخواست حرکت را کاهش دهد.

## مدار تجربهٔ نرم‌افزاری
`snapshot بومی → امتیازدهی انگیزشی → حافظهٔ کاری → تصمیم بومی → رسید → ثبت انگیزش/حافظه`

خروجی انتخاب قبل از مشاهدهٔ نتیجه ذخیره می‌شود. فقط رسید
موفق BodyLoop به‌عنوان بازخورد مصرف می‌شود؛ شکست اجرا
یا بازپخش همان شناسه، تجربهٔ تازه نمی‌سازد. شمار رویدادهای
ثبت‌شده و تجربه‌های قبلی در SQLite نگهداری و پس از راه‌اندازی
سرد قابل بازیابی است.

## اجرای قابل تکرار
فرمان‌های زیر از root همان checkout اجرا می‌شوند؛ دستور
`__main__` منابع بدن را با SHA بررسی و در فرایند جدا اجرا می‌کند:

```bash
python3 -m examples.nasuraya_body_loop motivation-test
python3 -m examples.nasuraya_body_loop motivation-demo --output-dir /tmp/tadash-motive-new
```

اجرای اختیاری روی نشست تازه:

```bash
python3 -m examples.nasuraya_body_loop start --fixture sleep --max-actions 3 --session /tmp/tadash-motive-body.sqlite
python3 -m examples.nasuraya_body_loop experience-enable --session /tmp/tadash-motive-body.sqlite
python3 -m examples.nasuraya_body_loop workspace-enable --session /tmp/tadash-motive-body.sqlite
python3 -m examples.nasuraya_body_loop motivation-enable --session /tmp/tadash-motive-body.sqlite --desire-proxy 0.9
python3 -m examples.nasuraya_body_loop motivation-step --session /tmp/tadash-motive-body.sqlite --decision-id one
python3 -m examples.nasuraya_body_loop motivation-status --session /tmp/tadash-motive-body.sqlite
```

فعال‌سازی مقدار میلِ مدل‌شده را تنظیم می‌کند و بدون دستور صریح
دوباره تغییر نمی‌دهد. هیچ فرایند دائمی و هیچ حالت پیش‌فرض
تحریک/تمایل جنسی وجود ندارد.

## ارزیابی
آزمون‌های با ورودی ساختگیِ مهندسی به‌طور جداگانه ثابت می‌کنند
که در وضعیت سالم و امتیازهای نزدیک، `desire_proxy` بالا
می‌تواند ترجیح را به اکتشاف تغییر دهد، اما با درد یا خستگی
این تغییر مسدود می‌شود. دمو با **۱۲ چرخهٔ واقعیِ نرم‌افزاری**
در چهار نشست و دو fixture `normal`/`sleep`، وضعیت
خاموش/روشن را با رسیدهای بومی مقایسه می‌کند؛ عدد نتیجه
فقط بعد از اجرای CI باید گزارش شود. داده‌ها نمایندهٔ جهان
واقعی نیستند و این آزمایش نتیجهٔ علم اعصاب یا وجود احساس
را اثبات نمی‌کند.

## مرزهای ایمنی و صداقت
بدون هزینه API، رمز، شبکهٔ خارجی، حرکت فیزیکی، دریافت
سیگنال جنسی از انسان، تولید محتوای اروتیک، تغییر وزن ChatGPT
یا ادعای آگاهی. اتصال مستقل PR #132 (موج خودکار و
بازیابی) هنوز انجام نشده است. این سند یک مدل انگیزشی
قابل‌اندازه‌گیری را گزارش می‌کند، نه تجربهٔ شهوت.
