# تجربهٔ پیشین در ورودی عامل API — نسخهٔ ۰٫۱

این گام بر PR #11 و commit `123467a` قرار دارد. شاخهٔ مستقل آن
`nasuraya/experience-api-v01` است. هدف، رساندن تجربهٔ مستند بدن به ورودی عامل و
اجرای یک بیدارباش واقعی با مدل زنده، بدون بازسازی حافظه یا تمدید خودکار اختیار بود.

## نتیجهٔ اجرای زنده

کلید قبلی از همان میزبان خصوصی بازیابی شد؛ اثرانگشت آن با گزارش ماندگاری قبلی
برابر بود. Site همچنان owner-only با صفر visitor و editor اضافی است و تغییری
در منبع، انتشار یا دسترسی آن انجام نشد. فایل محلیِ از قبل مصوب، خصوصی و خارج
از Git است؛ کلید تازه‌ای ساخته نشد. SDK قفل‌شدهٔ موجود، OpenAI 3.29.0، نصب شد.
بررسی فقط‌خواندنی فهرست مدل‌ها موفق بود و مدل `gpt-6-astra` در آن وجود داشت.

بدن همان fixture ذخیره‌شدهٔ آزمایش PR #11 بود: revision 3 و دو خاطرهٔ care،
همراه با تجربهٔ قدیمیِ درخواست walk و اجرای protect. میزبان صریحاً **یک مجوز
تازهٔ یک‌کنشی و شش‌ابزاری** برای هدف `experience-live-20261014` صادر کرد؛ سپس
زمان‌بند همان مجوز را مصرف کرد. زمان‌بند هیچ مجوزی صادر یا تمدید نکرد.

| سنجه | نتیجهٔ اندازه‌گیری‌شده |

## اتصال حافظه به ورودی

`experience.py` حداکثر سه تصمیم کاملِ همین زمینهٔ بدن با feedback تأییدشده را
به یک packet حداکثر ۴۰۹۶ بایتی تبدیل می‌کند. ترتیب از revision واقعی بدن می‌آید؛
ترتیب شناسهٔ هش یا نمایش SQL معیار تازگی نیست. ترجیح درخواست، انتخاب هسته،
کنش واقعی، تطابق پیامد، نسخه‌های قبل/بعد، شناسه و هش منبع و حداکثر سه شناسهٔ
بازخورد بازیابی‌شده در آن هستند.

checkpoint کامل، وضعیت کامل بدن، گزینه‌های امتیازگذاری، یادداشت آزاد، متن
دلیل، کلید یا حافظهٔ خصوصی در این packet قرار نمی‌گیرند. مقدار کنش فقط از
واژگان بومی و شناسه‌ها از قالب محدود پذیرفته می‌شود. مدل همان سه ابزار محدود
قبلی را دارد؛ packet مجوز بازپخش یا بودجهٔ تازه نمی‌دهد.

`BodyAPIHost.continuation_input()` متن آغازین هدف حفظ‌شده را با این packet
می‌سازد. در `APIRecovery`، این تابع تنها هنگام ساخت نشست تازه فراخوانده می‌شود؛
پیش از درج رزرو transport، اعتبار ورودی بررسی می‌شود. خطای ساخت context، یک
رزرو مبهمِ ایجاد نشست تولید نمی‌کند. پس از رزرو، سازوکار نامعلوم‌بودن ایجاد نشست
و جلوگیری از تکرار همان قرارداد قبلی است. در reconnect همان session، context
دوباره ساخته یا ارسال نمی‌شود؛ بازخوانی terminal نیز نه شبکه و نه context لازم دارد.

در نمونهٔ زنده، پارامتر `input` درست در مرز `SDK.sessions.create` خوانده و با
packet موردانتظار مقایسه شد. پس از آن همان متد SDK واقعی فراخوانده شد؛ ابزارهای
مدل، کنش بدن و تکمیل نشست از سرویس واقعی دریافت شدند. این شواهد، انتقال context
و اجرای واقعی را تأیید می‌کنند؛ میزان استفادهٔ معنایی مدل از هر رکورد یا بهبود
علّی تصمیم در مقایسه با نبود context در این آزمایش سنجیده نشده است. تغییر
وزن مدل نیز در این گام رخ نمی‌دهد.

## آزمون و بازتولید

۸ آزمون تازهٔ تجربه و هر ۵۵ آزمون API/تداوم با SDK نصب‌شده موفق بودند؛ هیچ آزمون
SDK در این اجرای جدید skip نشد. سناریوهای context محدود، رد متن آزاد/مقادیر
مسموم، فقط پیامدهای تأییدشده، ترتیب نسخه‌ها، رسیدن packet به پارامتر واقعی create،
رد ورودی پیش از رزرو transport، عدم ارسال مجدد در reconnect و terminal replay
بدون شبکه بررسی شدند. CI اکنون experience-test را نیز اجرا می‌کند.

بدون شبکه و کلید:

```sh
python -m examples.nasuraya_body_loop experience-test
python -m examples.nasuraya_body_loop api-test
```

با SDK پین‌شده، آزمون دوم شاخه‌های SDK را هم پوشش می‌دهد. فرمان صریح
`experience-live-check` فقط یک بیدارباش API **از قبل ثبت‌شده** را اجرا می‌کند؛
خودش authorize یا schedule نمی‌سازد. خروجی باید تازه باشد:

```sh
python -m examples.nasuraya_body_loop experience-live-check \
  --session /private/session.sqlite --wake-id previously-approved-wake \
  --output-dir /private/new-live-check
```

مانند فرمان api، این فرمان فقط در انتخاب صریح، کلید از قبل مصوب را می‌خواند.
مدل، هدف، موعد، expiry و سقف تلاش از قرارداد ثابت بیدارباش می‌آیند. نتیجهٔ API،
trace کاهش‌یافته و summary در پوشهٔ خصوصی ثبت می‌شوند. شمار context در مرز create
با نتیجهٔ API جدا نگه داشته می‌شود؛ صرف آماده‌سازی یا تلاش ارسال، موفقیت مدل نیست.

## وضعیت حفظ‌شده

پایگاهِ پس از اجرای زنده، وضعیت بدن revision 4، هدف‌های قبلی و هدف زندهٔ کامل،
شمارنده‌های مصرف، دو خاطرهٔ care، بازخورد تازه، مجوزها و رسید terminal را دارد.
نسخهٔ کامل خصوصی همراه با خلاصهٔ نتیجه برای ادامه نگه‌داری می‌شود؛ در Git قرار

بعدی، بازیابی کلید از مسیر خصوصی ثبت‌شده و صدور صریح مجوز بعدی لازم می‌مانند؛
خواندن وضعیت کامل‌شده اجازهٔ خودکار ایجاد مأموریت تازه نمی‌دهد.

چرخهٔ بازبینی: نبودن فایل محلی ابتدا مانع اجرای زنده به نظر می‌رسید؛ گزارش
معتبر ماندگاری نشان داد مسیر بازیابی موجود است. همان مسیر بازیابی و بررسی شد،
context به ورودی وصل شد، اجرای تک‌چرخه‌ای انجام شد و بازخوانی سرد بدون شبکه
موفق بود. نتیجه در سطح کد، اجرای مدل و checkpoint جدا ثبت شده است.
