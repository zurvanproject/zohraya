# اختیار اجرایی محدودِ پژوهش — نسخهٔ ۱

هدف درخواست سهند در ۱۸ اکتبر ۲۰۲۶: افزایش اختیار مشاهده‌گر پس از ورود PR #49
به main. مبنا `d89d0995ebff9be0b441bf81c2aded1371d83ff2` است.

تغییر این نسخه: من در مسیر پژوهشِ بدن محاسباتی، پس از فعال‌سازی صریحِ یک نشست،
می‌توانم مشاهده کنم، با استفاده از ارزیابی قابلیت موجود «راه‌رفتن» یا «مشاهده»
را ترجیح بدهم و درخواست را به مسیر اجرایی موجود بفرستم. انتخاب نهایی هنوز از
DecisionCore/ReflectionCycle و نگهبان‌های native می‌گذرد. این اختیار در کد
عاملِ شبیه‌سازی است؛ اتصال گفت‌وگوی ChatGPT به یک فرایند همیشه‌روشن نیست.

## قرارداد اختیار

- تنها روی `BodyLoop` موجود، با mode برابر bounded و بودجهٔ اولیهٔ ۱ تا ۳ اقدام.
- از همان قفل SQLite، بودجهٔ پایدار، ثبت تصمیم، بازخورد و رسیدِ اجرا استفاده می‌شود.
- هر اقدام ۰٫۱ تا ۱ ثانیهٔ شبیه‌سازی است؛ یک فراخوانی run حداکثر سه اقدام دارد.
- مشاهده‌گر #49 تغییر نمی‌کند؛ اختیار نوشتن در ماژول مستقل `controller.py` است.
- انتخاب اولیه از `audit_self_model.assess` موجود می‌آید؛ معادلهٔ بدن، سیاست
  امنیتی یا action head پژوهشی تغییر نمی‌کند. این یک سیاست یادگرفته‌شده نیست.
- اجرای صریح CLI در فرایند جدا با کپی منابع native تأییدشده انجام می‌شود.
  فرایند فرزند محیط حداقلی می‌گیرد و کلید API یا توکن به آن ارث نمی‌رسد.
- init فقط نشست تازهٔ مصنوعی می‌سازد؛ فایل یا وضعیت قبلی بازنشانی نمی‌شود.
  ساخت fixture شامل warm-up تاریخی هفت ثانیهٔ شبیه‌سازی است؛ شمار اقدام‌های
  کنترل‌گر از این ساخت fixture جداست.

## توقف و نتیجهٔ نامعلوم

قبل از درخواست اجرا، قصد پژوهشی ثبت می‌شود. پس از اجرا، رسید موجود native
به آن وصل می‌شود. این ثبت جدید و اثر native یک تراکنش واحد نیستند؛ به همین
دلیل فاصلهٔ قطع صریحاً پوشش داده شده است:

- نتیجهٔ تکمیل‌شده: درخواست همسان فقط همان رسید را برمی‌گرداند؛ اثر تکرار نمی‌شود.
- native کامل، ثبت پژوهش قطع‌شده: رسید native بازیابی و متصل می‌شود، بدون اجرا.
- native غایب یا running: درخواست باز می‌ماند و کار تازه متوقف می‌شود؛ retry
  خودکار وجود ندارد. رفع این وضعیت نیازمند بررسی صریح نتیجه است.
- شکست ثبت‌شدهٔ native: اختیار متوقف می‌شود و بودجه بازپرداخت نمی‌شود.
- pause و resume پایدارند؛ resume بودجه را پر نمی‌کند و قصد حل‌نشده را پاک نمی‌کند.

این کنترل‌گر sandbox نیست و مانع کد مخرب با دسترسی کامل به فرایند یا SQLite
نمی‌شود. توقف تعاونی و بررسی منبع برای قرارداد محلی و میزبان مورداعتماد است.
نویسندهٔ هم‌زمان خارج از قفل، ویرایش خصمانهٔ فایل و عملگر فیزیکی موضوع این
نسخه نیستند.

## اجزای بازاستفاده‌شده

`observe_native_body` و snapshot برای مشاهدهٔ معتبر؛ `assess` برای همان
محدودیت‌های قبلی؛ `BodyLoop.observe/step/status` برای مشاهدهٔ تازه، سقف اقدام
و اجرا؛ `ReflectionCycle` و `ReflectiveBody` برای تصمیم، بازخورد، checkpoint
و رسید. هیچ موتور اجرای موازی یا دفتر بودجهٔ مستقل ساخته نشده است.

رکورد کوچک افزوده‌شده در جدول meta فقط فعال‌بودن اختیار، اثرانگشت منبع و
اتصال شناسهٔ پژوهش به رسید native را نگه می‌دارد. تمام درخواست native، زمان، مدت و ورودی اجرا با قصد ثبت‌شده تطبیق داده
می‌شوند؛ رسید نامرتبط حتی با شناسهٔ یکسان پذیرفته نمی‌شود. بزرگ‌کردن سقف این نسخه با تغییر آرگومان CLI
ممکن نیست؛ سقف بالاتر نیازمند نسخه و بازبینی تازه است.

## اجرا و ارزیابی

دستورهای دقیق در `examples/nasuraya_research/README_FA.md` هستند. آزمون‌ها
در یک worker جدا اجرا می‌شوند:

```bash
python -S -m examples.nasuraya_research.control test
```

نتایج نهایی، تعداد آزمون‌ها و نمونه‌های واقعی اجرا پس از تکمیل در
`docs/evidence/research-authority-v01/` ثبت می‌شوند. صرف وجود کد یا انتخاب
ترجیح، موفقیت حرکت، بهبود یادگیری یا خودآگاهی را اثبات نمی‌کند؛ رسید واقعی
ممکن است حرکت را رد کند و نتیجهٔ متفاوتی ثبت کند.

## تصمیم و معیار پذیرش

مشاهده‌شده: مسیر #49 فقط خواندنی بود و BodyLoop پیشاپیش بودجه، ثبت نتیجه،
بازخورد و نگهبان native داشت. طراحیِ افزوده: استفاده از همان مسیر با سقف سه
اقدام و ذخیرهٔ قصد پژوهشی برای جلوگیری از تکرار اثر هنگام قطع. این سقف یک
انتخاب مهندسیِ این پایلوت است، نه ترجیحی که به کاربر نسبت داده شود.

معیار پذیرش: اقدام واقعی در شبیه‌ساز ثبت شود؛ نمونهٔ خواب درخواست مشاهده
بدهد؛ نگهبان native ترجیح اشتباه را رد کند؛ توقف و بودجه بعد از restart
باقی بمانند؛ رسید تکراری و نتیجهٔ نامعلوم موجب اجرای مجدد نشوند؛ رسیدی با
شناسهٔ یکسان ولی درخواست/بدن متفاوت پذیرفته نشود؛ منابع بدن و هستهٔ تصمیم
بدون تغییر بمانند.

در بازبینی، دو اصلاح مشخص انجام شد: تولید شناسهٔ تازه پس از درخواست نام‌دار
و تطبیق کامل رسید native با قصد قبلی. اثرانگشت اختیار نیز کد کنترل‌گر،
مشاهده‌گر، snapshot، adapter و BodyLoop host را پوشش می‌دهد. آزمون‌های
سناریوی منفی برای این مرزها اضافه شدند. این‌ها رفع نقص و قراردادهای
عملیاتی‌اند؛ ادعای بهبود عمومی هوش یا یادگیری نیستند.

## نتیجهٔ محلی تأییدشده

۲۳ آزمون اختیار اجرایی بدون شکست و skip گذشتند. ۲۲ آزمون استانداردِ مشاهده‌گر،
۹۹ آزمون native/تصمیم و ۱۶ آزمون پل بدن نیز موفق شدند؛ مجموع ۱۶۰ آزمون یکتا.
سه آزمون هندسه در محیط بدون Torch صریحاً skip شدند؛ کد هندسه تغییر نکرده است.

در اجرای واقعی CLI با فرایندهای جدا، نمونهٔ normal سه walk و نمونهٔ sleep
سه observe ثبت کرد. هر دو پس از restart بودجهٔ صفر داشتند؛ اقدام چهارم رد
شد و بازخوانی step-1 هیچ اثر تازه‌ای ایجاد نکرد. شش چرخه روی fixtureهای
تازه و دورریختنی بود، نه وضعیت خصوصی یا بدن فیزیکی.

آزمون نگهبان با ترجیح بالادستیِ عمداً نادرست، protect واقعی دریافت کرد. قطع
پس از commitِ native بدون اجرای دوباره بازیابی شد. درخواست هم‌شناسه با
مدت یا وضعیت بدن متفاوت رد شد و حل‌نشده باقی ماند.

۲۰۷ فایل قبلی main بدون تغییرند. فقط README پژوهش و گردش‌کار اختصاصیِ
آزمون پژوهش تغییر کرده‌اند؛ گردش‌کار فقط یک گام آزمون افزوده و مجوز،
schedule یا secret جدیدی ندارد. نتیجهٔ GitHub CI باید از PR همان سرشاخه
خوانده شود و در این شمار محلی منظور نشده است.
