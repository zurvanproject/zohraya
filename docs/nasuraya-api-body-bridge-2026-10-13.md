# اتصال عامل API به بدن موجود — ۱۳ اکتبر ۲۰۲۶

عامل قبلی فقط چهار ابزار کارگاه مصنوعی را اجرا می‌کرد. اکنون همان runner
می‌تواند یک میزبان بدنی بگیرد: مشاهدهٔ کمینه، ارزیابی پیشرفت و درخواست ترجیح
اقدام از مسیر DecisionCore → ReflectionCycle → UnifiedBody. معادلات بدن و
۷۰ فایل منبعِ بازیابی‌شده عوض نشده‌اند؛ هسته یا بدن دوباره ساخته نشده است.

شش ایراد بازبینی اولیه نیز در لایهٔ اتصال و workflow اصلاح شده‌اند: تفکیک
شکست اجرا از پایان ثبت دفتر، قفل inode و رد hard link، اعتبارسنجی زودهنگام
مدت/شناسه، مجوز خصوصیِ session/export، قفلِ فرمان guided و CI آینهٔ حرکتی.
آینه همان نمونه‌های عمومی موجود را حفظ می‌کند؛ آزمون همهٔ مقادیر نمایشی را
بازتولید می‌کند و برابری بایت‌به‌بایت checkpointهای تاریخی را ادعا نمی‌کند.

## قرارداد اعتماد

- مدل فقط walk یا observe را ترجیح می‌دهد. هسته رتبه‌بندی می‌کند و بدن وتو
  و ممیزی بقای خود را حفظ می‌کند. نه مدل و نه ابزار API مستقیماً state را می‌نویسند.
- هر اقدام، مشاهدهٔ تازه با هش همان بدن، از همان session و turn می‌خواهد.
- بودجهٔ بدن از دفتر موجود می‌آید؛ سقف API نیز در همان دفتر برای restart ثابت است.
- result بر مبنای session/turn/call پایدار می‌شود؛ هم fingerprint payload و
  هم نتیجه نگه داشته می‌شوند. متن آرگومان‌های ناشناخته یا خطاهای دلخواه ذخیره نمی‌شوند.
- crash پس از commit بدن و پیش از ثبت پاسخ، از تصمیم کامل بازیابی می‌شود.
  crash با نتیجهٔ نامعلوم خودکار retry نمی‌شود و درخواست بعدی را مسدود می‌کند.
- فقط خلاصهٔ fixture تولیدشده و رسید کاهش‌یافته به API ارسال می‌شود؛ checkpoint
  کامل، دفتر خصوصی، یادداشت کاربر و اطلاعات احراز هویت ارسال نمی‌شوند.
- محیط API همان none موجود است؛ ابزار اضافی، زیرعامل، actuator واقعی یا
  اجرای پس‌زمینهٔ دائمی فعال نشده است. جریان remote پس از restart خودکار resume ندارد.

## شواهد اجرا

۱۳ آزمون تازهٔ ابزارهای بدن با SDK نصب‌شده موفق بودند. شامل read-only، ترجیح
مدل، وتوی بدن، یادآوری بازخورد، جلوگیری از وام‌گرفتن مشاهده از session/turn
دیگر، حفظ بودجه، رد پارامتر نامعتبر، replay پس از reopen، crash پس از commit،
مسدود کردن عملیات نامعلوم و serialization واقعی SDK در transport کنترل‌شده.

۱۶ آزمون اتصال و ۶۰ آزمون عامل/API موجود دوباره موفق شدند. ۹۹ آزمون بدن/هسته
از بازبینی قبلی حفظ‌اند و منابع آن‌ها همان manifest معتبر است. آزمون آینه
سه مورد مستقل دارد و در workflow اجرا می‌شود. تست‌های CI کلید زنده نمی‌خواهند.

## اجرای زنده و محدودیت فعلی

یک session واقعی فقط‌خواندنی با مدل gpt-6-astra و سقف صفر اقدام بدنی ساخته شد.
پیش از اجرای هر ابزار، جریان خطای داخلی و پایان مهلت داشت؛ session حذف شد.
هش ابتدایی و پایانی بدن یکسان بود و شمار اقدام صفر ماند. درخواست تشخیصی
جداگانهٔ Responses API، HTTP 429 با کد صریح billing_not_active داد. آن تشخیص
مانع صورتحساب را نشان می‌دهد؛ علت خطای داخلی Agents از آن به‌تنهایی اثبات نمی‌شود.
هیچ خرید اعتبار، تغییر صورتحساب یا تلاش بی‌پایان انجام نشد.

کلید تازه در فایل محلیِ خصوصی و نادیده‌گرفته‌شدهٔ Git نگهداری می‌شود. کلید،
دفتر SQLite، checkpoint کامل و session ID زنده در مخزن عمومی قرار نمی‌گیرند.

پس از فعال‌شدن صورتحساب، ابتدا فرمان فقط‌خواندنیِ README در session جدید اجرا
شود. موفقیت turn باید همراه با مشاهده و ارزیابیِ ابزار باشد؛ صرف ساخت session
یا پایان turn، اثبات اتصال زنده نیست. سپس یک چرخهٔ محدود روی fixture جدید
قابل‌آزمون است. merge مخزن در این کار انجام نمی‌شود.
