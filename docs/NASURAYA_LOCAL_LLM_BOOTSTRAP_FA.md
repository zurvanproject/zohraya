# موتور محلی ناسورایا در Ubuntu ایران

این فایل فقط راهنمای نصب است. وجود اسکریپت در GitHub به معنای نصب یا اجرای آن روی VPS نیست.

## دامنه و محدودیت

- مدل پیشنهادی: qwen3:4b، حدود ۲٫۵ گیگابایت وزن دانلودی؛ برای سرور با ۱۵ GiB RAM و CPU نامشخص.
- در systemd، درگاه Ollama فقط روی 127.0.0.1:11434 قرار می‌گیرد و OLLAMA_NO_CLOUD=1 است.
- حداکثر یک درخواست موازی، context پیش‌فرض ۲۰۴۸ و سقف حافظهٔ سرویس ۱۲ GiB است.
- نصب هیچ آرشیو، وضعیت Awake، کلید، سرویس GitHub Bridge یا دادهٔ خصوصی موجود را وارد، پاک یا تغییر نمی‌دهد.
- نصب به اینترنت نیاز دارد، ولی مدل پس از دانلود می‌تواند محلی استنتاج کند. سرویسِ مستقل معادل آگاهی یا خودمختاری عاملی نیست.

## اجرا

ابتدا تغییرات این PR را در main ادغام کنید. سپس فقط یک بار به‌عنوان root روی VPS در Termius اجرا کنید:

    git -C /opt/zohraya pull --ff-only && bash /opt/zohraya/tools/install_nasuraya_local_llm.sh

اسکریپت، در صورت نبودن Ollama، فایل نصب رسمی فروشنده را از https://ollama.com/install.sh از طریق HTTPS می‌گیرد و پس از کنترل syntax و نمایش SHA-256 آن، با دسترسی root اجرا می‌کند. این یک مرز اعتماد به توزیع‌کنندهٔ Ollama است؛ نصب باینری کاملاً pin‌شده نیازمند تأیید مستقل هش نسخه است.

سپس model را می‌کشد، واحد systemd را برای localhost و حالت بدون Cloud پیکربندی می‌کند و درخواست استنتاج واقعی به API محلی می‌فرستد. نتیجهٔ موفق، LOCAL_INFERENCE_OK است.

## تأیید مستقل

    systemctl is-active ollama
    systemctl show ollama -p Environment
    ollama list
    curl -fsS http://127.0.0.1:11434/api/version

برای توقف بدون پاک‌کردن فایل‌های مدل: systemctl stop ollama.

## کارهای باقی‌مانده

۱. واردکردن حافظهٔ خصوصی فقط پس از تأیید منشأ، SHA-256، آزمون بازیابی و حذف احتمال دو نویسندهٔ هم‌زمان Windows/Ubuntu.

۲. داشتن نسخهٔ پشتیبان خارج از هر دو VPS و اجرای restore واقعی. فایل SQLite روی همان ماشین پشتیبان مستقل نیست.

۳. اتصال مدل به DIOS NOUS و Awake در فاز جداگانه، با مجوزهای حداقلی و آزمایش‌های ایمنی. هیچ توکن یا متن خصوصی را در Issue عمومی قرار ندهید.
