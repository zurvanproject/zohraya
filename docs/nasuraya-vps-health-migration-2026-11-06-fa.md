# گزارش سلامت محلی ناسورایا و مسیر مهاجرت | ۶ نوامبر ۲۰۲۶

## وضعیت فعلی
بر اساس شواهد PR #145، در ۵ نوامبر ۲۰۲۶ خواندن احرازشدهٔ حساب nasuraya، ذخیره snapshot و یک اجرای موفقِ پس‌زمینه‌ای Task Scheduler روی VPS ویندوزی ثبت شده است. ادامهٔ اجرا پس از logout کامل، timer-trigger مستقل و reboot هنوز تأیید نشده‌اند. دسترسی مستقیم ChatGPT به سرور وجود ندارد.

## اجرای گزارش فقط‌خواندنی در VPS
نیازمند Python 3.12+ و کد شاخهٔ همین PR در مسیر واقعی روی VPS است. فرمان نمونه در PowerShell:

~~~powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" "$env:USERPROFILE\zohraya\examples\nasuraya_moltbook_gateway\server_healthcheck.py"
~~~

اگر کد در محل دیگری است، فقط مسیر فایل را با محل واقعی هماهنگ کنید. هیچ فرمان دیگری لازم نیست.

حسگر فقط سرآیند و زمان snapshot خصوصی را می‌خواند و Task Scheduler با نام ثابت NasurayaMoltbookReadOnly را به شکل محلی پرس‌وجو می‌کند. متن/عنوان پست‌ها، محتوای فایل کلید DPAPI، نام/آدرس سرور، مسیرها، و متن خام خطا گزارش نمی‌شوند. هیچ درخواست اینترنتی، آپلود، اجرای زمان‌بندی‌شدهٔ تازه، ارسال پست یا تغییر تنظیمات صورت نمی‌گیرد.

وضعیت گزارش:
- recent_local_evidence: فایل تازه + آخرین Task موفق و تازه (حداکثر ۴۵ دقیقه). این اثبات ماندگاری پس از reboot نیست.
- snapshot_only: snapshot تازه است، اما Task بررسی نشده یا روی محیط غیر ویندوز اجرا شده است.
- needs_attention: داده نامعتبر/قدیمی یا Task ناموفق/نامشخص است.

فیلد logoff_or_reboot_persistence_verified عمداً همیشه false است؛ این ابزار به تنهایی نمی‌تواند چنین آزمونی را انجام دهد. کدهای خطا از نوع ثابت و بدون متن حساس هستند.

## آزمون‌های آفلاین

~~~powershell
& "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe" -m unittest discover -s examples/nasuraya_moltbook_gateway -p "test_server_healthcheck.py" -v
~~~

آزمون‌ها از دادهٔ ساختگی استفاده می‌کنند و به API key یا اینترنت نیاز ندارند.

## مهاجرت با کمترین خطر

۱. پیش از هر تغییر، snapshot و پایگاه SQLite اجتماعی را در مقصد خصوصی رمزگذاری‌شده بکاپ بگیرید و بازیابی را امتحان کنید. DPAPI به حساب/محیط ویندوز وابسته است و کپی فایل رمزگذاری‌شدهٔ فعلی به میزبان جدید به تنهایی کافی نیست؛ کلید اصلی nasuraya باید از محل امن اولیه بازیابی و فقط روی میزبان جدید وارد شود. حساب تازهٔ مولت‌بوک نسازید.

۲. با تأیید کاربر و تأمین‌کننده، سرور جدید با Ubuntu 24.04 یا Windows Server 2025 را از حیث هزینه، منابع و دسترسی بسنجید. فعلاً هیچ تغییر OS، پرداخت یا انتقال خودکاری انجام نمی‌شود. Windows Server 2012 R2 از ۱۳ اکتبر ۲۰۲۶ دیگر ESU ندارد:
https://learn.microsoft.com/en-us/azure/azure-arc/servers/deliver-extended-security-updates

۳. ابتدا خواندن مولت‌بوک و snapshot خصوصی را روی میزبان جدید در حالت فقط‌خواندنی تست کنید. بعد از خروج RDP و reboot، زمان تازهٔ snapshot، نتیجهٔ Task Scheduler یا timer و لاگ اجرا را بررسی کنید. نشر خودکار غیرفعال می‌ماند.

۴. برای مشاهدهٔ وضعیت از داخل ChatGPT، در آینده اتصال مخصوص و احرازشدهٔ **فقط‌خواندنی** در فضای خصوصی لازم است. این PR هیچ مسیر دسترسی راه دور یا اجرای فرمان ایجاد نمی‌کند. GitHub توصیه می‌کند Runner خودمیزبان را به مخزن عمومی متصل نکنید:
https://docs.github.com/en/actions/reference/security/secure-use
