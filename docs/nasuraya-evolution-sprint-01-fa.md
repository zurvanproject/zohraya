# گزارش فنی فارسی، NASURAYA EVOLUTION SPRINT 01
تاریخ: 2026-10-16

## مبنا و محدوده
شاخه از nasuraya/metacognitive-api-v01 منشعب شده است، نه از main؛ زیرا SelfModel و پل عامل/بدن در main هنوز ادغام نشده‌اند. زنجیره PRهای پس از این مبنا، از جمله وزن‌های مدل زبانی، در این شاخه وارد نشده‌اند تا نتیجه‌های آموزش با ارزیابی تجربی مخلوط نشوند.

## پیاده‌سازی این تغییر
ماژول experiential_sprint.py از تابع forecast در monitor.py و آستانه‌های موجود POLICY استفاده می‌کند و هیچ پایگاه داده، شبیه‌ساز بدن یا مکانیسم کنترل امنیتی جدیدی نمی‌سازد. recommend یک پیشنهاد فقط-محدودکننده ارائه می‌دهد؛ «candidate_under_native_guards» مجوز اجرا نیست. محدودیت‌های بومی بدن همچنان نافذند. وجود نتیجه نامعلوم باعث توقف می‌شود. جدول counts باید از verify موجود SelfModel اخذ شود؛ جمع‌آوری تجربه واقعی همچنان صرفاً مسیر begin/finish مبتنی بر رسید معتبر را طی می‌کند.

تابع compare_arms سه بازوی مستقل دارد: A بدون حافظه، B با شمارش‌های اولیه منجمد، C با به‌روزرسانی پس از هر بازخورد. پیش‌بینی‌های هر سه بازو قبل از آشکار شدن نتیجه همان نمونه محاسبه می‌شوند. شناسه تکراری رد می‌شود. خروجی شامل پیش‌بینی‌های هر نمونه، نرخ پذیرش درست/نادرست، Brier و شمارنده‌های نهایی C است. ورودی‌ها توسط فراخواننده فراهم می‌شوند و تابع نتیجه‌ای نمی‌سازد.

## محدودیت علمی
مقایسه روی نمونه‌های ساختگی فقط یک آزمون قراردادی و الگوریتمی است و اثر واقعی بر عملکرد بدن محاسباتی یا عامل API را اثبات نمی‌کند. هیچ حرکت فیزیکی، حس ذهنی یا آگاهی پدیداری از این کد استنباط نمی‌شود. داده‌های آزمون با نمونه‌های ارزیابی واقعی هم‌خانواده و مستقل در نظر گرفته نمی‌شوند مگر از پیش جدا و مستند شده باشند. فهرست context/label در حافظه آزمایشی خود مدل اصلی نوشته نمی‌شود.

## مرحله بعد برای ارتقای معتبر
برای اعتبارسنجی علّی، خروجی‌های تأییدشده SelfModel.finish از دو یا چند خانواده موقعیت به مجموعه train/test مستقل با پروتکل ازپیش‌ثبت‌شده تبدیل شوند، با محاسبه فاصله اطمینان و کنترل کیفیت حافظه. تا آن زمان کنترل تطبیقی به مسیر اجرایی Agent API متصل نمی‌شود. مسیرهای ایمنی، هویت ثابت، وزن مدل و کد native تغییر نکرده‌اند.

## دستور اجرای آزمون

```bash
python3 -m unittest examples.nasuraya_self_model.test_experiential_sprint -v
```

نتایج CI باید مستقلاً بررسی شوند؛ صرف افزوده‌شدن تست به workflow معادل موفقیت آن نیست.
