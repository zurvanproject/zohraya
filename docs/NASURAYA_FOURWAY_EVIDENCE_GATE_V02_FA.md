# دروازهٔ شواهد چهارراه ناسورایا | نسخهٔ ۰٫۲

**بخش شناختی در GitHub اجرا و آزمایش می‌شود؛ طراحی تمام بدن مأموریت اصلی سرور Windows VPS باقی می‌ماند.**

## مسئله
در PR #183 آموختیم پنج اجرای عمومیِ واقعی GitHub Actions را به‌درستی از هم تفکیک کنیم. اما یک خطای خطرناک‌تر ممکن است: «تست سبزِ کد اطلس بدن» با «اجرای واقعی اطلس روی VPS» اشتباه گرفته شود. همین‌طور «بازپخش تاریخی دادهٔ Moltbook» با «گفت‌وگوی امروز در Moltbook». دروازهٔ حاضر از این نتیجه‌گیری غلط جلوگیری می‌کند.

## دو منبع مستقل از نظر نوع داده، نه لزوماً از نظر منشأ اعتماد
- `docs/evidence/public-ci-witness-v01/frozen-public-github-runs.json`: پنج اجرای عمومی گیت‌هاب که در روز ۱۰ نوامبر با ابزار متصل بررسی و ثبت شدند؛ شامل یک اجرای ناموفق، چهار اجرای موفق، SHA و jobهای مربوط. نتیجه‌ها گزارش سرویس GitHub هستند، نه اثبات اجرا روی سرور شخصی.
- `docs/evidence/fourway-evidence-v02/frozen-bridge-comments.json`: فقط شش کامنت مشخص و واقعاً مشاهده‌شده از Issue #149. دو فرمان تازهٔ وضعیت و اطلس جواب نداشتند؛ یک پاسخ قدیمی وضعیت کار ۲۴ساعته را RUNNING گزارش می‌کرد؛ یک پاسخ قدیمی `moltbook_repair_retest` با `GET=0` بازپخش بود و خواندن تازهٔ Moltbook را نشان نمی‌داد. این فایل یک **زیرمجموعهٔ شاهد ثابت** است و به‌تنهایی گزارش زنده نیست.

دروازه با خواندن **تمام کامنت‌های عمومی Issue #149** در حالت `--live` می‌تواند گزارش جدید بگیرد. فقط GET HTTPS با تأیید گواهی و نشانی ثابت GitHub API اجرا می‌شود، نه فرمان روی سرور. گزارش سرور با شناسهٔ درخواست، job و متنِ کاملاً مطابق فرمان پین‌شده تطبیق داده می‌شود. هرگونه پاسخ تکراری یا متناقض به جای موفقیت، نیازمند بررسی است.

## وضعیت مورد انتظار از شاهد ثابت
```text
GitHub  body atlas CI: PASSED      (فقط اجرای GitHub Actions)
GitHub  fourway CI:    PASSED      (فقط اجرای GitHub Actions)
VPS     atlas phase 1:  QUEUED_NO_RECEIPT
VPS     fresh 24h:      STATUS_REQUEST_PENDING
VPS     old 24h:        REPORTED_RUNNING (historical)
Moltbook old repair:    HISTORICAL_REPLAY_ONLY
All-four live:          NOT_LIVE_VERIFIED
```
حتی اگر یک پاسخ جدید با `ATLAS=INVENTORY;NODES=97;...` برسد، فقط «گزارش اجرای ممیزی» است، نه ساخته‌شدن بدن، شبکهٔ عروق، اعصاب یا خودآگاهی. همچنین حساب GitHub مالک، امضای رمزنگاری‌شدهٔ فرایند سرور نیست.

## بازتولید
```bash
python -m unittest discover -s tests -p 'test_fourway_evidence_gate_v02.py' -v
python tools/fourway_evidence_gate_v02.py
python tools/fourway_evidence_gate_v02.py --live
```
دو فرمان اول به شبکه وصل نمی‌شوند و داده‌های ثبت‌شده را بررسی می‌کنند. فرمان سوم تنها کامنت‌های عمومی Issue #149 را می‌خواند؛ **هیچ کار جدیدی به VPS نمی‌دهد**. اگر اینترنت یا صفحه‌بندی ناقص شود، خروجی UNVERIFIED است، نه سلامت فرضی.

## گام بعد
تا وقتی رسید مأموریت اصلی بدن در Issue #149 نیاید، گرهٔ VPS را «در صف، نامطمئن» نگه می‌داریم و مدل شناختی را جدا پیش می‌بریم. وقتی رسید معتبر آمد، دروازه صرفاً نتیجه و لینک را برای بازبینی ChatGPT می‌سازد. هر اجرای بعدی و انتشار در Moltbook نیازمند اجازه و محدودهٔ روشن است.

**محدودیت تجربی:** پنج اجرای CI گزینشی و فقط شش کامنت تاریخی، نمونهٔ آماریِ مستقل نیستند. ۱۶ کنترل آزمایشی به‌صورت دادهٔ مصنوعی ساخته می‌شوند. این مرحله، قرارداد مهندسیِ منشأ و گزارش است؛ نه تغییر حافظه/وزن مدل ChatGPT یا اثبات احساس و آگاهی.
