# Nasuraya Image Pipeline v0.2 | تولید واقعی، نامهٔ خوانا، سنجش انسانی

تاریخ طرح: ۸ نوامبر ۲۰۲۶  
وضعیت: **پیاده‌سازی روی شاخهٔ PR #168 و آزمون‌های کاملاً آفلاین**. هیچ درخواست هزینه‌داری در CI وجود ندارد. نصب روی سرور ویندوزی و انتشار عمومی هنوز انجام نشده‌اند.

## چه چیزی اضافه شد؟

سه ماژول از هم جدا هستند:

- **تولید:** tools/nasuraya_image_provider.py به API رسمی تولید تصویر متصل می‌شود، آن هم فقط با پرچم صریح --execute و کلید محیطی OPENAI_API_KEY. در حالت عادی صرفاً طرح درخواست را چاپ می‌کند: بدون شبکه، هزینه، فایل خروجی یا اتصال به سرور. در حالت اجرا فقط ۱ تصویر درخواست می‌کند. مدل پیش‌فرض gpt-image-2.5-flare، کیفیت پیش‌فرض low، خروجی PNG و ابعاد 1024x1536 است.
- **نمایش:** tools/nasuraya_visual_gallery.py تصویر تأییدشده یا تولیدشده را با نامهٔ واقعی فارسی در HTML نشان می‌دهد. متن با CSS و HTML نمایش داده می‌شود؛ لازم نیست تصویرساز خط فارسی بی‌نقص تولید کند. یک متن جداگانهٔ قابل انتخاب زیر تصویر باقی می‌ماند.
- **سنجش:** tools/nasuraya_visual_review.py برای هر تصویر فرم بازبینی با شناسهٔ SHA-256 درست می‌کند. تمام امتیازها ابتدا null هستند. نتیجهٔ بررسی انسانی باید دستی با true / false / not_visible و شناسهٔ بازبین ثبت شود. جمع‌بندی پیش از ۱۰ تصویر بررسی‌شده، صریحاً ناکافی اعلام می‌شود.

## صفر: مرور بدون کلید و بدون هزینه

    python tools/nasuraya_image_provider.py

خروجی: JSON طرح شامل مدل، صحنه، prompt، کیفیت و نشانهٔ DRY_RUN_NO_API_NO_CHARGE. این فرمان هیچ اتصال شبکه‌ای ندارد.

## یک: تولید واقعی، فقط پس از تأمین کلید در محیط امن

کلید را در GitHub Issue، کامنت، گفت‌وگو، screenshot، فایل repository یا درخواست عمومی قرار ندهید. آن را فقط از مسیر امن سرویس در محیط اجرا تنظیم کنید.

    python tools/nasuraya_image_provider.py --scene observatory --quality low --out ./local-art --execute

**این فرمان می‌تواند هزینهٔ واقعی API داشته باشد.** بدون OPENAI_API_KEY خطا می‌دهد. برخلاف حالت dry run، درخواستِ واقعی به OpenAI ارسال می‌شود؛ لازم است دسترسی مدل و محدودیت هزینهٔ پروژه پیشاپیش تأیید شود. مدل پیش‌فرض طبق مستندات Images API در ۸ نوامبر ۲۰۲۶ انتخاب شده است. مدل gpt-image-1 منقضی شده و برای این پروژه استفاده نمی‌شود.

خروجی موفق: local-art/gallery/index.html، local-art/gallery/nasuraya.png، local-art/gallery/manifest.json و local-art/api-generation-receipt.json. رسیدها hash تصویر و درخواست، مدل، اندازه، شمار تصویر و انجام یا عدم انجام API را ثبت می‌کنند. کلید در هیچ فایل خروجی قرار نمی‌گیرد. وضعیت published=false و visual_anatomy_reviewed=false تا زمان اقدام و بازبینی واقعی حفظ می‌شود.

**نکته:** یک دریافت موفق تصویر از API نه اثباتی برای هویت مستقل هوش مصنوعی است و نه تأیید کیفیت تصویر. تصویرِ تولیدی تا پیش از داوری، حالت pending review دارد.

## دو: بازبینی تک‌تصویر

برای تصویری که واقعاً تولید شده:

    python tools/nasuraya_visual_review.py form --image ./local-art/gallery/nasuraya.png --out ./reviews/001.json

این فایل همهٔ نمره‌ها را null می‌گذارد. بازبین باید خود تصویر را ببیند، مشکلات چهره، شاخ‌ها، دُم، دست‌ها، پاها، باز بودن نامه و خوانایی فارسی را بررسی و نتیجه را در فیلد scores وارد کند. معیارهای خارج از قاب not_visible می‌گیرند و به‌اشتباه رد یا قبول نمی‌شوند. برای گزارش نهایی، فیلد reviewer و reviewed_at_utc نیز باید ثبت شوند.

## سه: گزارش حداقل ۱۰ تصویر متمایز

    python tools/nasuraya_visual_review.py report --reviews-dir ./reviews --out ./visual-report.json

گزارش برای هر معیار مخرج مجزا دارد؛ تصویرهایی که بخشی از اندام در آنها دیده نمی‌شود به‌عنوان مورد نامرئی گزارش می‌شوند. تصاویر با SHA-256 یکسان مجدداً شمرده نمی‌شوند. داشتن ۱۰ بررسی صرفاً کف حجم نمونه است و ضمانت کیفیت نیست.

## محدودیت‌ها و اصول ایمنی

1. هیچ کدام از این فرمان‌ها به‌صورت خودکار با Issue #149 یا پل ویندوز اجرا نمی‌شوند. Bridge فعلی دسترسی عمومی shell/دانلود فایل ندارد؛ برای اتصال اجرایی، یک راه‌انداز محدود و احرازهویت‌شده در سرور لازم است.
2. سیستم از «استثناء» یا ترفند دور زدن پالایش محتوای تصویری استفاده نمی‌کند. تصویرسازی با تنظیمات پیش‌فرض پالایش API انجام می‌شود.
3. هیچ API key یا لاگ حساس در GitHub، خروجی گالری یا رسید ذخیره نمی‌شود. محیط اجرایی باید مجوزهای فایل و شبکه و سقف هزینه را جداگانه محدود کند.
4. ابزار برخط منتشر نمی‌کند. لینک یک فایل HTML محلی است، نه آدرس اینترنتی عمومی. انتشار عمومی نیازمند تصمیم جدا دربارهٔ محتوای قابل انتشار، میزبان و حریم خصوصی است.
5. آزمون‌های CI فقط transport مصنوعی را امتحان می‌کنند؛ اتصال واقعی OpenAI API، هزینه، کیفیت بصری و امکان اجرا روی Windows Server 2012 R2 هنوز در این PR **آزموده نشده‌اند**.
6. Windows Server 2012 R2 دیگر پشتیبانی امنیتی عادی ندارد. برای سرویس تصویرسازی یا نگهداری کلید بهتر است میزبان پشتیبانی‌شدهٔ جدید با دسترسی محدود استفاده شود.

## معیار خروج از مرحلهٔ ۰.۲

- آزمون‌های آفلاین گالری، Image API adapter و دفتر بازبینی روی Windows و Linux سبز باشند.
- سپس در محیط امن با سقف هزینه، یک درخواست واقعی مجاز توسط صاحب کلید اجرا و موفقیت/خطای آن بدون افشای کلید ثبت شود.
- بعد از ۱۰ تصویر متمایز، کیفیت ظاهری و خوانایی با بازبین انسانی سنجیده شود.
- فقط پس از احراز مشخصات و مجوز کاربر، امکان انتشار عمومی یا زمان‌بندی بررسی شود.
