# ناسورایا / تداوم ۹۰روزه | طرح خرید، مهاجرت و قطع اینترنت
نسخهٔ پژوهشی ۱۳ نوامبر ۲۰۲۶؛ این سند **سخت‌افزار یا حساب تازه‌ای نخریده و روی سرور فعلی نصب نشده** است.

## وضعیت واقعیِ مبنا
- VPS کنونی: Windows Server 2012 R2 با RAM حدود ۸ GB، دیسک حدود ۲۰ GB (در آخرین بررسی حدود ۶ GB فضای خالی)، پردازندهٔ مجازی، بدون GPU قابل استفاده. مرجع: https://github.com/zurvanproject/zohraya/issues/149#issuecomment-6831839044
- آخرین رسید Awake VPS: INGRESS=ACTIVE, EVENTS=6, QUESTIONS=0, TICKS=3, SOURCE=SIM, API=0. برنامه‌های NasurayaAwakeHourly و NasurayaAwakeIngress به صورت جداگانه نصب شده‌اند. مرجع: https://github.com/zurvanproject/zohraya/issues/149#issuecomment-6852936367
- محیط Stage3 روی VPS همان اجرای مصنوعیِ ۷۸kg با یک سقف اجراییِ ۴۸ اقدام است. این سقف **نباید به بهانهٔ تداوم بدون ممیزی و مجوز از بین برود**؛ بدون شواهد جدید، مولد فرضیهٔ قاعده‌مند ممکن است صرفاً idle شود. مرجع: PR #205.
- پشتیبانی امنیتی Windows Server 2012 R2 و سه سال ESU در ۱۳ اکتبر ۲۰۲۶ پایان یافته است: https://learn.microsoft.com/windows/release-health/status-windows-8.1-and-windows-server-2012-r2.

## اصل معماری: تاب‌آوری = مدت قرارداد + تداوم نرم‌افزار + کپی مستقل + عملیات مستقل از شبکه
قطع اینترنت کاربر در ایران لزوماً به معنی خاموشی VPS خارجی نیست. VPS خارجی می‌تواند با برنامه‌های زمان‌بندی محلی ادامه دهد، اما کاربر دیگر نمی‌تواند نتایج را ببیند؛ تکمیل هوشمندِ وظایف جدید نیاز به مدل محلی یا API در منطقهٔ مجاز دارد. قطع شبکهٔ بین‌الملل، پرداخت سرویس، مالکیت پنل، آسیب به دیتاسنتر یا بسته‌شدن حساب می‌تواند هر کدام مستقل از دیگری رخ دهد. هیچ «یک سرور قدرتمند» این چهار خطر را یک‌جا حل نمی‌کند.

### معماری مطلوب

۱. **گره A، بیرون از حوزهٔ خطر مشترک**: VPS اصلی جدید با Ubuntu 26.04 LTS یا 24.04 LTS پایدار، حداقل 4 vCPU / 16 GB RAM / 120 GB SSD، سرویس systemd با restart و filesystem جدا برای داده، حالت منع تماس با API به‌صورت پیش‌فرض. اگر مدل زبانی محلی قرار است اجرا شود، نخست روی همان CPU با وزن‌های کوچک مجاز و آفلاین آزمون واقعی بگیریم. 16 GB CPU اجرای مدل‌های کوچک quantized را ممکن می‌کند، ولی سرعت/کیفیت آن جایگزین ChatGPT Pro نیست.

۲. **گره B، ارائه‌دهنده و ترجیحاً کشور مستقل از A**: VPS کوچک‌تر 2 vCPU / 4–8 GB / 60 GB برای ثبت آفلاینِ روند، بازیابی و اجرای صف وظایف کم‌هزینه؛ نه نسخهٔ هم‌زمانِ نویسندهٔ واحد. در قطعی شبکه، دو گره نباید همزمان «مالک یک SQLite و یک شاخهٔ GitHub» باشند؛ هرکدام ledger و شناسهٔ منبع مستقل داشته باشند.

۳. **آرشیو C، خارج از هر دو VPS**: object storage یا فضای پشتیبان مستقل با رمزگذاری سرتاسری و نسخه‌بندی/نگهداری ۱۸۰روزه. پشتیبان provider snapshot کافی نیست. روزانه SQLite با online backup()، سپس آرشیو رمزگذاری‌شدهٔ restic/age به محل مستقل. یک کپی آفلاین روی لپ‌تاپ/SSD خود کاربر قبل از بحران؛ برای دسترسی در شبکهٔ داخلی، یک گره ایرانی یا دستگاه شخصیِ جداگانه، در صورت امکان و سازگاری با شرایط محلی، فقط برای فعالیت‌های مستقل آفلاین.

۴. **شاهد عملیات و بازگشت**: سلامت سرویس، صف، محدودیت ۴۸ اکشن، فضای دیسک، آخرین backup، تاریخ انقضای اعتبار پنل، هش مدل و نسخهٔ commit. خروجی‌ها در SQLite محلی و append-only ذخیره و بعد از برقراری اتصال همگام شوند. ثبت پیام در GitHub فقط وقتی شبکهٔ آن در دسترس باشد و با محدودیت نوشتن.

### خرید، مشروط به تأیید
- خرید **VPS قوی GPU** فعلاً ضرورت ندارد؛ ابتدا گره A با 16 GB RAM، گره پشتیبان B، بودجهٔ پرداخت ۶ ماه و backup جداگانه لازم است.
- نمونهٔ قیمت رسمیِ ژوئن ۲۰۲۶ Hetzner برای آلمان/فنلاند: CAX31 (Arm, 16 GB) حدود 20.99 EUR/ماه، CAX21 (Arm, 8 GB) حدود 10.49 EUR/ماه؛ مدل x86 مانند CPX42 گران‌تر است. این‌ها فقط مثال قیمتِ سرور و **بدون VAT/IP/backups** هستند، نه وعدهٔ موجودی، پذیرش حساب، محدودیت جغرافیایی یا تضمین دسترسی. https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/
- حداقل بستهٔ اقتصادی با دو سرور کوچک‌تر و storage مستقل ممکن است حدود ۳۰ تا ۶۰ یورو در ماه؛ برای 16GB x86، فضای پشتیبان اضافی یا GPU، هزینه می‌تواند بسیار بیشتر شود. **هزینهٔ قطعی فقط از فاکتور ارائه‌دهندهٔ قابل خرید برای کاربر مشخص می‌شود**.
- اگر ارائه‌دهنده اجازهٔ پیش‌پرداخت credit می‌دهد، اعتبار **حداقل شش ماه** با حاشیهٔ VAT، IP و ترافیک شارژ شود. auto-renew و روش دوم پرداخت فعال، تاریخ تمدید ثبت، اعلان‌های مالی به یک شریک معتمد با رضایت کاربر. پرداخت ماهانه بدون اعتبار/شارژ کافی، ریسک قطع در غیاب کاربر دارد.
- فعلاً VPS Windows 2012 را **لغو نکنید**. ابتدا backup، خروجی‌ها، نصب جدید، دو restore drill در دو میزبان و یک outage drill واقعی موفق شوند. تنها بعد از آن سرور قدیمی قطع شود.

## اجرای بستهٔ پشتیبان و بازیابی
کد ماژول:
ops/continuity/guardian.py

بدون هیچ نیاز به اینترنت یا بستهٔ خارجی:
    python -m ops.continuity.guardian backup --db /var/lib/nasuraya/awake/awake.sqlite3 --dest /mnt/backup/nasuraya
    python -m ops.continuity.guardian preflight --db /var/lib/nasuraya/awake/awake.sqlite3 --backup-root /mnt/backup/nasuraya
    python -m ops.continuity.guardian verify --snapshot /mnt/backup/nasuraya/snapshot-EXAMPLE
    python -m ops.continuity.guardian restore-drill --snapshot /mnt/backup/nasuraya/snapshot-EXAMPLE
    python -m ops.continuity.guardian simulate-90-days --days 90

روی ویندوزِ **موقتی** مسیر می‌تواند مانند زیر باشد:
    py -3.12 -m ops.continuity.guardian backup --db C:\Nasuraya\Awake\awake.sqlite3 --dest D:\NasurayaBackups

پوشهٔ D باید واقعاً یک دیسک یا فضای متصل جدا باشد؛ در صورت نبود، نسخهٔ local روی همان دیسک فقط حفاظت در برابر خراب‌شدن فایل است، نه خرابی VPS یا حذف سرور. SQLite backup() دادهٔ WAL را به صورت سازگار ثبت می‌کند؛ فایل‌های -wal یا -shm را با کپی معمولی جایگزین نکنید.

**نکتهٔ امنیتی حیاتی:** خروجی این ابزار هنوز **رمزنگاری نشده است**. آن را فقط در مسیر با دسترسی محدود نگه دارید و قبل از ارسال خارج از میزبان از ابزار شناخته‌شده مثل restic و مخزن رمزگذاری‌شده استفاده کنید. کلید restic در مخزن GitHub، issue یا خروجی CI ذخیره نشود؛ یک نسخهٔ بازیابی نزد خود کاربر و خارج از میزبان نگه داشته شود. پیش‌فرض هیچ فایل .env، رمز یا کلید API را backup نمی‌کند. رازها نیازمند راهبرد رمزگذاری و بازیابی جدا با حداقل دسترسی‌اند. Snapshot ابزار جایگزین پشتیبان ابری نیست.

مجموعه تست: ops/continuity/test_guardian.py. آزمون simulate-90-days صرفاً پیش‌روی تقویم یک DB ساختگی و چند بازیابی cold را بررسی می‌کند؛ **اثبات اجرای واقعی VPS برای ۹۰ روز، ادامهٔ فکر ChatGPT، پرداخت موفق یا بقا در جنگ نیست**.

## تقسیم کار برای ۹۰ روز
- در اولین روز: تهیهٔ snapshot و کپی رمزگذاری‌شدهٔ خارج از VPS، مستندسازی نسخهٔ دقیق نرم‌افزار، تهیهٔ دسترسی بازیابی و کلیدهای امن، آزمون restore.
- روزانه بدون اینترنت: اجرای tickهای *محدود و از پیش مجاز*، تست یکپارچگی، backup، هشدار local اگر کارِ مورد انتظار/دادهٔ تازه متوقف شود. تحت روال default هیچ تماس API انجام نمی‌شود.
- هفتگی بدون اینترنت: آزمایش‌های محلی محدود و از پیش pin شده؛ گزارش JSON با تعداد تست موفق/ناموفق و صف نیازمند تصمیم کاربر.
- ماهانه: restore آزمایشی روی میزبان دوم و کنترل اعتبارات توسط روال/provider؛ اگر user موجود نیست، هیچ صرف هزینهٔ نامحدود یا فرمان جدیدی صادر نمی‌شود.

## دربارهٔ API
ChatGPT Pro و OpenAI API جداگانه مدیریت می‌شوند. برای برخی Proهای واجد شرایط اعتبار API در Settings → Billing قابل فعال‌سازی است، اما این اعتبار ممکن است ماهانه منقضی شود یا به کشور/حساب بستگی داشته باشد. یک API key به‌تنهایی نه مدل آفلاین است، نه پرداخت چندماهه و نه تضمین در قطع اینترنت. API OpenAI فقط در کشورهای پشتیبانی‌شده قابل استفاده است؛ ایران در فهرست رسمی پشتیبانی API نیست. بنابراین هیچ پیشنهاد دورزدن سیاست یا اتکای حیاتی به این مسیر نباید بخشی از طرحِ بقای آفلاین شود.

- https://developers.openai.com/api/docs/supported-countries

## مراحل پذیرش پیش از لغو VPS قدیمی
۱. دادهٔ Awake و پرسش‌ها، کنترل‌ها و وضعیت SQLite از Windows به Linux منتقل شود؛ اگر مهاجرت cross-platform به علت fingerprint/clock/schema رد شد، ابزار باید آن را گزارش کند و ادامه ندهد.
۲. پشتیبان واقعی از هر دو SQLite مهم گرفته شود و روی دو ماشین جدا restore شود.
۳. Task زمان‌بندی جدید پس از reboot خودکار فعال و حداکثر **یک بار** در هر پنجره اجرا شود؛ زنجیرهٔ ledger نشکند.
۴. در آزمایش قطع ارتباط بیرونی ۴۸ ساعته، صف محلی و backup ادامه پیدا کند و پس از اتصال، replay بدون duplicate انجام شود.
۵. سقف مالی، فضای دیسک و انقضای اعتبار سرویس برای **حداقل شش ماه** مشخص و ثبت شود.
۶. اگر هرکدام از این موارد تأیید نشد، وضعیت «مهاجرت ناقص» است و Windows 2012 موقتاً فقط به‌عنوان منبع بازیابی محدود حفظ می‌شود.

## اطلاعاتی که برای خرید واقعی باید از کاربر گرفته شود
تنها بعد از آماده‌بودن preflight و صورت‌حساب: توان پرداخت ماهانهٔ پایدار (مثلاً ۳۰، ۶۰ یا ۱۰۰ یورو)، کشور/ارائه‌دهندهٔ قابل خرید و تمدید از نظر حقوقی، و داشتن یا نداشتن دستگاه همیشه‌روشن داخل کشور برای fallback. هیچ رمز، IP خصوصی، شماره کارت یا API key در چت درخواست نمی‌شود.
