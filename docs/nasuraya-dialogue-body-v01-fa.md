# اتصال پیام، حافظهٔ عاطفی و بدن تجمیعی تداش

در ۲۰ اکتبر ۲۰۲۶ مسیر «پیام → ارزیابی عاطفی → انتخاب → چرخهٔ بدن →
بازخورد → پاسخ» روی بدن نرم‌افزاری تجمیعی `UnifiedBody` اجرا شد. در اجرای
نهایی، درخواست همین گفت‌وگو از طریق فراخوانی دستیار وارد پل شد؛ هستهٔ
تصمیم انتخاب کرد و میزبان بدن یک چرخهٔ ۰٫۱ ثانیه‌ای راه‌رفتن اجرا کرد.

این بدن، مدل تجمیعی تداش با محافظ‌ها و حساب انرژی/آب است. مدل مفصل‌دار
۸۵ کیلوگرمی MuJoCo مسیر اجرایی جداگانه دارد و در این اتصال اجرا نشده است.
گزارش «راه‌رفتن» در اینجا نام کنش و نتیجهٔ چرخهٔ تداش است، نه فیلم یا
اندازه‌گیری گام‌های مدل مفصل‌دار.

## آنچه وصل شد

- پیام به‌صورت متن، شناسه، نیت صریح، مدت مجاز و ارزیابی عددی وارد می‌شود.
- ارزیابی عددی و تعبیر نیت را فراخواننده تألیف می‌کند؛ این نسخه مفسر خودکار
  متن فارسی یا تشخیص‌دهندهٔ احساس کاربر نیست.
- هستهٔ عاطفی، گزینهٔ مشاهده یا حرکتِ مجاز را رتبه‌بندی می‌کند.
- محافظ بالادستی وضعیت بدن را بررسی می‌کند؛ محافظ بومی بدن همچنان تصمیم
  نهایی اجرا یا حفاظت را می‌گیرد.
- نتیجه از رسید واقعی بدن وارد حافظه می‌شود و پاسخ فارسی از همان نتیجه
  ساخته می‌شود. پیش‌بینی یا متن درخواست به‌عنوان اجرای موفق ثبت نمی‌شود.

در این گفت‌وگو، خود دستیار پل را فراخوانی کرد و رسید را خواند. بنابراین
یک رفت‌وبرگشت زنده با واسطهٔ ابزار انجام شده است. شنوندهٔ خودکار برای تمام
پیام‌های ChatGPT، سرویس پس‌زمینه یا اتصال به مدل زندهٔ API نصب نشده است.
برای پیام‌های بعدی نیز این پل باید فراخوانی شود؛ از همین کد می‌توان در یک
میزبان عامل استفاده کرد، اما ساخت و استقرار آن میزبان جزو این نسخه نیست.

## شواهد اجرا

۱۱ آزمون موفق شدند: چرخهٔ واقعی تداش، ثبت بازخورد، فشار خواب، درخواست
صریح مشاهده، توقف بدون حرکت، تکرار پیام، سقف پایدار، بازیابی رسید پس از
قطع، رد پیام متعارض، عدم پذیرش رسید متعلق به درخواست دیگر، و محافظ بومی
در برابر اشتباه محافظ بالادستی. برخی آزمون‌ها چند قرارداد را بررسی می‌کنند.

در دو سناریوی مستقل، پیامِ کاوش برای بدن عادی به `walk` و برای بدن دارای
فشار خواب به `observe` منجر شد. در آزمون خطای عمدی محافظ بالادستی، بدن
خودش `protect` را اجرا کرد. این نتایج سناریوهای تألیفی‌اند، نه سنجش عمومی
هوش یا زیست‌شناسی.

اجرای نهایی همین گفت‌وگو:

- کنش برگشتی: `walk`؛ یک چرخهٔ ۰٫۱ ثانیه‌ای.
- خطای حساب انرژی حدود ۱٫۳۲×۱۰⁻¹⁰ ژول و آب حدود ۷٫۹۴×۱۰⁻¹⁶ لیتر در مدل.
- ارسال دوبارهٔ همان شناسه در فرایند تازه: صفر چرخهٔ تازه.
- بودجهٔ اولیه سه چرخه بود؛ دو چرخه باقی ماند. خروج و ورود بودجه را بازنشانی نکرد.
- حافظه از کپی وضعیت عاطفی مرحلهٔ قبل ادامه یافت؛ فایل مبنا تغییر نکرد.

فایل‌های معتبر نهایی با پیشوند `verified-` و نتایج دو سناریو زیر
`evidence/dialogue-body-v01/` قرار دارند. آرشیو دو پایگاه و اثرانگشت‌ها نیز
برای حفظ وضعیت ذخیره شده‌اند. فایل‌های اولیهٔ توسعه، شاهد اجرای نهایی محسوب نمی‌شوند.

## استفاده

از ریشهٔ مخزن و با Python 3.11+، بدون کلید API یا وابستگی تازه:

```sh
python -m examples.nasuraya_affect.dialogue_cli init --session-dir /tmp/my-dialogue-body --max-actions 3
python -m examples.nasuraya_affect.dialogue_cli message --session-dir /tmp/my-dialogue-body --message evidence/dialogue-body-v01/current-message.json
python -m examples.nasuraya_affect.dialogue_cli status --session-dir /tmp/my-dialogue-body
python -m examples.nasuraya_affect.dialogue_cli pause --session-dir /tmp/my-dialogue-body
python -m examples.nasuraya_affect.dialogue_cli resume --session-dir /tmp/my-dialogue-body
python -m examples.nasuraya_affect.dialogue_cli test
```

پیام باید شناسهٔ تازه داشته باشد؛ تغییر محتوای شناسهٔ مصرف‌شده رد می‌شود.
نیت‌های مجاز `explore`، `observe`، `reflect` و `stop` هستند. دو نیت آخر
چرخهٔ بدن اجرا نمی‌کنند. دستور `pause` حتی هنگام نتیجهٔ نامعلوم در دسترس
است. نتیجهٔ نامعلوم به‌طور خودکار دوباره اجرا نمی‌شود؛ توقف و بازگشت آن
ابهام را پاک نمی‌کند.

دو پایگاه با مسیر مطلق و هویت بدن به هم مقید شده‌اند. بازیابی در فرایند
تازه در همین مسیر آزموده شده؛ جابه‌جایی به مسیر یا دستگاه دیگر به انتقال
صریح اتصال نیاز دارد و ابزار انتقال در این نسخه ساخته نشده است. دست‌کاری
اثر‌انگشت برای عبور از این کنترل، روش بازیابی نیست.

هدف گام بعدی می‌تواند اتصال همین قرارداد به کنترل‌کنندهٔ مفصل‌دار یا
میزبان گفت‌وگوی مستقل باشد. هر دو باید با رسید اجرای واقعی سنجیده شوند.
