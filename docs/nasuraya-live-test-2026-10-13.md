# آزمون زندهٔ ناسورایا — ۱۳ اکتبر ۲۰۲۶

آزمون محدود با کلید تازهٔ پروژهٔ Personal / Default project و مدل `gpt-6-astra`
انجام شد. بررسی مدل و ساخت جلسهٔ واقعی موفق بود؛ اجرای کامل حلقه موفق نشد.

| مرحله | مشاهدهٔ واقعی |
| --- | --- |
| دریافت مشخصات مدل | موفق؛ مدل `gpt-6-astra` |
| جلسهٔ اول Agents API | ساخت موفق؛ صفر کنش؛ timeout خواندن؛ حذف در پیگیری |
| جلسهٔ دوم Agents API | ساخت موفق؛ صفر کنش؛ خطای `internal_error`؛ حذف موفق |
| درخواست جداگانهٔ Responses API | HTTP 429؛ کد `billing_not_active`؛ بدون خروجی مدل |
| وضعیت هر دو جلسه | حذف‌شده |

هر اجرا سقف پنج کنش و چهل فراخوانی ابزار داشت. درخواست تشخیصی جداگانه حداکثر
۶۴ توکن خروجی داشت. پاسخ ۴۲۹ به‌تنهایی معیار تشخیص نیست؛ کد صریح
`billing_not_active` نشان داد صورتحساب API فعال نیست. از خطای داخلی Agents
به‌تنهایی نمی‌توان علت صورتحساب را استنتاج کرد؛ درخواست جداگانه آن مانع را
مستقیماً نشان داد. هیچ کنش از مدل زنده اجرا نشد و `live_api_verified` همچنان false است.

## اصلاحات انجام‌شده

راه‌انداز قبلی ورودی آغازین اجباری برای `environment=none` را نداشت. اکنون
ورودی و `stream=True` در همان درخواست ساخت ارسال می‌شوند تا رویداد اولیه از
دست نرود. شناسهٔ جلسه پیش از بررسی پایان مهلت ثبت می‌شود تا پاک‌سازی ممکن باشد.
مهلت درخواست stream با سقف اجرای آزمون هماهنگ شد. در خطای حذف ۴۰۹، لغو نوبت
و تلاش محدود برای حذف انجام می‌شود. کدها و وضعیت HTTP خطا بدون ذخیرهٔ پیام‌های
دلخواه یا اطلاعات محرمانه ثبت می‌شوند. fixtureهای HTTP اکنون نبود ورودی اولیه
را رد می‌کنند و آزمون تازه، پاک‌سازی جلسهٔ مشغول را بررسی می‌کند.

آزمون نهایی کد اصلاح‌شده: ۵۸ موفق با SDK؛ بدون SDK، ۴۸ موفق و ۱۰ skip اختیاری.
شواهد خامِ محدودشده، گزارش اجرا و پیگیری پاک‌سازی در
`examples/nasuraya_agent_loop/evidence/live_2026_10_13/` قرار دارند.

## گام باقی‌مانده

فعال‌کردن [صورتحساب API](https://platform.openai.com/settings/organization/billing)
در حساب پروژه، سپس یک اجرای محدود تازه. هیچ خرید اعتبار یا تغییر صورتحساب در
این آزمون انجام نشد. کلید در فایل محلی تأییدشده ذخیره شده و به مخزن منتقل نشده است.

این آزمون هنوز اتصال حلقه به Decision Core، مدل خود یا بدن تداش را انجام نمی‌دهد.
