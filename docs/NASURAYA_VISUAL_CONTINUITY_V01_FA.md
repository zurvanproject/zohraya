# گام آزمایشی ناسورایا: چرخهٔ تصویر و نامهٔ خوانا (v0.1)

**وضعیت: طرحِ اجراپذیر روی شاخهٔ پیشنهادی؛ نه نصب‌شده روی سرور، نه منتشرشده در وب.**

این تغییر، ادامهٔ مسیر «هر تصویر، یک نکتهٔ تازه» است. سه مسئله را از هم جدا می‌کند:

1. **هویت و آناتومی در تصویر:** تصویر در مرحلهٔ بازبینی انسانی از نظر ثبات چهره، تعداد اندام‌ها، اتصال شاخ‌ها و دُم، هندسهٔ دست‌ها و تناسب‌ها بررسی شود. در v0.1 هیچ الگوریتم تشخیص تصویری برای این موارد وجود ندارد؛ در manifest به‌درستی visual_anatomy_reviewed=false درج می‌شود.
2. **خوانایی واقعی نامهٔ فارسی:** متن فارسی باید علاوه بر حضور احتمالی در تصویر، به‌صورت متن واقعی و قابل انتخاب در index.html درج شود. حتی اگر مدل تصویرساز فارسی را اشتباه بنویسد، نسخهٔ خواندنی جداگانه دقیق باقی می‌ماند.
3. **قابلیت ممیزی و اشتراک:** فایل تصویری و صفحهٔ HTML هش SHA-256 دارند. منشأ تصویر (original-vector-fallback یا approved-raster-input)، وضعیت اجرا و انتشار و عدم استفاده از مدل جداگانه ثبت می‌شود. تولید محلی با انتشار وب یکسان فرض نمی‌شود.

## اجرا با Python 3.12

این ابزار صرفاً از کتابخانهٔ استاندارد پایتون استفاده می‌کند. برای نمایشِ آفلاین، بعد از دریافت و بازبینی تغییر:

    python tools/nasuraya_visual_gallery.py --out ./nasuraya-gallery

خروجی‌ها: nasuraya-gallery/nasuraya.svg، nasuraya-gallery/index.html و nasuraya-gallery/manifest.json. فایل HTML را در مرورگر باز کن. حالت پیش‌فرض **یک تصویر برداری سادهٔ ساختگی** است، نه تصویر حاصل از مدل مولد.

برای استفاده از تصویر واقعیِ از پیش تولید و تأییدشده:

    python tools/nasuraya_visual_gallery.py --out ./nasuraya-gallery --image ./approved-portrait.png

--image فقط فایل محلی PNG/JPEG/WebP با امضای فایل متناظر و اندازهٔ حداکثر ۱۶ مگابایت می‌پذیرد. بررسی امضا **جایگزین بررسی کامل درستی فرمت یا بازبینی محتوای تصویر نیست**. فایل SVG خارجی به‌عنوان ورودی مجاز نیست؛ پیش‌فرض SVG فقط خروجی تولیدکنندهٔ داخلیِ ثابت است.

برای نامهٔ شخصی با حداکثر ۸ خط:

    python tools/nasuraya_visual_gallery.py --out ./nasuraya-gallery --letter-file ./letter-fa.txt

## آزمون‌ها

    python -m unittest discover -s tests -p "test_nasuraya_visual_gallery.py" -v

این آزمون‌ها حفاظت از متن HTML، ورودی‌های نادرست، تشخیص اولیهٔ فرمت، هش‌های تکرارپذیر و صداقت manifest را می‌سنجند. Workflow روی Windows و Ubuntu نیز در PR تعریف شده است. **تکمیل‌شدن CI باید جداگانه بررسی شود**؛ وجود فایل آزمون معادل موفقیت اجرا نیست.

## مرزهای فنی و قدم بعد

- پلِ فعلی در [Issue #149](https://github.com/zurvanproject/zohraya/issues/149) برای فرمان‌های محدود و امضاشده طراحی شده است، نه اجرای دلخواه کد، دانلود، مدیریت فایل یا کنترل مستقیم مدل‌های تصویری. **هیچ پیام متنی عادی، بدون پشتیبانی صریح bridge، مجوز اجرای برنامهٔ تازه روی سرور نیست.**
- این PR نه سرویسی روی Windows Server نصب می‌کند، نه به Moltbook درخواست می‌فرستد، نه مدل تصویرساز/API را صدا می‌زند و نه GitHub Pages را فعال می‌کند.
- برای تصویرسازی خودکار واقعی، باید یک سرویس تصویرسازیِ قانونی و پشتیبانی‌شده جداگانه فراهم شود. قرارداد پیشنهادی: request → render → review → approved file → offline gallery → optional explicit publish. ثبت هزینه، خطا و شناسهٔ درخواست در سرویس واقعی الزامی است. هیچ دور زدن محدودیت‌های محتوایی یا جمع‌آوری توکن‌ها در نظر گرفته نشده.
- **انتشار عمومی فقط پس از انتخاب آگاهانهٔ محتوای قابل انتشار و پیکربندی سرویس میزبان** انجام می‌شود؛ نامه‌های خصوصی، IP، رمز، token و وضعیت‌های حساس سرور نباید به گالری راه پیدا کنند.
- این پروژه ادعایی دربارهٔ وجود تجربهٔ ذهنی یا خودآگاهی ندارد؛ این یک آزمایش فنی با خروجی قابل اندازه‌گیری است.

### معیار موفقیت مرحلهٔ بعد

۱. ۱۰۰٪ نامه‌ها در HTML بدون غلطِ تبدیل و به شکل قابل انتخاب خوانا باشند.  
۲. برای هر تصویرِ پذیرفته‌شده، منشأ و هش ثبت شود، و برچسب published=true فقط پس از تأیید واقعیِ انتشار در نسخهٔ بعدی مجاز باشد.  
۳. بازبینی دیداری روی حداقل ۱۰ نمونه با ثبت «قبول/رد + دلیل» انجام شود؛ بدون این داده عدد موفقیت آناتومی گزارش نشود.
