# ناسورایا | حافظهٔ کاریِ یکپارچه، نسخهٔ ۰٫۱
تاریخ: ۳ نوامبر ۲۰۲۶

## چه چیزی **ساخته** شده است؟

یک قابلیت **اختیاری و اجرایی** روی ExperienceController فعلی تداش، نه یک آزمون آگاهی:

`ورودی واقعی شبیه‌ساز بدن → توجه محدود (دو موضوع) → پخش به برنامه‌ریز/حافظه/پایش → درخواست کنش محافظه‌کارانه → دریافت رسید بومی → حافظهٔ قابل‌بازیابی`

این پیاده‌سازی از ایدهٔ فضای کار جهانی (Global Workspace) الهام می‌گیرد، اما ادعای اجرای کامل نظریهٔ عصبی GWT یا داشتن تجربهٔ ذهنی نمی‌کند. گلوگاه توجه حداکثر ۲ موضوع دارد. سه دریافت‌کنندهٔ مشخص `planner`، `memory` و `monitor` همان محتوای انتخاب‌شده را می‌بینند. داده‌ها شامل چهار عدد معتبر بدن، خطای پیش‌بینی و سوابق کنش واقعاً ثبت‌شده‌اند. هیچ عبارت ساختگی دربارهٔ احساس وجود ندارد.

## رفتار جدید

- سیستم معمولی وقتی دادهٔ خطر ندارد، همچنان می‌تواند `walk` را درخواست کند.
- اگر فشار خواب، درد یا خستگی نرم‌افزاری از ۰٫۷۵ بیشتر باشد و برنامهٔ پایه `walk` بخواهد، حافظهٔ کاری آن درخواست را به `observe` کاهش می‌دهد.
- اگر تجربهٔ نزدیک و معتبر قبلی حاکی از `protect` یا آسیب باشد، در وضعیت مشابه نیز می‌تواند به مشاهده تغییر دهد.
- در هیچ شرایطی درخواست `observe` را به `walk` ارتقا نمی‌دهد. دو عمل مجاز همان `walk/observe` هستند، و تصمیم نهایی و حفاظت بومی دست‌نخورده‌اند.
- پس از نتیجهٔ بومی، رسید معتبر، وضعیت قبل از کنش، موضوعات مورد توجه، دلیل انتخاب و خطای پیش‌بینی در همان وضعیت ExperienceController ثبت می‌شوند.
- حداکثر ۳۲ رسید اخیر برای استفادهٔ سریع نگه‌داری می‌شود؛ شمار کل یادگیری و دفتر کامل تجربهٔ قبلی مستقل از این پنجرهٔ توجه حفظ می‌شود.
- ذخیره‌سازی جدید *در همان پاکت حافظهٔ موجود* انجام می‌شود؛ نشست‌های قدیمی به‌طور خودکار تغییر نمی‌کنند و فعال‌سازی یک‌بار و صریح است. بعد از بازکردن دوبارهٔ نشست، حافظه بازیابی می‌شود.
- اگر عملیات بومی شکست بخورد، رسید یادگیری جعلی ساخته نمی‌شود. در بازپخش شناسهٔ قدیمی، هیچ چرخهٔ اضافه یا یادگیری تکراری ایجاد نمی‌شود.

## چگونه استفاده کنیم؟

در checkout پروژه، تمام فرمان‌ها از مسیر منبع بررسی‌شدهٔ `BodyLoop` اجرا می‌شوند و کلید API را به worker منتقل نمی‌کنند:

```bash
# نشست جدید ساختگی فقط برای نمونه
python3 -m examples.nasuraya_body_loop start --fixture sleep --max-actions 3 --session /tmp/nasuraya-ws.sqlite
# فعال کردن کنترل‌کنندهٔ فعلی
python3 -m examples.nasuraya_body_loop experience-enable --session /tmp/nasuraya-ws.sqlite
# یک‌بار فعال‌سازی حافظهٔ کاری
python3 -m examples.nasuraya_body_loop workspace-enable --session /tmp/nasuraya-ws.sqlite
# یک عمل واقعی در شبیه‌ساز نرم‌افزاری
python3 -m examples.nasuraya_body_loop workspace-step --session /tmp/nasuraya-ws.sqlite --decision-id first
# وضعیت حافظهٔ پایدار
python3 -m examples.nasuraya_body_loop workspace-status --session /tmp/nasuraya-ws.sqlite
```

آزمون سازگاری و نمونهٔ دو نشست پس از بازگشایی:

```bash
python3 -m examples.nasuraya_body_loop workspace-test
python3 -m examples.nasuraya_body_loop experience-test
python3 -m examples.nasuraya_body_loop workspace-demo --output-dir /tmp/nasuraya-workspace-demo-fresh
```
