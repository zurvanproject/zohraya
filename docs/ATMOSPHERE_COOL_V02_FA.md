# ATMOSPHERE COOL v0.2 | خنک‌سازی محاسبات با شواهد زمانی مستقل

**وضعیت:** پژوهشی، Draft، فقط توصیه‌ای، بدون استقرار یا اجرای فرمان روی VPS. این نسخه ادامهٔ COOL v0.1 در PR #247 است؛ زنجیرهٔ پایه PR #246 نیز همچنان آزمایشی است.

## هدف و مرز
کم‌کردن کار پژوهشیِ تکراری، آشکارکردن فشار غیرعادی CPU/RAM و توصیهٔ فاصلهٔ مشاهده، بدون خاموش‌کردن سرویس‌ها، فعال‌کردن Awake، تغییر DIOS، اتصال شبکه، نوشتن حافظه یا ادعای تجربهٔ ذهنی آرامش. CPU load/cores نه دمای پردازنده است و نه درصد دقیق CPU. COOL هیچ کاهش واقعی دما، مصرف برق یا منابع سرور را اندازه‌گیری نکرده است.

## چه چیزی در v0.2 اصلاح شده؟

۱. **بازپخش، معادل بهبود نیست:** سابقهٔ هشدار شامل زمان UTC و SHA-256 خود نمونه است. تکرار عین همان نمونه امتیاز بازیابی نمی‌گیرد. اگر دو محتوای مختلف با یک timestamp عرضه شوند یا زمان نمونه نسبت به سابقه عقب برود، خروجی بازبینی انسانی است. برای خارج‌شدن از COOL_ADVISED باید دو مشاهدهٔ سالم، هر یک با فاصلهٔ حداقل ۶۰ ثانیه نسبت به مشاهدهٔ قبلی، ثبت شوند.

۲. **خطر حتی هنگام توقف دیده می‌شود:** فشار بحرانی حافظهٔ میزبان (حداقل ۹۲٪)، بار یک‌دقیقه‌ای CPU تقسیم بر هسته (حداقل ۲) و حداقل شش خطا در پنج دقیقه، حتی اگر Awake متوقف باشد یا برخی فیلدهای پژوهشی در دسترس نباشند، منجر به REVIEW_REQUIRED می‌شوند. منشأ تأییدنشده برای مشاهدهٔ تازه هیچ حکم قطعی نمی‌سازد؛ اگر هشدار قبلی معتبر وجود نداشته باشد OBSERVE_ONLY است، ولی هشدار REVIEW_REQUIRED یا COOL_ADVISED قبلی را نیز پاک نمی‌کند. برچسب source_verified وضعیت اعتبار شاهد فعلی را آشکار می‌کند.

۳. **حافظهٔ هشدار بحرانی:** REVIEW_REQUIRED در سابقهٔ منتقل‌شده بدون بازبینی انسانی به MONITOR تبدیل نمی‌شود. چون این ماژول عمداً وضعیت پایدار یا امضای مستقل نمی‌سازد، یک میزبان که سابقه را حذف کند می‌تواند این محافظ نمایشی را دور بزند. پس این برنامه محافظ اجرایی نیست.

۴. **پنجرهٔ زمانی کوچک:** evaluate_window حداکثر پنج نمونهٔ دقیقاً مرتب و جداشده به فاصلهٔ حداقل ۶۰ ثانیه را می‌پذیرد. هر نمونه باید در پنج دقیقهٔ گذشته باشد. نمونهٔ تکراری، خارج از ترتیب یا خارج از پنجره رد می‌شود. تابع next_state حالت نمایشیِ دارای mode، healthy_streak، sampled_at و sample_digest_sha256 می‌سازد. ورودی قدیمیِ فاقد زمان برای امتیاز بازیابی پذیرفته نمی‌شود.

۵. **راهنمای وقفه بدون اعمال آن:** خروجی cooling_plan پیشنهادهای پژوهشی اولیه می‌دهد:
- CPU بالا: به‌تعویق‌انداختن کار غیرضروری برای ۳۰۰ ثانیه، با تصمیم اپراتور
- فشار متوسط RAM: پیشنهاد ۶۰۰ ثانیه
- تکرار صرفِ ورودی بدون شاهد تازه: پیشنهاد ۹۰۰ ثانیه
- حالت بحرانی: بدون فرمان زمان‌بندی، فقط بازبینی انسانی

این مقادیر کالیبره نشده‌اند. next_readonly_observation_seconds صرفاً یک راهنمای مشاهده است، نه زمان‌بند یا مجوز دسترسی. پیشنهادها نباید خودکار روی سرویس اجرا شوند.

## آستانه‌های آغازین و شرایط عدم قطعیت
- COOL_ADVISED: CPU load/cores حداقل ۰٫۸، RAM حداقل ۸۰٪، حداقل سه خطا در پنج دقیقه یا نسبت تکرار حداقل ۰٫۶.
- REVIEW_REQUIRED: CPU حداقل ۲، RAM حداقل ۹۲٪، حداقل شش خطا یا شواهد پژوهشی قدیمی‌تر از شش ساعت.
- اطلاعات ناقص دربارهٔ پژوهش یا توقف Awake: OBSERVE_ONLY؛ مگر اینکه یک شاخص بحرانیِ قابل‌اعتماد موجود باشد.
- نمونهٔ قدیمی‌تر از ۳۰۰ ثانیه یا ساعت برگشتی: بازبینی.
- source_verified تنها از میزبان احرازشده می‌آید، نه از فایل JSON یا متن مدل.

## آزمون و بازتولید
از ریشهٔ checkout ایزوله:
    python3 -m unittest discover -s tests -p 'test_atmosphere_cool.py' -v
    python3 tools/atmosphere_cool.py --demo
    python3 tools/atmosphere_cool.py --host

در v0.2 تعداد ۷۰ آزمون واحد محلی موفق بوده‌اند؛ علاوه بر سناریوهای کنترل‌شده، ۱۵٬۰۰۰ ورودی ساختگی برای رد هرگونه اجازهٔ اجرای سرویس و تغییر DIOS بررسی شدند. این‌ها آزمون نرم‌افزاری هستند و روی VPS به صورت عملیاتی اجرا نشده‌اند. CI روی Python 3.12 و 3.13 تعریف شده است و باید نتیجهٔ واقعی GitHub جداگانه بررسی شود.

## محدودیت‌های مهم
- SHA-256 برابر با امضای هویت یا اثبات حقیقت نیست؛ caller باید منشأ نمونه‌ها و تاریخچه را جداگانه احراز کند.
- ریست‌کردن تاریخچهٔ UI، قفل REVIEW_REQUIRED را به صورت رمزنگاری‌شده حفظ نمی‌کند.
- دو نمونهٔ با زمان متفاوت ممکن است از یک منبع غیرمستقل آمده باشند؛ host باید استقلال واقعی نمونه‌ها را تضمین کند.
- آستانه‌ها هنوز روی بار واقعی سرور کالیبره نشده‌اند.
- هیچ نصب، ادغام، فعال‌سازی، تغییر main، VPS، Bridge، کلید، مدل، هزینهٔ API یا حالت PAUSED انجام نمی‌شود.

**گیت استقرار:** تأیید ریشهٔ اعتماد و پشتیبان بیرون از VPS، ممیزی منبع متریک، آزمون فرایندی و تأیید جداگانهٔ اپراتور. COOL به تنهایی مجوز هیچ اقدام اجرایی صادر نمی‌کند.
