# بررسی دسترسی چت و تصویر روی دسکتاپ ناسورایا — ۱۲ نوامبر ۲۰۲۶

**نتیجه:** مقصد هر دو میان‌بر و پاسخ اولیهٔ HTTPS از خود VPS تأیید شد. ورود به حساب، رندر رابط، دریافت پاسخ چت و تولید/ذخیرهٔ تصویر هنوز آزمایش نشده‌اند. نصب یا اجرای مدل مستقل نیز اثبات نشده است. Chrome 109 و Windows Server 2012 R2 برای یک محیط روزمره و پایدار مبنای مناسبی نیستند.

`LINKS=XX` در آزمون اول فقط عدم برابری بایتی با قالب اولیه بود. آزمون دوم مقصدهای واقعی را به شکل محدود و بدون انتشار محتوا بررسی کرد و هر دو را تأیید کرد؛ میان‌برها تغییر داده نشدند.

## رسید اولیه چه چیزی را ثابت می‌کند؟

[رسید اولیه](https://github.com/zurvanproject/zohraya/issues/149#issuecomment-6811703306) و [کد ثابت آن](https://github.com/zurvanproject/zohraya/blob/f4f2aa661f5f375a86efce02c566b7483960ccb1/tools/bridge_jobs/nasu_desktop_ai_links.py) نشان می‌دهند که دو فایل InternetShortcut ساخته شده‌اند. `CHAT=OK` و `IMAGES=OK` از بررسی همان فایل‌ها تولید می‌شوند. `LOGIN=USER_REQUIRED` یک برچسب ثابت در کد است و وضعیت واقعی ورود را نمی‌خواند. این کار هیچ مرورگری را اجرا نکرده و هیچ مدل یا سرویس استنتاجی را نصب نکرده است.

رابط وب به‌خودی‌خود نشانهٔ ابری‌بودن نیست: مثلاً رابط localhost برای یک موتور محلی واقعاً می‌تواند استنتاج را روی همان میزبان انجام دهد. برعکس، میان‌بر دسکتاپ ChatGPT مدل را به VPS منتقل نمی‌کند. اتصال یک برنامه به API بیرونی هم به معنی اجرای مدل مستقل روی VPS نیست.

## محدودیت مرورگر و سیستم‌عامل

- [Google](https://support.google.com/chrome/a/answer/7100626?hl=en) می‌گوید Chrome 109 آخرین نسخه برای Server 2012/R2 است و اصلاحات ویژهٔ آن در اکتبر ۲۰۲۳ پایان یافت. نصب شخصی یا portable، محدودیت موتور/OS را از بین نمی‌برد.
- [Microsoft](https://learn.microsoft.com/en-us/lifecycle/products/microsoft-edge) نیز Edge 109 را آخرین نسخه برای این سیستم معرفی می‌کند. نسخه‌های پشتیبانی‌شدهٔ جدید [Server 2022 و 2025 را شامل می‌شوند](https://learn.microsoft.com/en-us/deployedge/microsoft-edge-supported-operating-systems).
- حتی دورهٔ ESU سیستم‌عامل [در ۱۳ اکتبر ۲۰۲۶ پایان یافت](https://learn.microsoft.com/en-us/azure/azure-arc/servers/license-extended-security-updates#end-of-windows-server-2012-esu-coverage). داشتن ESU قبلی، پشتیبانی امروز را اثبات نمی‌کند.
- [صفحهٔ جاری Mozilla](https://support.mozilla.org/en-US/kb/firefox-users-windows-7-8-and-81-moving-extended-support) در توضیح اصلی، پشتیبانی Firefox 115 ESR برای Windows 7/8/8.1 را تا مارس ۲۰۲۷ تمدید می‌کند؛ انتهای همان صفحه هنوز متن قدیمی اوت ۲۰۲۶ دارد. این منبع تضمین صریح Server 2012 R2 یا ChatGPT نیست. Firefox فقط گزینهٔ موقتِ نیازمند بررسی نسخه، تأیید نصب و آزمون واقعی است؛ مشکل پشتیبانی OS را حل نمی‌کند.
- نصب مستقیم برنامه‌های جدید نیز جای بررسی OS را نمی‌گیرد: [Ollama برای ویندوز](https://docs.ollama.com/windows) حداقل Windows 10 22H2 را ذکر می‌کند. [Comfy Desktop](https://docs.comfy.org/installation/system_requirements) Windows 10 به بعد و برای بهترین تجربهٔ وب Chrome 143 به بعد را توصیه می‌کند. هیچ باینری جدیدی روی R2 آزمایش یا نصب نشده است.

## منابع برای برنامه‌ریزی اجرای مستقل

اعداد این جدول، جز مواردی که صریحاً به سازنده نسبت داده شده‌اند، برآورد مهندسی اولیه‌اند؛ تضمین حداقل یا سرعت نیستند. نیاز دقیق به مدل، طول متن، batch، رزولوشن، روش کم‌حافظه و کارهای هم‌زمان وابسته است.

| هدف | پیشنهاد اولیه برای بررسی بعدی | مقایسه با این VPS |
| --- | --- | --- |
| وب | مرورگر پشتیبانی‌شده روی OS پشتیبانی‌شده؛ GPU لازم نیست | ۸ GiB کل می‌تواند کافی باشد، ولی فقط ۲٫۲ GiB در لحظه آزاد بوده است |
| متن سبک ۱ تا ۴ میلیارد پارامتر Q4 | آزمایش روی CPU با context کوتاه؛ ۸ GiB حد آزمایشی وابسته به مدل، ۱۶ GiB ظرفیت مناسب‌تر؛ ۱۰ تا ۲۰ GiB فضای آزاد برای موتور/مدل/حاشیه | فعلاً RAM آزاد کم است. فایل نمونهٔ [Qwen3-4B Q4_K_M](https://huggingface.co/Qwen/Qwen3-4B-GGUF/tree/main) به‌تنهایی حدود ۲٫۵ GB است؛ حافظهٔ زمان اجرا و KV cache علاوه بر آن لازم است |
| تصویر محلی برای استفادهٔ تعاملی | پس از انتخاب مدل، GPU با حدود ۱۲ تا ۱۶ GB VRAM، RAM سیستم ۳۲ GB و ۵۰ تا ۱۰۰ GB فضای آزاد را به‌عنوان بودجهٔ اولیه بررسی کنیم؛ مدل‌های سبک‌تر/فشرده ممکن است کمتر بخواهند | تنها گرافیک مجازی مشاهده شده و ظرفیت محاسباتی GPU اثبات نشده؛ منابع فعلی برای پیشنهاد نصب کافی نیست |

[LM Studio](https://lmstudio.ai/docs/app/system-requirements) برای x64 به AVX2 نیاز دارد و حداقل ۱۶ GB RAM را توصیه می‌کند؛ این شرایط نباید به همهٔ موتورهای محلی تعمیم داده شود. [llama.cpp](https://github.com/ggml-org/llama.cpp) گزینه‌های CPU، کوانتش و GPU دارد، اما سازگاری یک build با R2 و CPU این VPS هنوز بررسی نشده است.

نمونهٔ تفاوت نیاز مدل‌ها: [Stability AI](https://stability.ai/news-updates/introducing-stable-diffusion-3-5) برای SD 3.5 Medium عدد ۹٫۹ GB VRAM را **بدون text encoderها** بیان می‌کند؛ بنابراین آن را نیاز کل گردش‌کار نمی‌نامیم. [ComfyUI](https://docs.comfy.org/installation/system_requirements) اجرای CPU را ممکن و کندتر می‌داند. مدل دارای وزن قابل دریافت الزاماً مجوز متن‌باز یکسانی با ابزار اجرایی ندارد؛ انتخاب نهایی باید مجوز همان مدل را نیز لحاظ کند.

## کار باقی‌مانده برای پذیرش محیط وب

1. محیط دسکتاپ دارای OS پشتیبانی‌شده و مرورگر جاری انتخاب و با تأیید کاربر آماده شود. پیشنهاد پایدار، میزبان جایگزین Server 2022/2025 با Desktop Experience یا دسکتاپ لینوکسی پشتیبانی‌شده است؛ انتقال داده/Bridge و راه بازگشت باید پیش از تغییر مشخص شود. این گزارش مجوز خرید یا مهاجرت نیست.
2. در نشست RDP واقعی، مرورگر نصب‌شده، نسخهٔ کامل و برنامهٔ پیش‌فرض بازکنندهٔ `.url` بررسی شوند. بارگیری صفحه، JavaScript، cookie، فرایند ورود و چالش احتمالی باید همان‌جا آزموده شود. فایروال، TLS، حفاظت مرورگر یا کنترل‌های ورود برای عبور از خطا خاموش نشوند.
3. کاربر شخصاً در صفحهٔ رسمی وارد حساب شود و در صورت لزوم مرحلهٔ دوم را انجام دهد. رمز یا کد ورود در چت، گیت‌هاب یا Bridge قرار نگیرد. ورود موبایل/Work/مرورگر دیگر به معنی ورود این پروفایل RDP نیست. [راهنمای رسمی OpenAI](https://learn.chatgpt.com/docs/web.md) مسیر ورود وب را توضیح می‌دهد.
4. یک پیام آزمایشی فارسی ارسال و پاسخ واقعی ثبت شود. سپس یک تصویر ساده تولید، روی VPS ذخیره و از همان فایل باز شود. [راهنمای تصویر OpenAI](https://learn.chatgpt.com/docs/image-generation.md) تولید تصویر از داخل گفت‌وگوی وب را پشتیبانی می‌کند؛ امکانات و محدودیت‌ها به حساب/فضای کار وابسته‌اند. اگر `/images/` مسیر مؤثری نبود، تولید از داخل چت آزموده شود.
5. برای استفادهٔ معمول دسکتاپ، بازکردن مجدد مرورگر و اتصال مجدد RDP بررسی شود. ماندن نشست مرورگر، اجرای Bridge پس از قطع RDP و اجرای سرویس مدل پس از reboot سه نتیجهٔ مجزا هستند و به‌جای هم گزارش نشوند.

برای محیط مستقل، معیار پذیرش اضافه است: مدل و نسخهٔ دقیق، مجوز، footprint واقعی دیسک/RAM/VRAM، سرعت اندازه‌گیری‌شده، نمونهٔ خروجی و محل ذخیره، و سپس در صورت درخواست سرویس ماندگار و رفتار پس از reboot. یک فرایند دستی که فقط تا زمان بسته‌شدن پنجره کار کند، سرویس مستقل پایدار محسوب نمی‌شود. در طرح اولیهٔ سرویس، رابط فقط روی loopback باشد؛ هر تغییر فایروال، دسترسی شبکه یا startup نیازمند تأیید جداگانه است.

## دامنهٔ اقدام انجام‌شده

دو job فقط‌خواندنی در شاخهٔ جداگانه منتشر و با commit و SHA256 ثابت از مسیر موجود Bridge اجرا شدند. خود jobها تنظیمی تغییر نمی‌دهند؛ Bridge موجود، فایل موقت job و journal معمول اجرای خود را می‌نویسد. هیچ مدل، برنامه، درایور یا سرویس جدیدی نصب نشد؛ هیچ API تولیدی یا سرویس پولی فراخوانی نشد؛ هیچ رمز، کلید خصوصی، cookie، پروفایل مرورگر یا دادهٔ بیمار خوانده یا منتشر نشد. صفحهٔ دسکتاپ/RDP در اختیار این اجرا نبود، بنابراین مرورگر کاربر باز یا کنترل نشد.

- موجودی: commit `547cb868d98ef7f30db52d7e5139e1323d76c572`؛ SHA256 `0a7563f3c69d0eb8b36147a373add6e67865620410b41504412faed6299e4149`.
- بررسی مقصد: commit `2af4e79a5331f0a19e2e69ed615e3e0103d2b75e`؛ SHA256 `fd2a9b642f63eb146cb723848d633f2447f2f54bc1243fa1bdc3218a7b3805e7`.
- بررسی محلی: نحو Python، مسیر بدون عملیات روی غیر ویندوز، طبقه‌بندی GPU نامشخص/مجازی، مقصد HTTPS مجاز، رد خروجی نامعتبر/طولانی، و ۱۰ حالت parser میان‌بر شامل UTF-16/BOM، URL تکراری، دامنهٔ مشابه، query و خواندن محدود گذشتند. این‌ها آزمون رندر یا مدل نبودند.

اقدام بعدی پیشنهادی، انتخاب مسیر وب روی OS پشتیبانی‌شده و انجام آزمون تعاملی است. روی این VPS هیچ نصب یا تغییر امنیتیِ تأییدنشده‌ای در صف باقی نمانده است.
