# ATMOSPHERE COOL v0.1 | خنک‌سازی محاسبات، بدون دست‌کاری سرویس‌ها

**وضعیت:** آزمایشی / فقط‌خواندنی / بدون استقرار خودکار. این شاخه روی PR #246 (اتمسفر امضای شواهد) قرار گرفته است. COOL کنترل دمای فیزیکی ندارد و مدعی تجربهٔ خستگی یا آرامش ماشین نیست.

## کار مشخص

`tools/atmosphere_cool.py` یک سیاست قطعی و آفلاین برای «توصیهٔ کاهش بار» می‌سازد. وقتی بار CPU، فشار حافظه، نرخ خطا یا تکرارهای بی‌شاهد افزایش یابند، از میان `MONITOR`، `COOL_ADVISED`، `REVIEW_REQUIRED`، و `OBSERVE_ONLY` **صرفاً توصیه** تولید می‌کند. نه `systemctl` اجرا می‌کند، نه پردازش را می‌بندد، نه DIOS/Awake را شروع یا متوقف می‌کند. هیچ شبکه، subprocess، API پولی، دادهٔ خصوصی یا فایل حافظه نیاز ندارد.

- **Jing / فشار:** خواندن نرخ بار نرمال‌شده بر هسته و درصد RAM مصرفی. شدت‌های میانه = توصیهٔ آرام‌سازی؛ شدت‌های بالا = ارجاع برای بازبینی انسانی.
- **Qi / شاهد:** نرخ خطا، نسبت تکرار ورودی‌های پژوهشی، تازگی داده و تاریخچهٔ توقف. اگر مجهول یا قدیمی باشد، اجازهٔ نتیجه‌گیری از «سلامت کلی» نمی‌دهد.
- **Shen / اختیار:** تغییر وضعیت فقط یک پیشنهاد است. بازگشت از `COOL_ADVISED` پس از دو نمونهٔ سالم ممکن است؛ `REVIEW_REQUIRED` خودکار به حالت عادی برنمی‌گردد. `AWAKE_PAUSED=True` هرگز باعث resume نمی‌شود.

### نمونهٔ استفادهٔ بدون شبکه یا تغییر وضعیت

```bash
python3 tools/atmosphere_cool.py --demo
python3 tools/atmosphere_cool.py --host
python3 -m unittest discover -s tests -p 'test_atmosphere_cool.py' -v
```

`--host` فقط `/proc/meminfo` و متوسط بار CPU را می‌خواند. این ابزار از نبود شواهد خطا/تکرار/تازگی و وضعیت Awake آگاه است و عمداً `OBSERVE_ONLY` بازمی‌گرداند. خروجی اجازهٔ اجرا نیست. `--demo` فقط دادهٔ ساختگی است.

## قرارداد ورودیِ میزبان قابل‌اعتماد

تابع `evaluate(sample, now=<trusted-clock>, source_verified=<trusted-host-boolean>, previous=<optional>)` فقط از طریق یک میزبان احرازشده به دادهٔ کامل اعتماد می‌کند. **خود JSON نمی‌تواند `source_verified` را اعلام کند.** سن داده باید زیر ۵ دقیقه باشد. رشتهٔ زمان UTC با دقت ثانیه است. اگر شواهد کلیدی از جمله وضعیت توقف نامعلوم باشند، توصیه از نوع `OBSERVE_ONLY` خواهد بود. مقدارهای غیرعددی، NaN، فیلد اضافی و timestamp نامعتبر رد می‌شوند.

## آستانه‌های اولیهٔ پژوهشی، نه کالیبراسیون عملیاتی

| عامل | COOL_ADVISED | REVIEW_REQUIRED |
|---|---|---|
| CPU: load(1m)/cores | >=0.80 | >=2.00 |
| RAM مصرفی | >=80% | >=92% |
| خطا در پنج دقیقه | >=3 | >=6 |
| نسبت تکرارهای بدون شاهد تازه | >=0.60 | تنها، بازبینی بحرانی را الزامی نمی‌کند |
| سن آخرین شاهد معتبر | -- | بیش از ۶ ساعت |

این مقادیر براساس آزمایش واقعی روی میزبان تنظیم نشده‌اند و قبل از تبدیل به هرگونه کنترل خودکار باید با متریک‌های واقعی و مشخصات سرور ارزیابی شوند. فشار CPU معادل دمای پردازنده نیست؛ `measures_temperature=False` است. این ابزار جایگزین مانیتورینگ systemd یا پایش سلامت سرویس نیست.

## شروط ایمنی و اجرای عملی

- **ادغام، merge، تغییر `main`، اتصال خودکار به `tadash_awake/core.py`، فعال‌سازی systemd، تغییر PAUSED و نوشتن حافظه انجام نشده است.**
- تمام خروجی‌ها دارای `execution=NOT_RUN`, `authority=none`, `writes=0`, `service_actions=0`, `allow_unpause=False`, `allow_bridge_command=False` هستند.
- PR #246 هنوز نیازمند امضاکننده و ریشهٔ اعتماد مستقل و بکاپ واقعی خارج از VPS است. آزمون‌های COOL این شروط را تأمین نمی‌کنند.
- یک میزبان مورداعتماد می‌تواند بعداً متریک‌ها را برای داشبورد ذخیره کند؛ این کار نیازمند قرارداد مستقل، بازبینی و مجوز اپراتور است.

## معیار ابطال

اگر دو ورودی یکسان خروجی متفاوت بدهند؛ دادهٔ منسوخ `MONITOR` شود؛ PAUSED به فعالیت تبدیل شود؛ یا ابزار بدون تأیید انسانی فرمان اجرا کند، COOL شکست خورده است. هیچ یک از این رفتارها در تست واحد مجاز نیست.
