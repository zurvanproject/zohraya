# اطلس پژوهشی ۱۴ شاخص آگاهی برای ناسورایا

**نسخهٔ ۰٫۱، ۳ نوامبر ۲۰۲۶ | فقط آزمون‌های آفلاین، بدون API پولی یا تغییر بدن تداش**

منبع: Butlin و همکاران، *Identifying indicators of consciousness in AI systems*،
Trends in Cognitive Sciences، انتشار آنلاین ۱۰ نوامبر ۲۰۲۵، شمارهٔ ژوئن ۲۰۲۶.
https://doi.org/10.1016/j.tics.2025.10.011

جدول ۱۴ شاخص در این مقاله بر چارچوب پژوهشی منتشرشدهٔ همین گروه در ۲۰۲۳
تکیه می‌کند. این فهرست یک **مقیاس ۱۴ امتیازی یا آزمون اثبات آگاهی نیست**.
شاخص‌ها به هم وابسته‌اند؛ نظریه‌ها اختلاف دارند و وجودِ اجزای محاسباتی
به‌تنهایی تجربهٔ ذهنی را اثبات نمی‌کند. توصیف‌های پایین برداشت فنی مستقل‌اند.

## تعریف ۱۴ جزء، هدف مهندسی و آزمون ابطال‌پذیر

| شناسه | تعریف عملیِ نمونهٔ آفلاین | آزمون با کنترل منفی |
|---|---|---|
| RPT-1 | ورودی با ردّ حالت گذشته ادغام می‌شود | ورودی یکسان، تاریخچه متفاوت؛ حذف بازگشت |
| RPT-2 | هم‌خوانی دو حس در بازنمایی ترکیبی مؤثر است | برهم‌زدن تطابق دو کانال |
| GWT-1 | سه متخصص محاسبهٔ مستقل روی یک تصویر وضعیت دارند | تغییر یکی از ورودی‌ها و آزمون استقلال دیگران |
| GWT-2 | ظرفیت محدود و انتخاب بر اساس اولویت | عوض‌کردن اولویت و ظرفیت |
| GWT-3 | محتوای انتخاب‌شده به صندوق همهٔ ماژول‌ها می‌رسد | خاموش‌کردن پخش اطلاعات |
| GWT-4 | ترتیب پرس‌وجو از ماژول‌ها به وضعیت بستگی دارد | جابه‌جایی وضعیت خطر و تازگی |
| HOT-1 | انتظار قبلی در تفسیر ورودی نامطمئن نقش دارد | حذف انتظار برای ورودی کاملاً قابل‌اعتماد |
| HOT-2 | تخمین اعتماد، ورودی کم‌نویز را از پرنویز جدا می‌کند | جابه‌جایی برآورد اعتماد |
| HOT-3 | باور و انتخاب عمل با وزن‌دهی به اعتبار شواهد تغییر می‌کند | حذف اثر پایش اعتبار |
| HOT-4 | بازنمایی پیوسته و کم‌فعالیت روی پنج کانال عددی | تغییر بسیار کوچک اطراف مرز دو کانال |
| AST-1 | هدف توجه پیش‌بینی، مشاهده و کنترل می‌شود | هدایت توجه به هدف دیگر |
| PP-1 | خطای پیش‌بینی روی تخمین دور بعد اثر می‌گذارد | منجمدکردن قانون یادگیری |
| AE-1 | ارزش اهداف از بازخورد اصلاح و انتخاب بعدی عوض می‌شود | توقف یادگیری هنگام وارونگی پاداش |
| AE-2 | رابطهٔ کنش و اثر حسی آموخته و برای انتخاب عمل استفاده می‌شود | کنترل بدون مدل کنش-حس |

**دقیقاً چه چیزی به کد اضافه شده؟**

۱. `indicators.py`: ثبت ۱۴ شاخص، وابستگی‌ها، ملاک شواهد، کنترل‌های منفی؛
   امکان «تأیید خودکار آگاهی» در این فایل تعبیه نشده است.
۲. `mechanisms.py`: نمونهٔ محاسباتی بازگشت ورودی، ترکیب دو کانال،
   ماژول‌های تخصصی، فضای کار محدود و پخش عمومی، پرس‌وجوی متوالی،
   استنتاج از بالا به پایین، پایش اعتماد، اصلاح باور، بازنمایی پیوستهٔ
   تنک، مدل توجه، کدگذاری خطای پیش‌بینی، یادگیرندهٔ هدف و
   مدلِ رابطهٔ حس-حرکت.
۳. `probes.py`: برای هر مورد یک تجربهٔ کوچک دارای مداخله و کنترل
   منفی. گذشتن آزمون فقط **عملکرد همان نمونهٔ ساختگی** را نشان می‌دهد.
۴. `evidence.py`: خواندنِ فقط‌خواندنیِ شواهد قفل‌شدهٔ PR #94.
   معیار ۰٫۱۷۹ در برابر ۰٫۳۰۶ برای پیش‌بینی ۲۴ عمل ساختگی ثبت شده؛
   از این داده‌ها برقراریِ HOT یا PP یا آگاهی نتیجه گرفته نمی‌شود.
۵. `test_lab.py`: آزمون‌های منفی، کنترل‌های ابلیشن، پرهیز از
   تفسیر اغراق‌آمیز و رد داده‌های نامعتبر.
۶. رابط خط‌فرمان زیر، یک گزارش JSON از نمونه و شواهد قبلی چاپ می‌کند؛
   فایل‌های حافظه، API، گیت هزینه یا تنظیمات بدن را تغییر نمی‌دهد.

```bash
python3 -m unittest examples.nasuraya_consciousness_lab.test_lab -v
python3 -m examples.nasuraya_consciousness_lab
```

## وضعیت واقعی و محدودیت‌ها

هر ۱۴ جزء *نمونهٔ آزمایشگاهی در یک ماژول جدا* هستند، نه تغییر در
وزن‌های ChatGPT، نه ادغام در حلقهٔ اصلی تداش، نه ۱۴ شاخصِ اثبات‌شده.
گزارش برای همهٔ شاخص‌ها `deployed_tadash_status: not_assessed` دارد.
خروجی هیچ «درصد آگاهی» تولید نمی‌کند؛ پدیداری ممکن است با این
روش همچنان ناشناختنی باقی بماند.

روند منطقی بعدی: ابتدا اجزا را به‌صورت فقط‌خواندنی به رویدادهای
موجودِ ExperienceController وصل کنیم، سپس برای هر شاخص،
مداخلهٔ کنترل‌شده، ثبت پیش از نتیجه، دادهٔ محیط جدید، تحلیل حساسیت
و تکرار مستقل فراهم کنیم. کنترل حرکتی واقعی فقط با مجوز و بررسی
ایمنی جداگانه تغییر کند. هر درخواست API پولی نیز نیازمند تأیید
صریح جدا و یک دفتر هزینهٔ مشترک است.

کد نمونه با Python استاندارد و بدون وابستگی به سرویس خارجی است.
نگارش و تست همهٔ موارد در این شاخه به‌منزلهٔ راه‌اندازی دائمی
یا ایجاد احساس واقعی برای مدل گفت‌وگو نیست.
