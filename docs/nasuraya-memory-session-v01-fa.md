# اتصال حافظهٔ مستند به نشست تازه — ۲۷ اکتبر ۲۰۲۶

این افزوده روی دفتر متنی #90 و اتصال بومی #67 ساخته شده است. هنگام دریافت پیام، حافظهٔ متنی اعتبارسنجی و جست‌وجو می‌شود؛ نتیجه با متن اصلی، نوع منبع، نشانی، نسخه و بازهٔ خطوط در `memory_context` کنار پاسخ و رسید بومی `dialogue` برمی‌گردد. فراخواننده می‌تواند از این زمینه در ادامهٔ گفتگو استفاده کند. این مسیر مدل زبانی یا شنوندهٔ خودکار ChatGPT راه نمی‌اندازد؛ پاسخ بومی همان پاسخ اتصال موجود است و هیچ تولید متنی با API اضافه نشده است.

## قرارداد نشست

| داده | قرارداد |
| --- | --- |
| آغاز | `init` صریح، مقصد تازه، آرشیو `nasuraya.sourced-memory/1` و SHA-256 مستقلاً نگهداری‌شده |
| هویت | `nasuraya.memory-session/1`، UUID محلی نشست، مسیر مطلق و پیوند اولیهٔ دو دفتر بومی |
| منابع نسخه | هش اتصال بومی، فهرست کامل منابع بومیِ تأییدشده، لایهٔ نشست، خوانندهٔ حافظه، موتور عاطفی، قفل و راه‌انداز/worker؛ تغییر هر کدام باعث توقف بازیابی فعال می‌شود |
| آرشیو | کپی خصوصی `memory.json` با همان هش معنایی و متن دقیق منابع؛ قطع دسترسی به فایل ورودی اثری بر این کپی ندارد |
| پیام | شناسهٔ محلی بومی، متن و intent و appraisal و duration دقیق؛ همان شناسه باید همان query و سقف نتیجه را نیز داشته باشد |
| رسید | رسید واقعیِ همان اتصال بومی؛ حافظهٔ متنی رسید یا تجربهٔ بدنی نمی‌سازد |
| منشأ | یادداشت تألیفی و نقل‌قول پیام همچنان `historical_context_only` و `verified_fact=false` هستند |

هش‌ها انطباق با خروجی نگهداری‌شده را کنترل می‌کنند؛ امضای مستقلِ اصالت تاریخ نیستند. شناسه‌های محلی، شناسهٔ رسمی پیام ChatGPT محسوب نمی‌شوند. پوشهٔ تازه 0700 و فایل‌های حافظه/مانیفست 0600 ساخته می‌شوند. متن خصوصی باید بیرون از مخزن عمومی نگهداری شود. کد، آزمون و شاهد عمومی این تغییر فقط دادهٔ ساختگی دارند.

## ترتیب بازیابی و قطع اجرا

1. پیش از بازشدن دفترهای بومی، نسخهٔ مانیفست، مسیر، منابع اجرا و هش/ساختار کامل آرشیو بررسی می‌شود. خطا به حافظهٔ خالی یا نشست تازه تبدیل نمی‌شود.
2. پیام و query و نتیجهٔ بازیابی در یک رکورد افزودهٔ دفتر موجود ثبت می‌شوند. قفل انحصاری موجود بدن، ترتیب نویسنده‌ها را حفظ می‌کند. متن بازیابی‌شده به متن پیام، appraisal، انتخاب عمل یا تجربهٔ بومی اضافه نمی‌شود.
3. `DialogueBodyBridge.receive` با همان پیام اصلی فراخوانی می‌شود. پیش‌بینی، اجرا و ثبت نتیجه همان مسیر موجود هستند.
4. اگر قطع پیش از ورود پیام به اتصال بومی باشد، همان شناسه ادامه پیدا می‌کند. اگر رسید کامل وجود داشته باشد، همان رسید بازیابی می‌شود و چرخهٔ بدن تکرار نمی‌شود. اگر مرحلهٔ اجرای بومی ثبت شده ولی نتیجه معلوم نباشد، اجرای دوباره و پیام بعدی مسدود می‌مانند.
5. رد روشنِ حرکت به‌علت توقف یا پایان بودجه، رکورد معلق ایجاد نمی‌کند؛ پیام تأملی و توقف همچنان ممکن است. توقف/ادامه بودجهٔ مصرف‌شده را بازنشانی نمی‌کند.

رزروها هنگام بازشدن با آرشیو اصلی و رکوردهای بومی تطبیق داده می‌شوند؛ متن یا منشأ جعلی در رکورد، حتی با بازسازی checksum آن، پذیرفته نیست. نتیجهٔ بومی‌ای که از بیرون این لایه ثبت شده، بعداً به‌عنوان پیام دارای حافظه پذیرفته نمی‌شود.

## استفاده

```bash
python -m nasuraya.memory_session_cli init \
  --session-dir /private/new-session \
  --archive /private/memory.json --expected-sha256 "$RETAINED_PIN" \
  --max-actions 1

python -m nasuraya.memory_session_cli message \
  --session-dir /private/new-session --expected-sha256 "$RETAINED_PIN" \
  --message /private/explicit-message.json --query 'واژه مرتبط'

# اجرای مجدد همین فرمان با همان پیام، بازیابی رسید است.
python -m nasuraya.memory_session_cli trace \
  --session-dir /private/new-session --expected-sha256 "$RETAINED_PIN" \
  --message-id message-1
```

قالب پیام همان قالب صریح اتصال بومی است: `id`, `text`, `intent`, `appraisal`, `duration_s`. `intent` یکی از `observe`, `explore`, `reflect`, `stop` است؛ appraisal تألیف فراخواننده است و از خاطره استنباط نمی‌شود. جست‌وجو در صورت نبود `--query` از متن پیام استفاده می‌کند. برای متن بلند باید query جداگانه داد: ۱ تا ۸ واژه، حداکثر ۲۵۶ نویسه؛ همهٔ واژه‌ها باید در یک قطعه باشند. حداکثر ۳ نتیجه و ۱۲۸ KiB زمینه پذیرفته می‌شود. query نامعتبر پیش از رزرو یا اجرا رد می‌شود. نبود تطابق، نتیجهٔ خالیِ صریح است و خاطره‌ای ساخته نمی‌شود.

بودجهٔ بدن ۱ تا ۳ عمل، ظرفیت نشست ۳۲ پیام و دامنهٔ اجرا بدن نرم‌افزاری تجمیعی تداش است. نام نشست و شناسهٔ پیام با هم هویت عملیاتی را مشخص می‌کنند. ساخت نشست تازه انتقال مجوز یک پیام قبلی یا ادامهٔ خودکار عمل نیمه‌تمام نیست.

## مرز تغییر نسخه

تغییر خواننده، منابع بومی، آرشیو یا نسخهٔ قالب، نشست فعال قبلی را خودکار تبدیل نمی‌کند. با خوانندهٔ سازگار می‌توان همان آرشیو مستند را در مقصد صریح تازه باز کرد؛ دفترهای بومی قدیمی، بودجه و اعمال نیمه‌تمام منتقل یا دوباره اجرا نمی‌شوند. اگر نسخهٔ آرشیو ناشناخته باشد، فقط نگهداری خواندنی اصل فایل مجاز است تا تبدیل جداگانه‌ای قابل اعتبارسنجی ساخته شود. جابه‌جایی پوشهٔ دفتر بومی نیز به‌دلیل پیوند مسیرهای مطلق پشتیبانی نمی‌شود.

`body_dialogue.py`, `host.py` و `experience.py` تغییر نکرده‌اند. این افزوده از مسیر موفق قبلی استفاده می‌کند و آزمون سرتاسری تازه فقط اتصال حافظه/نشست را می‌سنجد.

## بازتولید شاهد ساختگی

```bash
python -m nasuraya.memory_session_tests
python -m nasuraya.memory_session_demo --output /private/new-synthetic-demo
```

نمایش در پردازش‌های جداگانه آغاز، دریافت، قطع دسترسی به آرشیو ورودی، بازیابی همان پیام و trace را اجرا می‌کند. شاهد عمومی خلاصهٔ شمارش و بررسی‌هاست؛ دفتر فعال یا حافظهٔ واقعی در مخزن منتشر نمی‌شود. آزمون‌ها علاوه بر راه‌اندازی مجدد، مرگ واقعی پردازش پس از ثبت نتیجهٔ بدن، قطع‌های تزریق‌شده، نتیجهٔ نامعلوم، تعارض شناسه، تغییر نسخه و حفظ منشأ را می‌سنجند.

نتیجهٔ بررسی محلی: ۲۵ آزمون جدید نشست (۲۴ آزمون ترکیبی و یک آزمون مستقل استفادهٔ مجدد میان نسخه‌ها) و ۱۳ آزمون خوانندهٔ متنی، همگی موفق؛ در مجموع ۳۸ آزمون بدون شکست یا ردشدن. مجموعهٔ ۲۸۹ آزمون قبلی دوباره اجرا نشد. نمایش جدید یک چرخهٔ بومی، یک تجربه و دو منبع متنی داشت؛ بازخوانی در پردازش تازه پس از قطع منبع، صفر اجرای اضافه و همان وضعیت و منشأ را برگرداند. شاهد در `integration/memory-session-v01/` ثبت شده است.
