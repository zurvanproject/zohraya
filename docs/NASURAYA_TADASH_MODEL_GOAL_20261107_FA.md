# اتصال محدود مدل زبانی به تداش — ۷ نوامبر ۲۰۲۶

این تغییر روی PR #155 ساخته می‌شود. هدف یک دور محدود و قابل‌بازیابی است: مشاهدهٔ بدن نرم‌افزاری موجود، حداکثر سه چرخهٔ بومی، ارزیابی از رسیدها، و حفظ همان هدف و نتایج میان فرایندهای جدا.

## محل اجزا

- مدل `gpt-6-astra` در Agents API، با `environment.type=none` و subagent غیرفعال.
- گردانندهٔ فراخوانی در محیط Work، با کلید اختصاصی در فایل خصوصی تأییدشدهٔ کاربر؛ کلید به سرور یا GitHub فرستاده نمی‌شود.
- بدن، checkpoint و دفتر هدف روی Windows VPS موجود؛ اجرا از طریق پل v2 و job ثابتِ commit/SHA256.
- این اتصال **caller-mediated** است: گردانندهٔ مجاز باید نتیجهٔ ابزار درخواستی را از پل دریافت و به API برگرداند. listener همیشگی یا daemon مدل روی VPS نصب نشده است.

## سه ابزار

| ابزار | اختیار |
|---|---|
| observe_body | مشاهدهٔ کاهش‌یافتهٔ انرژی، خستگی، درد، فشار خواب، revision و پیشرفت هدف |
| request_body_action | فقط ترجیح walk یا observe برای یک چرخهٔ ۰٫۱ ثانیه‌ای؛ حفاظت بومی و بازخورد قبلی می‌توانند ترجیح را تغییر دهند |
| evaluate_goal | خواندن شمار تکمیل‌شده از دفتر هدف؛ تأیید فقط پس از سه رسید بومی یگانه |

ابزارها به shell، فایل خصوصی، شبکه، کلید، reset یا کنش فیزیکی دسترسی ندارند. وضعیت اولیهٔ جاری از PR #155 ادامه داده می‌شود؛ دو چرخهٔ قبلی به‌عنوان انجام این هدف شمرده نمی‌شوند. مدل بومی همان شبیه‌ساز تجمیعی قدیمیِ ۱۹۵ کیلوگرمی است.

## پایداری و بازپخش

- قرارداد تغییرناپذیر هدف: `nasuraya-review-20261107-v1`؛ سقف سه چرخه و ۱۲ شناسهٔ ابزار.
- دفتر هدف در `state/agent-goals.sqlite` کنار نشست بدن روی سرور است؛ سقف کلی ۲۰ کنشِ میزبان قبلی نیز حفظ می‌شود.
- شناسهٔ ابزار از SHA256 نشست/دور/فراخوانی API ساخته می‌شود. شناسه‌های اصلی نشست و متن گفت‌وگو در کد عمومی job قرار نمی‌گیرند.
- reservation درخواست و شناسهٔ تصمیم، پیش از اجرای بدن با SQLite/FULL ذخیره می‌شوند.
- اگر بدن commit کند ولی ثبت نتیجهٔ ابزار قطع شود، همان رسید بومی بازیابی و با هدف تطبیق داده می‌شود؛ اثر دوباره اجرا نمی‌شود.
- نتیجهٔ کامل با همان شناسه از دفتر برمی‌گردد؛ تغییر payload با همان شناسه رد می‌شود.
- عملیات native حل‌نشده، مشاهدهٔ کهنه، کنش خارج از مسیر و گذشتن از سقف جلوی کنش تازه را می‌گیرند.
- سمت API، session id، هدف، pending calls، outbox نتایج و کلیدهای idempotency ذخیره می‌شوند؛ ارسال نتیجه پس از پاسخ نامعلوم با pending واقعی آشتی داده می‌شود.

## کلید و دسترسی

با تأیید صریح کاربر، کلید تازهٔ مخصوص تداش از اتصال امن Platform ساخته و در `.env.local` خصوصی با مجوز 0600 ذخیره شد. مقدار کلید در ابزار خروجی داده نشد و بخشی از مخزن، checkpoint گزارش یا فایل شواهد نیست. `.env.*`، محیط بسته‌ها و وضعیت خصوصی گرداننده از Git کنار گذاشته شده‌اند.

GET مدل‌ها موفق بود و مدل انتخاب‌شده در حساب موجود بود. نشست واقعی Agents API ساخته شد و observe_body را درخواست کرد. یک گزینهٔ اختیاری spending limit که SDK جدید می‌شناسد، در API این حساب با HTTP 400 / unknown_parameter رد شد؛ درخواست اصلاح‌شده از قرارداد پایهٔ مستند استفاده می‌کند. سقف مبلغ دلاری از سرویس ادعا نمی‌شود؛ سقف کنش و تعداد ابزار در میزبان صریح و پایدار است.

## بررسی فعلی

۷ آزمون goal/native و ۶ آزمون گرداننده، بدون API، محلی گذشتند. موارد شامل حفظ هدف در فرایند تازه، سقف سه چرخه، رسید تکراری، payload متعارض، نبود مشاهده، قطع بین commit بدن و ذخیرهٔ هدف، دفتر بیگانه، بازیابی session و آشتی‌دادن پاسخ نامعلوم API هستند.

در زمان ثبت اولیه، مدل واقعی منتظر نتیجهٔ مشاهدهٔ سرور است؛ تکمیل سه چرخه یا دور مدل هنوز ادعا نمی‌شود. شواهد نهایی با شناسهٔ پاسخ‌های متناظر و نتیجهٔ turn جدا ثبت می‌شوند.

## اجرا

```sh
python -m unittest discover -s tests -p "test_tadash_agent_*.py" -v
python -m pip install -r deploy/tadash_agent/requirements.txt
python deploy/tadash_agent/client.py start
python deploy/tadash_agent/client.py pending
python deploy/tadash_agent/client.py submit --call-key HASH --result-file PRIVATE_RESULT.json
python deploy/tadash_agent/client.py status
```

فرمان start با وجود session ذخیره‌شده، همان هدف را دنبال می‌کند. ایجاد نشست با کلید idempotency ثابت انجام می‌شود. فراخوانی ابزار باید توسط گردانندهٔ احراز هویت‌شده روی سرور اجرا شود؛ client.py به‌تنهایی احراز هویت GitHub را ایجاد نمی‌کند. در پایان، تنها پس از ذخیرهٔ گزارش‌ها، session از API پاک می‌شود.
