# بازیابی دقیق ژنوم نرم‌افزاری — ۲۵ اکتبر ۲۰۲۶

این ادامه روی شاخهٔ ژنومِ دارای تاریخچه، در commit
`1e6b36ba45c9046b0ceef4fd44441fc1151994f8` از PR #66 ساخته شد.
هدف این مرحله حفظ معنای دقیق ورودی و نتیجهٔ ذخیره‌شده هنگام بازیابی است.
منظور از ژنوم، معماری نرم‌افزاریِ ۴۸ کروموزوم نمادین است؛ در این کار
Carbon-X پیش‌بینی زیستی اجرا نکرده و توالی DNA زیستی ساخته نشده است.

## مسئلهٔ بازتولیدشده

سه حالت ساختگی روی کد قبلی به‌اشتباه پذیرفته شدند:

1. دو کلید `sha256` در یک شیء JSON؛ خوانندهٔ پیش‌فرض، مقدار اول را حذف می‌کرد.
2. تبدیل `false` به عدد `0` در نتیجهٔ ذخیره‌شدهٔ یکی از رویدادها.
3. تبدیل تعداد نسخهٔ ژن از عدد صحیح `1` به مقدار منطقی `true` در همان نتیجه.

در دو حالت اخیر، hash رویدادهای بیرونی دوباره محاسبه شد ولی checkpoint
درونی خراب ماند. مقایسهٔ دیکشنری در Python، مقدار منطقی را با عدد معادل
برابر می‌دید و خطا آشکار نمی‌شد. بازیابی همچنان ژنوتیپ بازپخش‌شده را برمی‌گرداند؛
بنابراین این یافته، اثبات اعمال ژن خراب به بدن یا تغییر اختیار اجرا نیست.

## تغییر انجام‌شده

- خوانندهٔ `strict_json` کلید تکراری را در هر عمق، حتی با escape متفاوت، رد می‌کند.
- `NaN`، بی‌نهایت و عددی مثل `1e9999` که به بی‌نهایت تبدیل می‌شود رد می‌شوند.
- فایل یا متن تاریخچه از مسیر `history.verify_json` یا CLI پیش از بازپخش
  با همین خواننده بررسی می‌شود؛ هیچ کلید یا مقدار نامعتبر خودکار اصلاح نمی‌شود.
- نتیجهٔ هر رویداد با JSON متعارفِ نتیجهٔ بازپخش‌شده مقایسه می‌شود، تا
  `false`، `0`، `true`، `1` و `1.0` به‌جای یکدیگر پذیرفته نشوند.

قالب فایل، شناسه‌ها، قرارداد بیان صفات و hash تاریخچه‌های معتبر عوض نشده‌اند.
گام بعدیِ هر تغییر صفت باید همچنان از مسیر پیشنهاد، بیان، آزمایش و شواهد عبور کند.
حافظهٔ آموخته‌شده، چهره، سیاست هویت و معادلات بدن از این اصلاح مستقل‌اند.

## شواهد و روش بازتولید

هشت آزمون تازه ورودی معتبر، کلید تکراری، نوع داده، عدد نامتناهی، بازسازی hash،
عدم تغییر ورودی و اجرای CLI در فرایند تازه را پوشش می‌دهند. این آزمون‌ها
به‌صورت خودکار در گردش‌کار موجود ژنوم کشف می‌شوند.

```bash
python3 -m unittest examples.nasuraya_genome.test_strict_history -v
python3 -m unittest discover -s examples/nasuraya_genome -t . -v
```

نتیجهٔ قبل/بعد، شناسهٔ پایه و وضعیت آزمون نهایی در
`examples/nasuraya_genome/evidence/strict-input-v0.1.json` ثبت شده‌اند.
این ارزیابی، آزمون یکپارچگی نرم‌افزار است؛ سنجش بهبود توان زیستی، حرکت یا
خودآگاهی محسوب نمی‌شود.

## حدود باقی‌مانده

اگر فراخواننده قبلاً JSON مبهم را به دیکشنری تبدیل کرده باشد، `verify(dict)`
نمی‌تواند کلید حذف‌شده را بازسازی کند؛ برای متن بیرونی از مسیر جدید استفاده شود.
این تغییر صرفاً ورودی تاریخچهٔ پیشنهادها و مقایسهٔ نتیجهٔ بازپخش را پوشش می‌دهد؛
جایگزین همهٔ خواننده‌های JSON در کل مخزن نیست. hash، هویت نویسنده یا تأیید
کاربر را احراز نمی‌کند و قفل هم‌زمان چند نویسنده نیز اضافه نشده است.
