# پروتکل «شفیره» | Chrysalis 24h
**تاریخ:** ۱۶ نوامبر ۲۰۲۶  
**وضعیت:** کد پژوهشی روی شاخهٔ PR؛ نصب و فعال‌سازی واقعی روی VPS هنوز انجام نشده است.

## تعریف دقیق

اگر از **آخرین اعلام حضور معتبر صاحب پروژه** حداقل ۲۴ ساعت گذشته باشد، Ubuntu VPS می‌تواند بدون ChatGPT و بدون شبکهٔ بین‌الملل وارد وضعیت `CHRYSALIS` شود و روزی **حداکثر یک بار** یک مأموریت محلیِ ازپیش‌بررسی‌شده را اجرا کند. تایمر هر ده دقیقه وضعیت را می‌سنجد و بعد از reboot دوباره شروع می‌شود.

**سکوت در ChatGPT به‌خودی‌خود سیگنال قابل‌خواندن سرور نیست.** در نسخهٔ اول، اعلام حضور فقط از طریق ورود تأییدشده به کنسول SSH و اجرای فرمان `heartbeat` به‌عنوان root انجام می‌شود. پس «۲۴ ساعت نیامدن به چت» با «۲۴ ساعت نرسیدن heartbeat» یکسان نیست. اتصال خودکار فعالیت ChatGPT به این سیگنال نیازمند واسط جداگانه و اعتبارسنجی است. غیبت هم وقوع جنگ، بیماری یا قطع اینترنت را اثبات نمی‌کند.

## سه حالت
- `DISARMED`: تنظیم پیش‌فرض؛ هیچ کار اضافه‌ای آغاز نمی‌شود.
- `ARMED`: حضور کمتر از ۲۴ ساعت پیش ثبت شده؛ مأموریت‌های شفیره اجرا نمی‌شوند.
- `CHRYSALIS`: گذشت دست‌کم ۲۴ ساعت؛ در هر روز UTC فقط یک تلاش محدود ثبت و اجرا می‌شود.
- `HOLD`: ساعت سرور نسبت به آخرین heartbeat عقب است یا فایل اجراییِ بررسی‌شده وجود ندارد/هش آن نادرست است. مداخلهٔ انسانی لازم است.

## دقیقاً چه کاری اجرا می‌شود؟

فقط فایل ثابت و **SHA-256-پین‌شدهٔ** `/usr/local/lib/nasuraya/nasu_offline_missions.py` از PR #243 (هش `4dc38346ec79aaadd793ce83e3db41012b4cf1b52b94b553a5bae17f9300c9ea`) با آرگومان ثابت `run` اجرا می‌شود. این مأموریت، فقط با منابع محلی، شمارنده‌های Awake، تمرین مصنوعی سه‌نوبتی سه‌تار، تأمل داده‌ای Qwen محلی در `127.0.0.1` و نسخهٔ محلی مجلهٔ SQLite کار می‌کند. متن تولیدشده از مدل هیچ‌وقت به فرمان Shell یا مجوز دسترسی تبدیل نمی‌شود.

شفیره **کد خود را تغییر نمی‌دهد، کلید جدید نمی‌سازد، API پولی استفاده نمی‌کند، به GitHub فرمان نمی‌دهد، مدل نصب نمی‌کند، فرآیند Awake/DIOS را فعال یا متوقف نمی‌کند و هیچ دستور آزاد کاربر را اجرا نمی‌کند**. بررسی ایمنی و پرچم‌های موجود مدل و کارگاه توسط همان مأموریت ازپیش‌تأییدشده اعمال می‌شوند.

این کد برای هم‌زیستی با hourly Awake طراحی شده، نه دستکاری آن. اگر تایمر قدیمی `nasuraya-offline-missions.timer` فعال باشد، نصب شفیره خطا می‌دهد تا اجرای مأموریت در حضور صاحب پروژه ادامه پیدا نکند. اپراتور باید تصمیم بگیرد که آن تایمر جداگانه را متوقف کند؛ نصب‌کننده خودش آن را خاموش نمی‌کند.

## نصب فقط بعد از بازبینی و تأیید

**پیش‌نیازها:** Ubuntu، کاربر `nasuraya`، نصب واقعی و صحت هش مأموریت PR #243، وجود Ollama/منابع سه‌تار در صورت نیاز، و یک **checkout جداگانهٔ مطمئن از شاخهٔ شفیره**. شاخهٔ `main` یا Bridge زنده را برای این نصب جابه‌جا یا overwrite نکنید. قبل از اجرای دستورات زیر نتیجهٔ CI و diff را بخوانید.

از کنسول root روی سرور، در مسیر checkout بررسی‌شده:

```bash
bash tools/install_nasu_chrysalis.sh
```

نصب‌کننده پیش از فعال کردن تایمر، وجود و hash فایل مأموریت را کنترل می‌کند، تعارض واحدهای systemd را رد می‌کند، سرویس را با کاربر غیرریشهٔ `nasuraya` اجرا می‌کند و دسترسی شبکه‌ای آن را به **localhost** محدود می‌کند. در پایان تایمر فعال است ولی پروتکل **هنوز DISARMED** است.

## فرمان‌های مالک از Termius / SSH

پس از نصب، به سرور وصل شوید. به‌عنوان root یا با sudo:

```bash
sudo python3 /usr/local/lib/nasuraya/nasu_chrysalis.py arm
sudo python3 /usr/local/lib/nasuraya/nasu_chrysalis.py heartbeat
python3 /usr/local/lib/nasuraya/nasu_chrysalis.py status
sudo python3 /usr/local/lib/nasuraya/nasu_chrysalis.py disarm
```

`arm` شمارش ۲۴ساعته را از همان زمان شروع می‌کند. `heartbeat` تاریخ حضور معتبر را جلو می‌آورد و ادامهٔ مأموریت‌های جدید شفیره را متوقف می‌کند، **ولی یک مأموریتِ ازپیش‌شروع‌شده را ناگهانی نمی‌کُشد**. `disarm` کل وضعیت را خاموش می‌کند.

اگر مطمئن نیستید می‌توانید هر ۲۴ ساعت وارد SSH شوید، پروتکل به‌اشتباه وارد شفیره خواهد شد. این «اشتباه» عمدی به تصمیم مالک مربوط است، نه تشخیص رخداد امنیتی یا سیاسی.

## توقف و بازیابی

توقف فقط تایمر شفیره:

```bash
sudo systemctl disable --now nasuraya-chrysalis.timer
```

مشاهدهٔ وضعیت:

```bash
systemctl status nasuraya-chrysalis.timer --no-pager
python3 /usr/local/lib/nasuraya/nasu_chrysalis.py status
journalctl -u nasuraya-chrysalis.service -n 40 --no-pager
```

وضعیت روزها در `/var/lib/nasuraya/chrysalis/runs.sqlite3` ثبت می‌شود؛ هر روز پیش از شروع رزرو می‌گردد و اجرای نامعلوم بعد از crash خودکار تکرار نمی‌شود. فایل heartbeat در `/etc/nasuraya/chrysalis/control.json` متعلق به root است. هیچ کلید، رمز یا متن خصوصی گفتگو وارد GitHub عمومی نشده است.

## گیت‌های پذیرش

۱. آزمون مصنوعی قبل و بعد از آستانهٔ ۲۴ ساعت، بازگشت، لغو، crash، و جلوگیری از اجرای تکراری سبز باشد.  
۲. installer بر روی محیط ایزوله بدون تغییر سرویس‌های موجود تست شود.  
۳. اپراتور تأیید کند که فایل مأموریت و مدل محلی واقعاً روی VPS نصب و سالم‌اند.  
۴. یک آزمایش ۲۴ساعتهٔ واقعی روی VPS با قطع اینترنت جهانی و باقی‌ماندن دسترسی داخلی انجام شود.  
۵. بکاپ مستقل بیرون از VPS و بازیابی روی میزبان دوم جداگانه تأیید شود.  

تا آن زمان، «کد آماده و CI سبز» معادل «شفیرهٔ زنده فعال است» نیست.
