# آزمون سرتاسری بازگردانی مستقل ناسورایا | ۱۶ نوامبر ۲۰۲۶

**شاخهٔ اصلاحی:** `fix/offsite-restic-e2e-20261116`، بر پایهٔ PR #234.
**وضعیت:** پژوهشی، بدون نصب/فعال‌سازی روی VPS، بدون انتقال دادهٔ واقعی.

## مسئله

PR #234 پیش‌تر آماده‌سازی snapshot سازگار با SQLite، رمزگذاری/آپلود Restic، بازیابی همان snapshot و بررسی SHA-256 را پیاده‌سازی کرده بود. آزمون‌های قبلی فقط بلوک‌های Python داخل اسکریپت را به‌صورت جداگانه اجرا می‌کردند. اشتباه در کنترل جریان Bash، استخراج شناسهٔ snapshot، پرچم حالت بکاپ‌تنها یا اتصال بین `restic backup` و `restic restore` ممکن بود از دید آن آزمون‌ها دور بماند.

## آنچه این تغییر به پروژه اضافه می‌کند

فایل `tests/test_nasu_offsite_roundtrip_e2e.py` **تمام دستور Bash** موجود در `tools/nasu_offsite_restore_drill.sh` را در یک محیط موقت اجرا می‌کند. فقط مسیر دو منبع واقعی در یک کپی موقت با مسیرهای نمونه جایگزین می‌شود؛ منطق snapshot، Restic و بازبینی تغییر نمی‌کند.

برنامهٔ `restic` در آزمون، یک جانشین محلی بدون شبکه است و صرفاً فایل‌ها را کپی می‌کند؛ بنابراین **هیچ رمزگذاری یا بازیابی از راه دور در این آزمون انجام نمی‌شود**. هدف آزمون، بررسی اتصال قطعات نرم‌افزار و رفتار در شکست است، نه اثبات مقاومت در خرابی دیتاسنتر.

هفت آزمون:

1. تهیهٔ snapshot از دیتابیس مهاجرت‌یافتهٔ فعلی (نه نمونهٔ قدیمی)، ثبت manifest و بازگردانی و بررسی SHA/SQLite.
2. حالت `NASU_BACKUP_ONLY=1` باید restore را واقعاً رد کند و فقط backup انجام دهد.
3. اگر پس از restore فایل Awake دستکاری شود، نتیجه باید شکست بخورد.
4. در صورت خطای آپلود، عملیات موفق اعلام نشود و restore اجرا نشود.
5. مسیر Restic محلی به‌جای URL دارای طرح مقصد دوردست، پیش از هر عملیات رد شود.
6. اگر گزارش مهاجرت به مسیر خارج از محدودهٔ مجاز اشاره کند، پیش از آپلود شکست بخورد.
7. اگر فایل رمز Restic وجود نداشته باشد، پیش از آپلود شکست بخورد.

CI موجود در `.github/workflows/nasuraya-offline-recovery-preflight.yml` به‌روزرسانی شده تا این هفت آزمون را نیز اجرا کند.

## وضعیت پذیرش عملیاتی

- **ساخت و بررسی کد:** نتیجهٔ واقعی GitHub Actions باید جداگانه دیده شود.
- **ذخیره‌سازی مستقل:** هنوز نیازمند مقصدی با مالکیت/مدیریت و حوزهٔ خرابی مستقل از VPS اصلی.
- **بازیابی واقعاً مستقل:** هنوز نیازمند رمز و کلید بیرون از هر دو VPS، snapshot واقعی، restore روی ماشین دوم، و صورت‌جلسهٔ آزمون.
- **عملکرد LLM هنگام قطع اینترنت:** آزمون CPU واقعی + reboot + قطع خروجی بین‌الملل جداگانه لازم است.
- **امنیت:** هیچ رمز، IP اختصاصی، کلید شخصی یا دادهٔ خصوصی در GitHub قرار نگیرد. انتشار خروجی‌های حساس ممنوع است.
