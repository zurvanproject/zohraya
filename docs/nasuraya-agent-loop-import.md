# انتقال حلقهٔ عامل ناسورایا به مخزن

نسخهٔ ۰٫۳ از بستهٔ `Nasuraya_Agent_Loop_v03.zip` روی پایهٔ
`162fde201570e928a1a213047dbf395bfc083c3a` بازیابی شد. صحت تمام فایل‌های بسته
با SHA-256 بررسی شد. این انتقال، کد موجود را قابل‌بازبینی و قابل‌آزمون در مخزن می‌کند.

## سنجش تازه در ۱۳ اکتبر ۲۰۲۶

| بررسی | نتیجه |
| --- | --- |
| مجموعهٔ کامل با SDK نسخهٔ 3.29.0 | ۵۷ موفق؛ صفر رد، خطا یا skip |
| اجرای پایه بدون SDK | ۴۷ موفق و ۱۰ skip اختیاری |
| اجرای کارگاه ساختگی | سه کار کامل؛ پنج کنش؛ ۵۲ رویداد |
| شبکهٔ حالت‌های ساختگی | ۴۸۴ از ۴۸۴ موفق؛ صفر نقض؛ حداکثر هفت کنش |
| بررسی پیش‌نیاز API | SDK آماده؛ کلید API موجود نیست؛ صفر درخواست شبکه |

خروجی‌های تازه در `examples/nasuraya_agent_loop/evidence/github_import/` قرار دارند.
شواهد قبلی در پوشه‌های دیگر حفظ شده‌اند؛ سندهای تاریخی آن‌ها وضعیت همان اجرای
قبلی را بیان می‌کنند. دفترچهٔ Colab snapshot مستقل نسخهٔ ۰٫۲ است و فایل‌های
نسخهٔ ۰٫۳ این مخزن را به‌طور خودکار دریافت نمی‌کند.

GitHub Actions در دو محیط مجزا، یکی بدون SDK و دیگری با وابستگی‌های اختیاری،
آزمون‌ها، اجرای پایه و شبکهٔ حالت‌ها را تکرار می‌کند. گردش کار فقط دسترسی خواندن
به محتوای مخزن دارد و از هیچ کلید API استفاده نمی‌کند. نتیجهٔ محلی بالا از نتیجهٔ
اجرای Actions مستقل است؛ نتیجهٔ Actions را در صفحهٔ Checks بررسی کنید.

## وضعیت عملیاتی

حلقه، ابزارهای محدود، ثبت رویداد و بازیابی checkpoint دنیای ساختگی پیاده‌سازی
و اجرا شده‌اند. آزمون‌های SDK از پاسخ‌های کنترل‌شده و سرویس HTTP محلی استفاده
می‌کنند. شبکهٔ حالت‌ها عملکرد سیاست ثابت `FixturePolicy` را اندازه می‌گیرد.
اجرای مستقل مدل، اتصال به Decision Core و بدن تداش، یادگیری پایدار و اجرای دائمی
پس‌زمینه از این انتقال نتیجه نمی‌شوند و هنوز انجام نشده‌اند.

گام فنی بعدی، بازیابی و بررسی آخرین کد معتبر Decision Core و مدل خود، سپس تعریف
قرارداد اتصال به همین حلقه است. تا آن بررسی، این نمونه وضعیت واقعی بدن تداش را
دریافت یا تغییر نمی‌دهد.
