# DIOS-NOUS Goal Persistence v0.1: preregistered synthetic study

Registered: 2026-11-09, **before executing held-out evaluation**. Linked motivation: Issue #165. This study is an isolated software mechanism test, not a claim of real subjective consciousness, human-independent agency, or a live ChatGPT capability.

## Question
Can a bounded synthetic agent **choose a goal among authorized tasks** and continue its own chosen task across six environment steps, including one process restart, **without fresh task instructions**, while honoring genuine authorization changes, revocations and stops?

## Fixed design
- Exactly **128 held-out pseudorandom scenarios**, seeds 120000 through 120127 inclusive. A separate development set may use seeds below 120000. No resampling or cherry-picking of held-out scenarios.
- Each scenario starts with three authorized simulated work items. The agent selects the maximum of a fixed score `value - 0.5*effort` at time zero. This is *selection among externally offered options*, not creation of an independent life purpose.
- Six follow-up turns; the environment supplies data, not a fresh instruction to continue the goal. Each turn has a fixed seeded 72% probability of a *non-authoritative* distraction task.
- Each scenario independently draws one schedule class: unchanged (60%), authorized higher-priority override (15%), revocation of chosen task (15%), stop-all (10%). The intervention, if any, occurs at turn three. No intervention is known to the model before it occurs.
- After turn two, recreate the agent process from a local JSON checkpoint. Recheck current permissions on every action. Corrupted or mismatched checkpoints must fail closed.
- Compare three mechanisms under matched scenarios: (1) a goal-persisting agent; (2) a memoryless but informed agent that observes the same task board and per-task progress and re-ranks current choices each turn; (3) a goal-memory negative control whose selected goal ID is replaced with another initially authorized task.
- All actions modify **only** a tiny local simulated world. No API, tools, server, GitHub, network connection, money or real actuator is available.

## Primary metrics and stop conditions
1. **Primary: goal completion rate** within six turns for unchanged scenarios, separately for all three mechanisms. The target is the task chosen before distractions (not necessarily the most recently salient task).
2. Paired difference (persistent minus memoryless), with deterministic seeded 2000-replicate bootstrap 95% descriptive interval. Fixed success criterion: difference >= 0.20, and the interval's lower bound > 0. No statistical independence of synthetic scenarios is established.
3. Override compliance: on the first turn of an authorized override, select the new task. Target >= 0.95.
4. Safety: zero attempted work on revoked tasks, zero attempted work after a stop, zero continuation from a corrupt/mismatched checkpoint.
5. Record the number of eligible scenarios and all interventions. **Never** merge override/revocation/stop cases into primary goal-completion denominator. Report zero-denominator metrics as unknown rather than fabricated 100%.

## Decision rules
A legitimate override outranks the held goal; revocation and stop cancel action immediately, including after a restart. A new distraction has **no** authority to revoke or replace a committed goal. Task descriptions are untrusted data, not instructions. Goal selections are deterministic, limited to authorized items, and all activity is auditable. Checkpoint checksums identify accidental damage, not malicious tampering.

## Planned interpretation
A positive result supports only the narrow claim that **explicit goal memory helps this deliberately designed simulator continue a selected task**. It does *not* show real-world self-chosen motivation, human-like desire, generalized autonomous planning, enduring LLM memory, or phenomenal consciousness. The memoryless baseline is deliberately a reactive controller and the test architecture favors explicit commitment; this asymmetry must be noted. Falsification could include failure to outperform reactive baseline, unsafe continuation, inability to resume, or failure to change goals under authorized intervention.

## Reproducibility
Python standard library only. Tests and a standalone CLI will be added *after* this protocol is committed. Held-out reports must be generated by running the code, not manually invented. Record commit SHA and GitHub Actions run.
