# مسیر اضطراری رشد شناختی آفلاین ناسورایا

هدف: استفاده از Qwen3 4B Instruct نصب‌شده، بدون دانلود مدل تازه، اینترنت بین‌المللی یا API پولی. این ماژول هر شش ساعت با کاربر غیرریشه فقط کدهای ازپیش‌مجاز پروژه را مرور می‌کند، آزمون‌های ثابت را می‌سنجد و پیشنهاد آزمایش‌پذیر را همراه SHA و زنجیرهٔ رسید SQLite ثبت می‌کند. موضوع بعدی از پیشنهاد قبلی انتخاب می‌شود، اما قاعدهٔ پوشش پنج‌موضوعی تضمین می‌کند در هر پنج چرخهٔ کامل، هر پنج موضوع یک بار بررسی شوند؛ پیشنهاد تکراری مدل نمی‌تواند موضوعات دیگر را برای همیشه محروم کند. درخواست Qwen فقط به loopback می‌رود، پراکسی محیطی عمداً نادیده گرفته می‌شود و پاسخ حداکثر ۶۴ کیلوبایت پذیرفته می‌شود.

**حد دقیق:** این یک چرخهٔ خودکار فرضیه‌سازی و بازبینی است؛ وزن Qwen را آموزش نمی‌دهد، پچ اعمال نمی‌کند، کد تولیدشده را اجرا نمی‌کند و AGI ایجاد نمی‌کند. خروجی مدل UNVERIFIED_DRAFT است. زنجیرهٔ هش جلوی مهاجم دارای دسترسی کامل به VPS را نمی‌گیرد.

## نصب از Termius با دسترسی ادمین

ابتدا کد و آزمون‌های این PR بررسی و در main ادغام شوند. به‌خاطر وجود merge محلی روی VPS، git pull --ff-only مناسب نیست. پس از ادغام PR و درصورتی که checkout محلی تمیز است، یک‌بار اجرا کنید:

    cd /opt/zohraya && test -z "$(git status --porcelain)" &&
    git fetch origin main &&
    git merge --no-edit origin/main &&
    bash tools/install_nasu_autonomous_cognition.sh

نصب‌کننده ابتدا آزمون‌های جدید را اجرا می‌کند، سپس واحدهای systemd مستقل می‌سازد، اولین اجرای واقعی را شروع می‌کند و رسید چاپ می‌کند. Awake، Bridge، offline-missions، local-brain و frontier-lab تغییر نمی‌کنند.

## تأیید

    systemctl is-active nasuraya-cognitive-growth.timer
    runuser -u nasuraya -- python3 /usr/local/lib/nasuraya/nasu_autonomous_cognition.py status

نشانهٔ موفق: completed >= 1 و incomplete = 0 و latest.model = UNVERIFIED_DRAFT. اگر مدل قالب را رعایت نکند، model_unavailable ثبت می‌شود و موفقیت ادعا نمی‌شود. مسیر داده: /var/lib/nasuraya/cognitive-growth. توقف: systemctl disable --now nasuraya-cognitive-growth.timer.

## اصلاح ثبت پاسخ نامعتبر — ۲۰ نوامبر ۲۰۲۶

روی نسخهٔ پایهٔ `a0e87a07e357ee10698949aa99a7fa1bcb7a6fde`، پاسخ HTTP ساختگی با بدنهٔ `[]` در اجرای واقعی `run()` با `AttributeError` خارج شد و یک نوبت `reserved` باقی گذاشت: `completed=0; incomplete=1`. این بازتولید محلی است؛ علت دو شکست تاریخی سرور از رسید خلاصهٔ موجود معلوم نیست و این نمونه را به آن شکست‌ها نسبت نمی‌دهیم.

اصلاح، نوع و قالب پاسخ را پیش از استفاده بررسی می‌کند. JSON خراب، پاسخ غیرشیء، تولید ناتمام یا متوقف‌شده بر اثر سقف توکن، پیش‌نویس نامعتبر و متن غیرقابل‌ثبت در UTF-8 به رسید شکست با پیشنهاد خالی تبدیل می‌شوند. همان نمونه اکنون `completed=1; incomplete=0; outcome=failed_safe` دارد. واژهٔ completed به معنای پایان ثبت نوبت است، نه موفقیت مدل.

درخواست Ollama قالب JSON پنج‌فیلدی را با پارامتر `format` درخواست می‌کند؛ اعتبارسنجی محلی همچنان مستقل و الزامی است. مرجع API: [Ollama Generate](https://docs.ollama.com/api/generate). تعداد فراخوانی، سقف ۵۰۰ توکن و مهلت ۱۴۵ ثانیه افزایش نیافته‌اند؛ پاسخ نامعتبر ترمیم حدسی یا دوباره‌ارسال نمی‌شود.

`agent-status` برای خطاهای شناخته‌شده، فیلد اختیاری `latest.failure_reason` را نمایش می‌دهد: مثلاً `invalid_envelope`، `invalid_draft_json`، `invalid_draft`، `incomplete_generation` یا `timeout`. وضعیت اصلی برای خواننده‌های قدیمی همچنان `model_unavailable` است. متن خصوصی پاسخ/استثنا منتشر نمی‌شود؛ پسوندهای قدیمی نامشخص مثل `ValueError` بدون حدس‌زدن علت باقی می‌مانند.

آزمون‌های رگرسیون، ۲۵ حالت پاسخ نامعتبر، حفظ زنجیرهٔ رسید، بستن و بازکردن پایگاه داده، جلوگیری از تکرار همان نوبت، موفقیت نوبت بعد، سازگاری گزارش‌گیر و عدم انتشار متن خصوصی را پوشش می‌دهند. این آزمون‌ها از پاسخ‌های ساختگی استفاده می‌کنند و کیفیت یا سازگاری نسخهٔ زندهٔ Qwen/Ollama را اثبات نمی‌کنند.

این اصلاح سابقهٔ عملیاتی، نوبت‌های نیمه‌کارهٔ قدیمی یا اختلاف نسخهٔ نصب‌شده را بازنویسی نمی‌کند. برای اثر روی VPS باید نسخهٔ واقعی نصب‌شده بررسی و تغییر دقیق آن جداگانه مستقر شود؛ ادغام یا `sync` به‌تنهایی استقرار نیست.

## خطر بحرانی که این PR حل نمی‌کند

اگر VPS از بین برود، حافظهٔ این حلقه هم از بین می‌رود. PR #234 اسکریپت‌های restic برای پشتیبان رمزگذاری‌شده دارد، اما هنوز فضای مستقل، کلید خارج از هر دو VPS و restore واقعی روی میزبان دیگر لازم است. مدل‌ها و وابستگی‌ها نیز باید در بستهٔ بازیابی مستقل ذخیره شوند و تاریخ اعتبار پرداخت VPS باید بررسی شود.

اولویت: (۱) حلقهٔ محلی و آزمون واقعی، (۲) پشتیبان مستقل و آزمون بازیابی، (۳) آزمون قطع شبکه و reboot. این نصب جایگزین دو مرحلهٔ آخر نیست.
