# یکپارچه‌سازی ناسورایا: پژوهش، حافظه و مشاهدهٔ بدن

تاریخ: ۲۲ اکتبر ۲۰۲۶. این گزارش مربوط به به‌روزرسانی درخواست تغییر ۶۷ است.
شاخهٔ اصلیِ مبنا `5330cbee347c1ef5b7c3a77e74f91398d45aa76f` و منبع مدل خود
درخواست تغییر ۶۸ با شناسهٔ `4433ba8909c7e6e38b79f6d3bf29ca13805c4244` است.

## چه مشکلی رفع شد؟

نسخهٔ یکپارچهٔ قبلی، میزبان شش‌ساعتهٔ آزمایشی را با خود آورده بود. آن میزبان
هنگام خواندن وضعیت همیشه دفتر `cadence-v2.json` می‌خواست، درحالی‌که پژوهش
فعال شاخهٔ اصلی از قالب روزانه و حافظهٔ مدل استفاده می‌کند. این ناسازگاری
حتی پیش از درخواست مدل، خواندن حافظه را متوقف می‌کرد. تعارض متنی workflow
نیز مسیر اجرا و تعداد نوبت‌ها را تغییر می‌داد.

اکنون میزبان فعلی شاخهٔ اصلی و دو موتور پژوهش عیناً حفظ شده‌اند. نسخهٔ
شش‌ساعته و تست‌هایش در `continuity_host/cadence_host.py` مستقل مانده‌اند.
زمان‌بندی روزانه، مسیر اجرا، حالت‌های دستی و محدودیت‌های موجود حفظ شده‌اند.
هیچ مهاجرت یا بازنشانی دفتر زنده انجام نشده است.

## اتصال تازهٔ مدل خود

فرمان `self-observe` وضعیت همان بدن ذخیره‌شده را از audit بومی می‌خواند و
به مدل خودِ درخواست تغییر ۶۸ می‌دهد. برنامه از یک فرایند جدا، بدون credentials
و بدون بازکردن میزبان‌های تغییردهندهٔ وضعیت استفاده می‌کند. checkpoint پیش و
پس از مشاهده برابر می‌ماند و زمان شبیه‌سازی جلو نمی‌رود.

خواندن SQLite فقط‌خواندنی است. فایل مفقود ساخته نمی‌شود؛ فایل نامعتبر،
symlink، hardlink، نویسندهٔ فعال و اجرای حل‌نشده رد می‌شوند. دادهٔ نامعلوم
به مقدار ساختگی تبدیل نمی‌شود و کهنگی گزارش در مدل خود مشخص می‌ماند.
رد hardlink مهم است، چون دفتر WAL به مسیر فایل وابسته است و یک نام دیگر
ممکن است checkpoint قدیمی را نشان دهد.

در اجرای مشترک، یک پیام ساختگی به ارزیابی، تصمیم و بدن تجمیعی تداش رسید.
یک چرخهٔ `walk` اجرا شد. در بازپخش پیام با فرایند تازه، تعداد حرکت اضافه صفر
بود و وضعیت نهایی برابر ماند. مدل خود دقیقاً همان checkpoint پس از عمل را
خواند؛ مشاهده نیز صفر چرخهٔ بدنی ایجاد کرد. مقدار integrity نامعلوم باقی
ماند. برچسب عملیاتی `OPTIMAL` خروجی محدود همین مدل نرم‌افزاری است و سلامت
زیستی، حس درونی یا اندازه‌گیری مستقل جسمانی را اثبات نمی‌کند.

## شواهد این نوبت

- ۱۲ مجموعهٔ مرتبط، مجموعاً ۱۷۳ مورد آزمون: **۱۶۲ موفق، ۱۱ کنارگذاشته‌شده
  به‌علت نبود وابستگی اختیاری tensor، صفر شکست**. موارد کنارگذاشته‌شده پاس
  حساب نشده‌اند. مجموعهٔ تاریخی ۱۰۲۵ آزمونی در این نوبت دوباره اجرا نشد.
- ۱۱۰ آزمون میزبان، پژوهش، مدل، cadence و سازگاری وضعیت فعلی بدون skip
  موفق شدند. آزمون‌ها شامل فراخوانی واقعی زیرفرایندِ regression ثابت هستند.
- هر دو reader واقعی پژوهش و مدل با backend ساختگیِ فقط GET و بدون دفتر
  cadence کار کردند؛ مسیر `auto` نیز تماس اخیر را رعایت کرد.
- نسخهٔ فقط‌خواندنی حافظهٔ فعلی از commit عمومی
  `8aa17a665fae940da545cfae69323bdf6384e475` محلی اعتبارسنجی شد. hash موتور و
  anchor حافظه با نسخهٔ یکپارچه سازگار بودند. دفتر زنده تغییر نکرد.
- demo پژوهش آفلاین از ورودی مشترک اجرا شد: چهار آزمایش مصنوعی با ادامه
  در فرایندهای تازه، حفظ آخرین حافظه هنگام بازپخش و توقف پس از پایان برنامه.
  این demo از مدل زنده استفاده نمی‌کند و مجموعهٔ اعتبارسنجی آن بازاستفاده‌شده است.
- ۷۰ فایل بومی و ۹ blob وابستگیِ ثابت حفظ شدند. ورودی مشترک اکنون ۳۱ فرمان دارد.

خلاصه‌ها و لاگ‌های همین بررسی در `integration/refresh-v02/` هستند. وضعیت
GitHub Actions باید از اجرای مربوط به commit منتشرشده خوانده شود؛ نتیجهٔ
محلی جای نتیجهٔ CI را نمی‌گیرد.

## بازتولید

از ریشهٔ checkout اجرا کنید. پوشه‌های خروجی باید تازه باشند:

```bash
python -m nasuraya.verify_sources
python -m nasuraya demo --output /tmp/nasuraya-unified-v02
python -m nasuraya self-observe --session /tmp/nasuraya-unified-v02/session/body.sqlite
python -m nasuraya research-day --output /tmp/nasuraya-research-v02
```

برای تست‌های میزبان، checkout جداگانهٔ commit
`7aaee60198b50246d90242d5155d3e3736882792` را با `NASURAYA_TEST_SOURCE` معرفی
کنید. فرمان دقیق مجموعهٔ این نوبت در `integration/refresh-v02/summary.json` ثبت است.

## محدودهٔ نتیجه

این اصلاح، نسخهٔ مشترک را با پژوهش فعلی سازگار می‌کند و مدل خود را به بدن
همان demo متصل می‌کند. فراخوانی پولی، دریافت خودکار پیام زندهٔ ChatGPT،
فعال‌کردن بدن مفصلی در پس‌زمینه یا ادغام در شاخهٔ اصلی جزو اجرای این نوبت
نبوده است. آزمایش شبیه‌سازی‌شدهٔ بدن تجمیعی را نباید راه‌رفتن جسم واقعی یا
آزمون تازهٔ بدن مفصلی دانست.
