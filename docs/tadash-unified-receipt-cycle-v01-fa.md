# تداش | یک چرخهٔ پیوستهٔ بدن، نیاز، حافظه، تصمیم و یادگیری

**نسخهٔ آزمایشی ۰٫۱، ۴ نوامبر ۲۰۲۶.** این تغییر روی شاخهٔ آزمایشی PR #136 ساخته شده و تا ادغام دو PR، بخشی از `main` نیست.

## چه چیزی واقعاً اضافه شد؟

مسیر اجرایی `unified-enable / unified-step / unified-status` پنج نمای مرتبط را با **یک عملیات بومی** در اختیار می‌گذارد:

`وضعیت بدن → فشار نیازهای مدل‌شده → حافظه/پیش‌بینی قبلی → پیشنهاد عمل → رسید واقعی نرم‌افزار بدن → ثبت بازخورد در همان حافظه`

این پنج موتور مستقل جدید نیستند. یک هماهنگ‌کنندهٔ نازک روی **ExperienceController موجود** است و از لایه‌های موجود `motivation`، `workspace`، `autonomic_bridge`، `neurovisceral` و `spinal_reflex` استفاده می‌کند. برنامه‌ریز و حفاظت واقعی بدن همچنان در `BodyLoop` قرار دارند. موج خودکار و بازنمایی اندامی پیشنهادهای **محاسباتی و غیرزیستی** هستند، نه دادهٔ حسگر واقعی. هیچ‌کدام مجاز نیستند پیشنهاد محافظه‌کارانهٔ مشاهده را به حرکت ارتقا دهند.

### زنجیرهٔ علی قابل‌ردیابی

هر `unified-step` یک شیء JSON برمی‌گرداند:

- `body`: چهار متغیر بدن قبل از تصمیم، پیش‌بینی و نتیجهٔ اندازه‌گیری‌شده در شبیه‌ساز
- `need`: فشارهای محاسباتیِ کمبود انرژی، خستگی، درد و خواب؛ «نیاز» اینجا یک **proxy** تعریف‌شده توسط طراح است
- `memory`: شناسهٔ خاطرات فراخوانده‌شده، تعداد شواهد پیش‌بینی و پیام مشترک فضای کار
- `decision`: ترجیح انگیزشی، ترجیح فضای کار، توصیهٔ عصبی‌ـ‌احشایی، توصیهٔ ستون مهره، درخواست نهایی و نتیجهٔ بومی
- `learning`: منبع معتبر تصمیم، خطای پیش‌بینی و افزایش شمار رسیدهای یگانه

ستون‌های «نیاز» در گزارش **تشخیصی** هستند؛ اثر عملی آن‌ها از الگوریتم انگیزه و حفاظت موجود می‌آید. گزارش، علت‌مندی تجربیِ یک مدل عصبی زیستی یا «احساس واقعی» را اثبات نمی‌کند.

### ایمنی، بازآغاز، صداقت

- فعال‌سازی صریح است و فقط پیش از نخستین اقدام بدن مجاز است. در نشست قدیمی اجراشده، ادغام گذشته‌نگر جعل نمی‌شود.
- تمامی لایه‌ها در **همان رکورد ExperienceController** ذخیره می‌شوند. منشأ مبدأ دو مدل فرعی به هش checkpoint اولیه بسته است.
- منبع و شناسهٔ ۳۲ رسید اخیر میان حافظهٔ تجربه، انگیزه، فضای کار، موج و مدل عصبی‌ـ‌احشایی تطبیق داده می‌شود. شمار کامل چرخه‌ها نیز با شمار بومی مقایسه می‌شود.
- اجرای مستقیم بدن بیرون از این مسیر، چرخهٔ یکپارچه را **ناسازگار** می‌کند و ادامهٔ یکپارچه رد می‌شود.
- شناسهٔ تکراری فقط همان رسید را بازمی‌گرداند. اگر برنامه پس از تکمیل بومی و پیش از ثبت شناختی قطع شود، **همان شناسه** با رسید بومی آشتی داده می‌شود و بدن دوباره اجرا نمی‌شود. عملیات بومی حل‌نشده همچنان بلوکه است.
- شکست اجرای بدن بازخورد موفق یا خاطرهٔ ساختگی نمی‌سازد؛ بودجه و سیاست حفاظت بومی پابرجاست.
- کلید API، پردازش دائمی، عامل آزاد، تغییر وزن‌های ChatGPT، بدن فیزیکی، حس بیولوژیک یا خودآگاهی ادعا و اضافه نشده است.

## استفاده از ریشهٔ مخزن

پیش‌نیاز: checkout شاخهٔ حاوی PR #136 و این تغییر؛ Python و Linux مطابق مستندات حلقهٔ بدن.

```bash
# یک نشست تازه و محدود با وضعیت اولیهٔ آزمایشی
python3 -m examples.nasuraya_body_loop start --fixture normal --max-actions 2 --session /tmp/tadash-one.sqlite

# یک بار فعال‌سازی همهٔ پیوندها، بدون صرف بودجهٔ کنش
python3 -m examples.nasuraya_body_loop unified-enable --session /tmp/tadash-one.sqlite --desire-proxy 0.6

# یک تصمیم/کنش واقعی در شبیه‌ساز با رسید واحد
python3 -m examples.nasuraya_body_loop unified-step --session /tmp/tadash-one.sqlite --decision-id cycle-1
python3 -m examples.nasuraya_body_loop unified-status --session /tmp/tadash-one.sqlite

# همان شناسه را تکرار کنید: اجرا یا یادگیری مضاعف نمی‌شود
python3 -m examples.nasuraya_body_loop unified-step --session /tmp/tadash-one.sqlite --decision-id cycle-1

# تصمیم دوم همان نشست با وضعیتِ به‌روزشده و خاطرهٔ واقعی قبلی
python3 -m examples.nasuraya_body_loop unified-step --session /tmp/tadash-one.sqlite --decision-id cycle-2
```

آزمون و نمونهٔ دو بدن ساختگی `normal / sleep` (همراه با بازگشایی سرد):

```bash
python3 -m examples.nasuraya_body_loop unified-test
python3 -m examples.nasuraya_body_loop unified-demo --output-dir /tmp/tadash-unified-demo-new
```

نمونهٔ `unified-demo` تنها در یک مسیر خروجی **تازه** اجرا می‌شود و `summary.json` می‌نویسد. آمار و نتایج باید از اجرای CI واقعی خوانده شوند، نه از صرف وجود کد.
