# نسخهٔ یکپارچهٔ ناسورایا — به‌روزرسانی ۲۲ اکتبر ۲۰۲۶

قابلیت‌های ۵۹ درخواست تغییر باز، به‌همراه حرکت مارپیچی و ممیزی مستقل تکیه‌گاه،
در یک شاخه جمع شده‌اند. ورودی مشترک `nasuraya` مسیر دسترسی به بدن، حافظه،
ژنوم، عاطفه، تصمیم، پژوهش، زبان و ابزارهای پروژه را فراهم می‌کند.

در به‌روزرسانی ۲۲ اکتبر، پژوهش روزانهٔ فعلی شاخهٔ اصلی و مدل خودِ درخواست
تغییر ۶۸ نیز وارد همین نسخه شدند. ورودی مشترک اکنون ۳۱ فرمان دارد. قرارداد
حافظه و برنامهٔ روزانهٔ موجود حفظ شده و میزبان شش‌ساعته در ماژول آزمایشی
جدا باقی مانده است. [گزارش این به‌روزرسانی](nasuraya-unified-v02-fa.md)
نتیجهٔ آزمون‌های تازه و محدودیت‌های آن را ثبت می‌کند.

## شروع

از ریشهٔ همین مخزن اجرا کنید:

```bash
python -m nasuraya catalog
python -m nasuraya body --help
python -m nasuraya dialogue --help
python -m nasuraya articulated --help
python -m nasuraya genome --help
python -m nasuraya self-observe --help
python -m nasuraya research-day --output /tmp/nasuraya-offline-research
python -m nasuraya demo --output /tmp/nasuraya-unified-demo
```

آخرین فرمان یک نشست تازهٔ ساختگی می‌سازد. پیام به ارزیابی عاطفی و تصمیم‌گیر
می‌رسد، یک چرخهٔ بدن اجرا می‌شود و پیامد در حافظه می‌ماند. سپس برنامه در
فرایندی تازه باز می‌شود و همان پیام را بدون تکرار حرکت بازخوانی می‌کند.
تاریخچهٔ پایهٔ ژنوم و سیاست هویتی نیز کنار همین نشست حفظ و بررسی می‌شوند.
مدل خود، همان checkpoint پس از عمل را فقط می‌خواند و نتیجه را در
`self-observation.json` گزارش می‌کند؛ این مشاهده حرکت تازه‌ای ایجاد نمی‌کند.

## مسیرهای اصلی

| حوزه | فرمان مشترک | کارکرد |
|---|---|---|
| بدن و تداوم | `body` | خواب، رسیدگی، بیداری محدود، حافظهٔ تطبیقی و کنترل پذیرش |
| گفتگو | `dialogue` | پیام ← عاطفه و تصمیم ← بدن تجمیعی ← بازخورد پایدار |
| بدن مفصلی | `articulated` | راه‌رفتن محدود با مدل ۸۵ کیلوگرمی و حفظ حالت مکانیکی |
| ژنوم | `genome`، `genome-traits`، `genome-design` | بیان صفات، تاریخچه و مقایسهٔ پیشنهادها |
| عاطفه و زیبایی | `affect`، `aesthetics`، `genome-values` | ارزیابیِ دارای منبع و استقلال داوری زیبایی |
| خودمدل | `self-model` | هدف و تجربهٔ پایدار، ادامهٔ محدود |
| مشاهدهٔ خود | `self-observe` | خواندن فقط‌خواندنی audit بدن و حفظ وضعیت نامعلوم یا کهنه |
| پژوهش روزانه | `research-host`، `research-day` | مسیر میزبان فعلی و بازتولید آفلاین آزمایش حافظه |
| حرکت و پژوهش | `spiral`، `running`، `research` | مسیرهای حرکتی و مشاهدهٔ بدن |
| آزمایش آفلاین | `dream`، `dream-native`، `causal-study` | یادگیری و سنجش با حفظ نتایج منفی |
| زبان | `language-train`، `language-body`، `language-internals` | آزمایش وزن‌ها و ساختار مدل محلی |
| ابزار و نگهداری | `guard`، `continuity`، `host` | اجرای صریح با دفتر و بودجهٔ قبلی |
| خدمات پروژه | `fund`، `audit-service` | پیشنهاد بودجه و پایلوت ممیزی آفلاین |

## معنای یکپارچگی

یک درخت کد، ورودی مشترک و اتصال‌های سازگار داریم. مدل بدن تجمیعی، بدن مفصلی
و مدل آزمایشی دویدن همچنان مدل‌های متفاوت‌اند؛ وضعیت و واحدهای آن‌ها به‌جای
هم استفاده نمی‌شوند. ژنومِ قدیمی روی مدل بدنی تازه بی‌صدا اعمال نمی‌شود.

ماژول‌های اختیاری زبان و مکانیک محیط وابستگی خود را دارند. می‌توان مسیر مطلق
مفسر هر محیط را در `NASURAYA_PYTHON_TENSOR`، `NASURAYA_PYTHON_MECHANICS`
و `NASURAYA_PYTHON_SDK` تعیین کرد. هسته و فهرست قابلیت‌ها به نصب این بخش‌ها
وابسته نیستند. فایل‌های قفل وابستگی قبلی حفظ شده‌اند.

## اتصال تازه میان قابلیت‌ها

یک ناسازگاری واقعی رفع شد: مسیر زیبایی‌شناسی ورودی اجتماعی می‌فرستاد، اما
کنترل فراشناختی قبلی فقط ورودی خالی را می‌پذیرفت. نسخهٔ دوم این کنترل اکنون
همان ورودی را در پیش‌بینی، ثبت تصمیم و اجرای بدن حفظ می‌کند. ارزیابی زیبایی،
عاطفهٔ بدن و یادگیریِ وابسته به رسید در یک نشست کار می‌کنند؛ ورودی اجتماعی
تازه نیز مجوز دورزدن محدودیت حرکت نمی‌شود. خواب با همین کنترل آزمایش شده است.

## بررسی

```bash
python -m nasuraya test --profile core --output /tmp/unified-core-tests
python -m nasuraya test --profile mechanics --output /tmp/unified-mechanics-tests
python -m nasuraya test --profile tensor --output /tmp/unified-tensor-tests
python -m nasuraya test --profile sdk --output /tmp/unified-sdk-tests
```

برای آزمون میزبان، `NASURAYA_TEST_SOURCE` باید به checkout جداگانهٔ commit
`7aaee60198b50246d90242d5155d3e3736882792` اشاره کند؛ این همان منبع ثابت آزمون
قبلی است. وضعیت «ردشده»، «اجرانشده» و آزمونِ ردشده به دلیل نبود وابستگی،
در گزارش از موفقیت جدا هستند. نگاشت تمام شاخه‌ها در `integration/sources.json`
و تصمیم‌های ادغام در `integration/RESOLUTIONS.md` ثبت شده است.

نتیجهٔ اجرای محلیِ تاریخیِ ۲۱ اکتبر: **۱۰۲۵ آزمون موفق**، شامل ۹۲۶ آزمون قابلیت‌ها و ۹۹ آزمون
هستهٔ بومی. **۳۳ آزمون تاریخی اجرا نشده‌اند**: ۲۶ مورد کنار گذاشته شدند و
یک مجموعهٔ ۷ آزمونی به دلیل نبود نمونهٔ خصوصی متوقف شد. بنابراین اجرای همهٔ
آزمون‌ها بدون آن نمونه‌ها نتیجهٔ کاملاً سبز ندارد. این نمونه‌ها منتشر نشده‌اند.
گزارش دقیق در `integration/verification.json` و نسخهٔ وابستگی‌های آزموده‌شده
در `integration/test-environment.json` است.

بازخوانی سردِ گفتگو بدون تکرار حرکت موفق بود. بدن مفصلی نیز دو گام متوالی
را در دو فرایند جدا، با حفظ دقیق موقعیت، سرعت، زمان و حالت حل‌گر ادامه داد؛
بازخوانی پیام قبلی وضعیت تازه را عقب نبرد و گام سوم با پایان بودجه متوقف شد.
این شواهد شبیه‌سازی‌اند؛ آزمایش سخت‌افزار یا اعتبارسنجی تجربی نیستند.

این نسخه برای بررسی روی شاخهٔ یکپارچه آماده شده است. ادغام در شاخهٔ اصلی
هنوز انجام نشده است. برنامهٔ روزانه و حافظهٔ فعلی در این به‌روزرسانی حفظ
می‌شوند؛ هیچ مهاجرتی به برنامهٔ شش‌ساعته انجام نشده است.
