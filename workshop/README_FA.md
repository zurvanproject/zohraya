# کارگاه ساعتی محدود زهرایا، نسخهٔ ۰٫۱

این بخش یک **آزمونگر خودکار و محدود** است، نه یک عامل Gemini، نه مدل زبانی
خودآغازگر، و نه فرآیندی که برای همیشه زنده بماند. هدف مرحلهٔ اول، ایجاد
چرخهٔ واقعی و قابل مشاهدهٔ اجرای مستقل روی GitHub Actions است.

## بعد از ادغام بازبینی‌شده در main

فایل `.github/workflows/zohraya-hourly-workshop.yml` نزدیک دقیقهٔ ۱۷ هر ساعت
(زمان UTC) در صورت فراهم‌بودن ظرفیت GitHub Actions فراخوانی می‌شود. زمان‌بندی
ممکن است به تأخیر بیفتد یا اجرا نشود؛ هیچ تضمین «اجرای دقیق هر ساعت» نداریم.
همچنین از بخش **Actions → Zohraya bounded hourly continuity workshop → Run workflow**
می‌توان به‌صورت دستی یک کار معین را اجرا کرد. توقف از صفحهٔ Actions با غیرفعال
کردن workflow ممکن است. ادغام نشده و تنها در Pull Request باشد، برنامهٔ
زمان‌بندی‌شده فعال نمی‌شود.

هر اجرا تنها یکی از چهار کار ثابت زیر را انتخاب می‌کند:

| Task | Work performed |
| --- | --- |
| `research` | آزمون‌های ورودی و مشاهده‌گر پژوهشی، بدون SDK خارجی |
| `body-bridge` | آزمون پیوند بدنی و بازیابی کنترل‌شدهٔ آن |
| `motion-mirror` | آزمون بازپخش نمونه‌های حرکتی و تطبیق آن‌ها |
| `native-reflection` | آزمون‌های بومی بدنی و چرخهٔ تعمق (بر پایهٔ manifest) |

انتخاب `auto` بر اساس شمارهٔ ساعت UTC و به‌صورت قابل‌بازتولید چرخشی است. هر
فراخوانی حداکثر یک فرمان از مجموعهٔ مجاز اجرا می‌کند. بودجهٔ هر فرمان حداکثر
۳۶۰ ثانیه و بودجهٔ کل job نه دقیقه است. تداخل اجراها با concurrency کنترل
می‌شود. آزمون شکست‌خورده یا timeout باعث شکست job می‌شود و رسید JSON حاوی
داده‌های لازم برای بررسی در artifact همان اجرا ثبت می‌گردد (۱۴ روز نگهداری).

گزارش `receipt.json` دارای شناسهٔ اجرا، revision، SHA256 خروجی متنی، نتیجه و
پیشنهاد گام بررسی است. این رسید **حافظهٔ دائمی شخصی** و اثبات یادگیری نیست.
دسترسی GitHub در workflow فقط `contents: read` است؛ `main` یا شاخهٔ دیگری
از این ابزار ویرایش نمی‌شود. کلید Gemini یا OpenAI به subprocess منتقل نمی‌شود.
اجرای آزمون در checkout موقت ممکن است فایل محلی بنویسد؛ هیچ ادعایی دربارهٔ
تغییرنکردن همهٔ فایل‌های محلیِ آن checkout نشده است.

## بازتولید محلی

از ریشهٔ مخزن با Python 3.12:

```bash
python3 -m unittest discover -s workshop/tests -v
python3 -m workshop.runner --task research --output /tmp/zohraya-workshop
cat /tmp/zohraya-workshop/receipt.json
```

هیچ وابستگی شخص ثالث برای خود کارگاه لازم نیست. برای اجرای سایر وظایف، منابع
مربوطه باید در درخت مخزن در دسترس و checksum آنها معتبر باشد. شکست آزمون را
با عنوان «پیشرفت موفق» ثبت نکنید.

## مسیر توسعه به Gemini

گام جداگانهٔ بعدی مطابق Issue #69: گرفتن مجوز، تنظیم امن Secret، سقف توکن و
هزینه، دریافت وظیفهٔ تأییدشده و ایجاد **Draft PR** با بررسی اجباری انسانی.
فعال‌کردن API یا نوشتن کد توسط مدل در این نسخه وجود ندارد و از روی وجود
زمان‌بند نباید استنباط شود.
