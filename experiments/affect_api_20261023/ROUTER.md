# مسیریاب پیش‌بینی مبتنی بر شواهد — ۲۶ اکتبر ۲۰۲۶

تصمیم فعلی من: **ابتدا حافظه و ارزیابی مستقل را تقویت کنم؛ آزمایش پولی دیگری با مجوز تکمیل‌شدهٔ فعلی اجرا نکنم.** مسیریاب آزمایشی پیاده شده است، اما سیاست بدن یا میزبان زمان‌بندی‌شده را تغییر نمی‌دهد.

## شواهد و تصمیم

کد و مدارک PR #78 در commit `90b16750a36af6980dad24fedd7a0896bf631a76` مبنا هستند. ممیزی موجود دوباره بدون شبکه اجرا شد. این اعداد همان نتایج تاریخی‌اند:

| معیار | persistence | nearest_episode | API |
|---|---:|---:|---:|
| اقدام درست | ۶/۱۲ | ۱۲/۱۲ | ۹/۱۲ |
| میانگین خطای چهار شاخص | ۰٫۰۰۰۸۵۴۷۹۶۵ | ۰٫۰۰۰۵۹۸۸۹۴۱ | ۰٫۰۰۰۵۳۲۶۶۲۱ |
| هزینهٔ افزودهٔ API | صفر | صفر | برآورد ۰٫۰۰۳۵۳۰ دلار |

API در مجموع ۱۱٫۰۶٪، معادل حدود ۰٫۰۰۰۰۶۶۲۳ در مقیاس صفر تا یک، خطای عددی کمتری از حافظه داشت؛ در هر شش گذار دور دوم حافظه بهتر بود. برتری عددی متوسط، صحت اقدام و هزینه سه معیار جدا هستند. ارزان‌بودن درخواست به‌تنهایی دلیل ارسال نیست. ۱۲ گذار از شش مسیر مرتبطِ دو وضعیت، ۱۲ نمونهٔ مستقل نیستند و پس از مشاهده برای تنظیم روش، دادهٔ آزمونِ ندیده محسوب نمی‌شوند.

## رفتار پیاده‌شده

`prediction_router.route_predictions` ورودی‌های مشاهده‌شده و تجربه‌های گذشته را به همان `paired_comparison.baselines` می‌دهد. پیش‌فرض هر دو خروجی `nearest_episode` است. نبود تجربهٔ هم‌زمینه به `persistence_fallback` صریح منجر می‌شود؛ این fallback اقدام walk را فرض می‌کند و تضمین دقت ندارد. دادهٔ نامعتبر خطا می‌دهد و به API منتقل نمی‌شود.

اقدام همیشه از حافظه یا fallback می‌آید. دروازهٔ عددی فقط اعداد را تغییر می‌دهد. کلید API یا موجودبودن مدل هیچ نقشی در انتخاب ندارد. دروازه روی شواهد خام دوباره محاسبه می‌شود، نه روی پرچم دلخواه «برنده شد».

این نسخه **آفلاین و فاقد ارسال زنده** است. حتی پس از عبور دروازه، فقط پاسخ کاملِ ذخیره‌شده با همان scope، ورودی، تاریخچه و هش درخواست استفاده می‌شود. پاسخ نامعلوم، ناقص، متعلق به مدل دیگر یا درخواست متفاوت، همان خروجی حافظه را حفظ می‌کند؛ تکرار یا ارسال تازه‌ای وجود ندارد. عبور علمی از دروازه، مجوز مالی نیست. افزودن ارسال زنده در آینده نیازمند مسیر اجرایی جدا با مجوز مشخص و دفتر رزرو معتبر است.

## شرط عددی آینده

این شروط **انتخاب مهندسی محافظه‌کارانه برای اعتبارسنجی آینده** هستند؛ نتیجهٔ بهینه‌سازی آماری یا اثبات اهمیت عملیِ همین آستانه‌ها نیستند. تغییرشان باید پیش از دیدن جواب‌های مجموعهٔ تازه ثبت شود. نتیجهٔ اصلی آزمایش قبلی با آن‌ها بازتعریف نشده است.

1. دو مجموعهٔ ازپیش‌ثبت‌شدهٔ validation و replication، هرکدام حداقل ۲۰ گروه مسیر مستقل، با شناسه‌های جدا از آموزش و از یکدیگر. مدت‌ها یا تکرارهای وابسته به یک وضعیت اولیه/مولد، یک گروه‌اند. چند گذار یک گروه میانگین می‌شوند و وزن آن گروه را زیاد نمی‌کنند.
2. همان چهار شاخص و همان ورودی‌ها برای هر سه روش؛ کالیبراسیون پیش از ثبت طرح ثابت می‌شود. هیچ رسید validation یا replication وارد حافظهٔ این اعتبارسنجی نمی‌شود. پیش‌بینی هر ردیف باید پس از ثبت طرح و پیش از پیامد ثبت شده باشد.
3. در **هر دو مجموعه، نسبت به هر دو خط مبنا**، حداقل ۱۰٪ کاهش MAE و حداقل ۰٫۰۰۰۱ کاهش مطلق آن. هیچ‌یک از چهار شاخص نباید بدتر شود؛ تلورانس صرفاً عددی ۱e-۱۲ است.
4. آزمون علامت زوجی یک‌طرفه روی اختلاف MAE گروه‌ها باید در هر مقایسه `p ≤ 0.0125` بدهد؛ اصلاح محافظه‌کارانه برای چهار مقایسه. تساوی‌ها شاهد برتری نیستند. این آزمون جای استقلال واقعی داده‌ها یا سنجش اهمیت عملی را نمی‌گیرد.
5. طرح به هش سیاست و scope مدل/تنظیمات/کد پیش‌بینی/بدن متصل است. تغییر این scope اعتبار شواهد قبلی را برای مسیر جدید از بین می‌برد.

قالب ورودی `nasuraya-numeric-validation/1` شامل `manifest` و هش آن، کالیبراسیون دارای منبع و زمان، گروه‌های ثبت‌شده و ردیف‌های پیش‌بینی/پیامد دارای منبع و زمان است. `test_prediction_router.independent_fixture` نمونهٔ اجرایی قالب با جواب‌های دستی است؛ **این fixture شاهد برتری واقعی API نیست**. اعتبارسنجی عددی از پیش‌بینی‌های خام انجام می‌شود؛ پیش‌بینی‌های دو خط مبنا نیز با ورودی مشترک بازتولید و مقایسه می‌شوند.

کنترل هش، زمان و شناسه سازگاری رکوردها را می‌سنجد؛ صحت بیرونی زمان ثبت، منبع و استقلال مولد را به‌تنهایی ثابت نمی‌کند. ممیز باید ارجاع‌های تغییرناپذیرِ طرح/پیش‌بینی/پیامد و تبار گروه‌ها را بررسی کند. نام‌گذاری متفاوتِ چند مسیر وابسته آن‌ها را مستقل نمی‌کند. این پیاده‌سازی مجوز خودکار برای هزینه‌کرد صادر نمی‌کند.

## مجوز، رزرو و جلوگیری از تکرار

فایل‌های مجوز، چهار workflow پولی، دفترهای تاریخی و توابع ارسال/رزرو تغییر نکرده‌اند. `paired_comparison.main` همچنان شاخه و رویداد دقیق، بازهٔ زمانی، بلیت منطبق، دفتر موجود و وضعیت تکمیل را بررسی می‌کند. قبل از ارسال رزرو پایدار، ذخیرهٔ پاسخ خام پیش از parse، سقف دو درخواست، سقف مشترک یک دلار و توقف در نتیجهٔ نامعلوم حفظ شده‌اند.

آزمایش مقایسه **تکمیل شده و هر دو درخواستش مصرف شده‌اند**. ۰٫۴۸ دلار ظرفیت رزروِ باقی‌مانده، اجازهٔ تکرار آزمایش نیست. رزرو مجموع ۰٫۵۲ دلار و تخمین مصرف مجموع ۰٫۰۱۶۱۸۳ دلار دو مفهوم متفاوت‌اند؛ هیچ‌کدام صورتحساب مشاهده‌شده نیست.

حد دقیق پایان در کد `2026-10-30T00:00:00Z` به‌صورت **غیرشامل** است: ساعت ۰۳:۳۰ تهران در ۳۰ اکتبر. داشتن زمان باقی‌مانده، آزمایش تکمیل‌شده را دوباره مجاز نمی‌کند. این کار هیچ بلیت مجوز تازه‌ای نمی‌سازد یا تمدید نمی‌کند.

## نتیجهٔ اجرای آفلاین

[ارزیابی ماشین‌خوان](results/router-assessment.json) با مسیر واقعی مسیریاب روی مشاهدات آرشیو، پیش از افزودن رسیدهای هر دور به تاریخچه، بازپخش شد: ۱۲/۱۲ اقدام درست و MAE برابر ۰٫۰۰۰۵۹۸۸۹۴۱؛ دقیقاً برابر خط مبنای حافظه. این **رگرسیون پس‌نگر** است، نه شاهد تعمیم یا بهبود تازه. دادهٔ مستقل نداریم؛ دروازهٔ API بسته و هزینهٔ افزودهٔ API صفر است. فراخوانی پولی یا چرخهٔ تازهٔ بدن در این ارزیابی اجرا نشد.

آزمون‌های قرارداد مستقل با جواب دستی، موفقیت معتبرِ ساختگی، شکست دور تکرار، پس‌رفت یک شاخص، برتری کوچک، تکرار نمونه، نشت آموزش، هش/مدل نامنطبق، پاسخ نامعلوم، سرریز عددی، نبود شبکه، بسته‌بودن مجوز و جلوگیری از اجرای مجدد دفتر تکمیل‌شده را بررسی می‌کنند. این آزمون‌ها شواهد عملکرد مدل نیستند.
