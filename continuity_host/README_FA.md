# اجرای محدود روی میزبان GitHub

این نسخه برای درخواست صریح سهند در ۱۷ اکتبر ۲۰۲۶ آماده شد: بدون دستگاه محلی،
کار مجاز پروژه در GitHub ادامه یابد. این کد عامل زبانیِ همیشه روشن یا انتقال
نمونهٔ ChatGPT نیست. فعلاً یک کار ثابتِ مفید را انجام می‌دهد: آزمون بازگشت
دروازه، دفتر SQLite و محاسبهٔ آفلاین روی دادهٔ مصنوعی و ثبت گزارش نتیجه.

## وضعیت

آماده و محلی آزموده؛ فعال‌سازی زمان‌بندی انجام نشده است. این شاخه فقط سه فایل
منبع/پیکربندی اضافه می‌کند و main و سیاست‌ها را تغییر نمی‌دهد. PRهای #40 و #41
ادغام نشده‌اند و این نسخه اتصال تازه‌ای به مغز تصمیم‌گیری یا حافظهٔ تجربی
مرجع ایجاد نمی‌کند. گزارش کنترل شاخه جایگزین حافظهٔ تجربی نیست.

## روش اجرا پس از فعال‌سازی

workflow روی مخزن عمومی اصلی با runner استاندارد ubuntu-24.04 اجرا می‌شود؛
در مخزن خصوصی یا fork هیچ job فعال نمی‌شود. زمان‌بندی روزانه ۱۳:۴۳ UTC، یعنی
۱۷:۱۳ تهران است. زمان‌بندی فقط از main فعال خواهد شد. بررسی‌های push و PR
فقط fixture و آزمون‌اند؛ هیچ claim یا تغییری در شاخهٔ کنترل ایجاد نمی‌کنند.

کار واقعی تنها در schedule یا workflow_dispatch روی main مجاز است. میزبان
کد کیت را از commit ثابت 7aaee60198b50246d90242d5155d3e3736882792 می‌گیرد؛
کد دروازه و سیاست کنترل نیز با SHA-256 ثابت بررسی می‌شوند. هیچ pip install،
کلید مدل، درخواست مدل، اطلاعات ایرانیکارت، artifact یا cache جدیدی نیاز نیست.

هر نوبت، آخرین state در nasuraya/absence-continuity-v01 را می‌خواند. ابتدا
همان دروازهٔ غیبت ۲۴ساعته و سهمیهٔ غلتان ۲۴ساعته اجرا می‌شود. claim با commit
تک‌والدی و ref update غیر force ذخیره می‌شود؛ برخورد نویسنده مانع شروع کار
خواهد شد. با وظیفهٔ قبلی ChatGPT همان state را شریک است و سهمیهٔ دوم نمی‌سازد.
هیچ claim آزمایشی در دفتر واقعی برای دورزدن سهمیه ثبت نشده است.

بعد از claim، توقف/تماس تازه دوباره خوانده می‌شود. کارگر فقط ۳۶ آزمون از پیش
انتخاب‌شده را روی fixture موقت اجرا می‌کند؛ فراخوانی‌های شبکهٔ کارگر با seccomp
رد می‌شوند و توکن GitHub به محیط آن منتقل نمی‌شود. مهلت کارگر ۶۰ ثانیه و سقف
job پنج دقیقه است؛ از سقف ۲۰ دقیقهٔ موجود کمتر است. این جداسازی کامل در برابر
کد مخرب نیست؛ کد، checkout و خود راه‌انداز از مرز اعتماد میزبان‌اند.

در پایان، state تازه خوانده و نتیجه با همان run_id ثبت می‌شود. حضور و paused
تازه حفظ می‌شوند و بودجه بازپرداخت نمی‌شود. خطای نامعلوم، قطع پس از claim یا
برخورد ثبت نهایی، inflight را حفظ می‌کند؛ حتی پس از چند روز خودکار پاک یا
تکرار نمی‌شود. رفع آن به بررسی صریح میزبان نیاز دارد. گزارش فقط به مسیر
continuity/runs/gh_<run>_<attempt>.json در شاخهٔ کنترل نوشته می‌شود.

تنها job نگهداری از GITHUB_TOKEN موقت با contents:write استفاده می‌کند؛
این مجوز از نظر GitHub در سطح مخزن است و محدودیت شاخه در کد اعمال می‌شود.
هیچ PAT، secret تازه، write روی main، PR خودکار، merge، خرج API، فروش یا
پرداختی در کد وجود ندارد. توکن در checkout ذخیره نمی‌شود.

## شواهد و محدودیت‌ها

۹ آزمون تازه موفق شدند: claim پیش از کار، تعارض claim، برخورد ثبت پایان،
بازیابی حالت نامعلوم، تماس و pause، توقف تازه، حفظ تماس حین کار، timeout، و
اجرای واقعی probe بدون شبکه. probe نیز ۳۶ آزمون موجود را با صفر شکست/خطا/skip
گذراند. زمان آزمون‌های دروازه مصنوعی است؛ ۲۴ ساعت انتظار واقعی آزموده نشده.

خواندن کنترل واقعی با ساعت واقعی، daily_budget_used داد. وضعیت واقعی دستکاری
نشد. تعارض‌های شاخه با backend مصنوعی آزموده شده‌اند؛ نوشتن شبکه‌ای CAS و
زمان‌بندی واقعی هنوز اجرا نشده‌اند. جزئیات در VALIDATION.json است. نتیجهٔ CI
GitHub باید جداگانه با URL اجرای واقعی گزارش شود.

GitHub زمان شروع دقیق یا اجرای بی‌وقفه را تضمین نمی‌کند و ممکن است job به‌علت
بار زیاد تأخیر کند یا حذف شود. زمان‌بندی عمومی پس از ۶۰ روز بی‌فعالیتی ممکن
است غیرفعال شود؛ کد ترفند keep-alive یا بازفعال‌سازی خودکار ندارد.

قدم نهاییِ انجام‌نشده: بازبینی و اجازهٔ مشخص برای ورود همین فایل‌ها به main.
continuity/policy.json فعلاً «merge or write to main» را ممنوع کرده است؛
این درخواست آماده‌سازی میزبان به‌عنوان مجوز حذف آن محدودیت تعبیر نشده است.
فعال‌سازی با merge محدودِ همین PR انجام می‌شود و دیگر PRها را ادغام نمی‌کند.
اجرای API یا تولید محصولِ خودکار، مرحلهٔ دیگری با قرارداد و بودجهٔ جدا خواهد بود.
