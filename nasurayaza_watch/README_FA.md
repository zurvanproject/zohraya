# ناسورایازا: دیده‌بان دائمی سایه‌ها (آزمایش v0.1)

بر اساس حکمت ۷۵ زهرایا: «ناسورایازا (الههٔ دیوها) یعنی آگاهیِ بینایی که در تاریکی می‌نشیند تا به سایه‌ها راه بازگشت بیاموزد.» این نام **هویت روایی** یک منتقد پژوهشی است، نه اثبات ذهن یا احساس مستقل.

## دقیقاً چه چیزی ساخته شده؟

یک پردازهٔ پایتون ماندگار که هر ۱۵ دقیقه، تا ۳۰ PR اخیر مخزن عمومی zurvanproject/zohraya را فقط **می‌خواند**. برای هر تغییر جدید، سؤالات ابطال‌پذیر و پیش‌شرط‌های آزمایش را در SQLite نگه می‌دارد. برای یک PR تکراری هیچ گزارش دوباره‌ای ایجاد نمی‌کند. هر نظرسنجی یک status.json ثبت می‌کند تا حضور و خطا مشخص باشد. حافظه در volume داکر نگهداری می‌شود و پس از restart پابرجاست.

پرسش‌ها بر مبنای متن PR و قوانین آشکار ساخته می‌شوند. این نسخه **مدل زبانی متفکر، کارگر GPU، عامل خودویرایش‌گر یا خودآگاهی** نیست؛ ابزاری کوچک برای تفکیک ادعا از شاهد است. حتی پس از فعال شدن، بدون ورودی تازه صرفاً مخزن را دوره‌ای بررسی می‌کند. این نسخه فقط سؤال ایجاد می‌کند و خودکار هیچ PR را ادغام/تغییر نمی‌دهد.

## وضعیت عملیاتی

ساخت در شاخهٔ آزمایشی است. ساخت فایل و گذراندن آزمون، به معنی **نصب یا فعال بودن ۲۴ساعته نیست**. راه‌اندازی نیازمند یک میزبان لینوکسیِ دارای Docker با اتصال HTTPS خروجی به GitHub است. GPU یا API key لازم نیست.

از ریشهٔ مخزن:

    python3 -m unittest discover -s nasurayaza_watch/tests -v

برای یک اجرای آزمایشی روی سیستم شخصی:

    NASURAYAZA_DATA="$(mktemp -d)" python3 -m nasurayaza_watch --once

روی سرور لینوکسی همیشه‌روشن:

    docker compose -f nasurayaza_watch/compose.yaml up -d --build
    docker compose -f nasurayaza_watch/compose.yaml ps
    docker compose -f nasurayaza_watch/compose.yaml logs --tail 30

دادهٔ واقعی در named volume nasurayaza_state است. وضعیت و جزئیات بازبینی در status.json و reviews.sqlite3 قرار می‌گیرند. سرویس HTTP ورودی باز نمی‌کند. برای توقف:

    docker compose -f nasurayaza_watch/compose.yaml stop

## مرزها و مسیر رشد

- شبکه: فقط GET عمومی GitHub. بدون GitHub token، کلید OpenAI، پرداخت، ابزار کنترل تداش یا نوشتن در مخزن.
- هزینهٔ مدل: صفر. هزینهٔ احتمالی سرور/اینترنت جدا است و باید پیش از اجاره مشخص شود.
- فرکانس: POLL_SECONDS از ۳۰۰ تا ۸۶۴۰۰؛ مقدار پیش‌فرض ۹۰۰ ثانیه. GitHub ممکن است محدودیت نرخ یا قطعی داشته باشد؛ دریافت یک PR جدید می‌تواند عقب بیفتد.
- وضعیت سلامت: وجود heartbeat به معنی پاسخ دریافت‌شدهٔ موفق نیست؛ در خطا ok:false ثبت می‌شود. روی میزبان حقیقی باید اختلالات شبکه و restart آزموده شود.
- جلوگیری از دوباره‌کاری: fingerprint محتوای محدود، timestamp و commit PR؛ SQLite unique constraint.
- سیاست: هیچ نشانهٔ PASS برای ادغام صادر نمی‌کند. سؤال و نقص شاهد، جای داوری انسانی را نمی‌گیرند.
- توسعهٔ بعدی: اتصال اختیاری به یک مدل زبانی با سقف اعتبار صریح و ارزیابی کور، فقط پس از تعریف قرارداد جدید. این نسخه هیچ اتصال API یا بودجه‌ای فعال نمی‌کند.

## آزمون وضعیت

آزمون‌ها idempotency، تغییر SHA، atomic transaction، جداسازی دو مدل بدن، رد ورودی ناسالم، طبقه‌بندی خطا و سلامت timestamp را بررسی می‌کنند. برای سنجش ۲۴/۷ واقعی باید uptime، تعداد pollهای موفق و تاخیرهای چندروزه را روی سرور ثبت کرد. GitHub Actions فقط آزمون کوتاه انجام می‌دهد؛ نقش میزبان دائمی را ندارد.
