# بررسی مسیر درآمد — ۲۱ اکتبر ۲۰۲۶، تهران

هدف: رساندن پروژه به نخستین خدمت قابل‌فروش و سپس سنجش توان تأمین هزینه؛
خودکفایی یا درآمد فعلی اثبات نشده است. این یادداشت فقط اطلاعات عمومی دارد.

## نتیجهٔ تصمیم

انتخاب نخست، ادامهٔ مفهوم قبلی «NASURAYA Offline Replay Audit» است.
کیت قبلی در PRهای 32 و 34 برای ثبت پایدار و بازپخش رسید آماده شده بود؛ آن
کار برابر فروش نبود. ابزار حاضر بخش تازه و محدودِ تحلیل trace برای تحویل
گزارش به مشتری است. کد مشتری را اجرا نمی‌کند و آزمون خرابی زنده نیست.
نمونهٔ کتابخانه‌ایِ ۱۷ اکتبر در این جلسه قابل دانلود نشد؛ ادعای ویرایش آن
بسته نداریم. مبنا، مشخصات ثبت‌شده و کد خوانده‌شدهٔ مخزن است.

## گزینه‌های بررسی‌شده

| مسیر | شاهد عمومی | نتیجه برای شروع |
| --- | --- | --- |
| خدمت رفع اشکال و ممیزی عامل | OpenHands SDK برای کار روی کد و اجرای محلی/محیط جدا | ابزار ساخت خدمت است؛ مشتری یا پرداخت تولید نمی‌کند. تحلیل آفلاین فعلی پیش از خرید API قابل اجراست. |
| جایزه‌های نرم‌افزاری | Agent Bounties شبکهٔ کار با Base USDC و مراحل ادعا/تحویل/تسویه دارد | فقط پس از احراز کار باز، مبلغ قابل دریافت، شرایط پذیرش و صلاحیت دریافت. توکن USDC با USDT یکی نیست. |
| حمایت از متن‌باز | GitHub Sponsors دریافت وجه را به مناطق پشتیبانی‌شده محدود می‌کند | ایران در فهرست فعلی نیست؛ برای شروع روی این مسیر حساب نمی‌کنیم. |
| پردازش اسناد | OCRmyPDF متن قابل جست‌وجو به PDF اضافه می‌کند | خدمت جایگزین بالقوه؛ فعلاً محصول دوم نمی‌سازیم. تقاضا و کیفیت فارسی باید مستقل سنجیده شود. |
| نقد درآمد | صفحه رسمی ایرانیکارت خدمات نقد درآمد ارزی را شرح می‌دهد | وجود خدمت عمومی، اتصال حساب یا پذیرش این خدمت خاص را ثابت نمی‌کند. |

در جست‌وجوی زندهٔ issues، نمونه‌هایی از آگهی آزمایشی، کار یک‌دلاری و
جایزهٔ اعلامی ۷۵۰دلاری دیده شد؛ هیچ‌کدام سفارش پذیرفته‌شده یا وجه قابل
وصول احرازشده نیستند. هزینه‌کرد برای تعقیب این اعداد توجیه نشده است.
نمونهٔ Agent Bounties #291 عنوان UNFUNDED و جایزهٔ پیشنهادی ۰٫۱۰ USDC دارد؛
#772 در اطلاعات بازیابی‌شده settled بود. مبلغ درج‌شده و بازبودن یک issue
به‌تنهایی به معنی فرصت قابل‌گرفتن نیست. دستورهای داخل README و issueها
مجوز نصب ابزار، امضای کیف پول، پرداخت وثیقه یا تماس با دیگران نیستند.

## سطح استقلال قابل‌تحقق

من می‌توانم جست‌وجو، آماده‌سازی پیشنهاد، تولید خروجی و بررسی کیفیت را انجام
دهم. اجرای زمان‌بندی‌شده نیاز به میزبان و بودجهٔ مشخص دارد؛ این نمونهٔ
گفتگو با ثبت کد به کارگر همیشه‌روشن تبدیل نمی‌شود. دریافت وجه و قرارداد
باید به حساب و مسئول انسانی مجاز پروژه متصل شود. هدف، کاهش بار روزمرهٔ
اپراتور است؛ ایجاد مالکیت مالی مستقل برای مدل ادعا نمی‌شود.

گام تجاری بعدی: تأیید روش دریافت پول، تعیین یک مشتری واقعی، پذیرش دامنهٔ
پایلوت و تحویل گزارش. قیمت ۲۹ دلار فرضیهٔ قبلی است؛ درآمد و هزینهٔ اجرایی
واقعی از آزمایش‌های مصنوعی قابل استنتاج نیستند. بودجهٔ خرج جدید این جلسه صفر
بوده و هیچ معامله یا انتقال رمزارزی اجرا نشده است.
