# اتصال پژوهش‌های بیرونی به ناسورایا — پایلوت محلی

[گزارش اجرای ۱۸ اکتبر و شواهد](../../docs/nasuraya-external-research-2026-10-18-fa.md)
نتیجهٔ اندازه‌گیری و موارد پذیرفته‌نشده را ثبت می‌کند.

چهار زیرمجموعهٔ واقعی و بدون تغییر از کدهای منتشرشده، با مجوز و نسخهٔ ثابت
در `vendor/` نگه داشته می‌شوند. `upstream-lock.json` مسیر اصلی، commit،
Git blob و SHA256 هر فایل را ثبت می‌کند. `integrity.py` پیش از واردکردن
کد بیرونی، هم دفتر ثابت و هم فایل‌ها را بررسی می‌کند. این بررسی بر مفسر و
کد میزبان مورد اعتماد تکیه دارد و محافظی در برابر بازنویسی خصمانهٔ کل میزبان نیست.

| منبع | کد واقعاً استفاده‌شده | کاربرد و مرز اتصال |
| --- | --- | --- |
| [MMB](https://github.com/synthiumjp/metacognitive-monitoring-battery/tree/2f83d0fa506e7af2b72ca191b65ce42e07c9e185) | `analysis/probe_analysis.py`، MIT | محاسبهٔ تفاوت نگه‌داشتن تصمیم در موارد درست و غلط، از تصمیم‌های ثبت‌شدهٔ `ControlTrial` و برچسب‌های آزمون بدنی قبلی؛ بازتولید آزمون زبانی ۵۲۴سؤالی نیست. |
| [RoboRSI](https://github.com/OpenSenseNova/SenseNova-RoboRSI/tree/f7542dfea2a852dbd151da86a2e9fc475d3257fd) | `roborsi/evaluation/trajectory.py`، Apache-2.0 | نمایش و شمارش مسیر ثبت‌شدهٔ تصمیم/پیامد؛ عامل RoboRSI، بهبود بازگشتی یا مدل ۲۷B اجرا نمی‌شود. |

**کد انتخاب‌شده با کل محصول بیرونی برابر نیست.** نسخهٔ کامل PredVLA به
MuJoCo 2.3.7 و mjlab به MuJoCo 3.11 وابسته‌اند. این پایلوت فقط بخش‌های
مستقل از آن موتورها را در محیط CPU جدا اجرا می‌کند. وابستگی‌های برنامهٔ
اصلی و معادلات بدن تغییر نکرده‌اند. واردکردن بسته هیچ کاری را آغاز نمی‌کند.

مخزن [تشخیص خود/دیگری](https://github.com/Euron-ZC/Humanoid-self-other-distincton-model)
در زمان بررسی فقط README و تصویر داشت و کد و مجوز اجرای آن هنوز منتشر
نشده بود؛ از آن کدی وارد نشده است. گزارش‌های عملکرد دیگران تأیید مستقل ما نیستند.

## اجرا

آزمون‌های پایه با کتابخانهٔ استاندارد اجرا می‌شوند؛ آزمون‌های تانسوری در نبود
PyTorch به‌صورت صریح skip می‌شوند:

```sh
python -m unittest examples.nasuraya_research.test_adapters -v
python -m examples.nasuraya_research.evaluate --output /tmp/NEW-research-pilot
```

برای اجرای هر چهار اتصال، محیط تازهٔ CPU بسازید:

```sh
python -m venv /tmp/nasuraya-research-env
/tmp/nasuraya-research-env/bin/python -m pip install -r examples/nasuraya_research/requirements-cpu.txt
/tmp/nasuraya-research-env/bin/python -m unittest examples.nasuraya_research.test_adapters -v
/tmp/nasuraya-research-env/bin/python -m examples.nasuraya_research.evaluate --with-tensor --output /tmp/NEW-research-tensor-pilot
```

پوشهٔ خروجی باید تازه باشد. خروجی شامل پروتکل، نتایج تصمیم، مسیر اجرای
آفلاین، داده‌های حسی، وزن‌های مدل کوچک به‌صورت JSON و همهٔ مقایسه‌های سه
بذر ثابت است. داده‌ها از fixture ساخته می‌شوند، نه از وضعیت ذخیره‌شدهٔ کاربر.
فایل JSON وزن‌ها را با `restore_observer` می‌توان بازیابی کرد؛ pickle اجرا نمی‌شود.

برای تکرار فقط برازش حسی روی دادهٔ یک پایلوت کامل و منطبق، بدون اجرای دوبارهٔ
بدن، دستور صریح زیر وجود دارد. این دستور مسیر، آمار و قرارداد ثبت‌شده را
بررسی می‌کند و اثرانگشت ورودی‌های استفاده‌شده را در خروجی نگه می‌دارد؛ بازپخش
دادهٔ ثبت‌شده، اجرای تازهٔ بدن محسوب نمی‌شود:

```sh
/tmp/nasuraya-research-env/bin/python -m examples.nasuraya_research.refit --source /tmp/COMPLETED-pilot --output /tmp/NEW-sensory-refit
```

گردش کار PR آزمون‌های اتصال و پس‌رفت را اجرا می‌کند. بازتولید کامل ۳۲ وضعیت
با چهار بازوی تصمیم و سه مدل کوچک، از طریق اجرای دستی همان گردش کار نیز
ممکن است؛ این ارزیابی کامل در هر رویداد PR خودکار تکرار نمی‌شود.

## تفسیر نتیجه

محاسبهٔ MMB بر آزمون طراحی‌شدهٔ مجوز راه‌رفتن انجام می‌شود. برچسب هر مورد
از اجرای جداگانهٔ همان مدل بدن می‌آید و پیش از تصمیم در اختیار کنترل‌گر نیست.
این برچسب، اندازه‌گیری مستقل جهان واقعی یا تکمیل مسیر حرکت نیست. کنارگذاشتن
همهٔ کارها به‌تنهایی فراشناخت خوب محسوب نمی‌شود؛ پوشش اجرا، خطا و موارد
مجازِ کنارگذاشته‌شده در گزارش قبلی حفظ می‌شوند.

در PredVLA، شش متغیر وضعیت بدن و شش مؤلفهٔ جای پا استفاده می‌شوند.
جای پا ویژگی هندسیِ شبیه‌سازی است، نه تصویر دوربین. کدِ ثابت دوعددیِ کار،
زبان طبیعی نیست. وزن‌ها فقط روی چهار فشار خوابِ آموزشی به‌روز می‌شوند؛
چهار فشار دیگر کنار گذاشته شده‌اند. کاهش خطای متغیر نهان با دیدن مشاهدهٔ
جاری، **بهبود بازسازی همان مشاهده** است؛ نباید به‌عنوان پیش‌بینی آینده،
یادگیری یک مهارت حرکتی یا افزایش خودآگاهی گزارش شود.

سرِ کنش مدل آموزش نمی‌بیند؛ خروجی آن دور انداخته می‌شود و هیچ مسیری به
اجرای حرکت ندارد. تصمیم و وتوی حرکتی با کد قبلی باقی می‌مانند. تبدیل مختصات
نیز مشاهده‌گر است و زمان بدن را جلو نمی‌برد. همهٔ نتایج و موارد منفی گزارش
می‌شوند؛ فعال‌سازی خودکار، API زنده و ادغام در main در این پایلوت وجود ندارد.

ثابت‌ماندن سرِ کنش با غیرفعال‌کردن گرادیان پارامترهای آن و تطبیق اثرانگشت
پیش و پس از آموزش کنترل می‌شود. صفرکردن وزن خطای کنش کافی نیست، زیرا مسیر
کپی فرمان می‌تواند خطای حسی را به همان پارامترها برساند.

## اتصال آزمایشی Dream Ten به بدن

اجرای `dream_ten_native` نامزدها را روی کپی تازهٔ بدن و وضعیت‌های جداگانهٔ آموزش و آزمون می‌سنجد. `Step` از انرژی واقعی سوخت و ذخیره، حمایت مفصل و فاصله تا هدف ثابت نخستین قدم ساخته می‌شود. این فاصله، خطای مسیر کامل نیست. انتخاب از آموزش انجام می‌شود؛ آزمون مستقل فقط همان نامزد را ارزیابی می‌کند.

```sh
python -m examples.nasuraya_research.dream_ten_native --output /tmp/NEW-dream-ten-native
```

[گزارش قرارداد، روش و نتیجهٔ منفی ثبت‌شده](../../docs/nasuraya-dream-ten-native-v01-fa.md): در افق یک‌ثانیه‌ای خطای قدم کمتر نشد و حرکت پا رخ نداد؛ کاهش مصرف انرژی به‌تنهایی شاهد بهبود مهارت نیست.
